# DREAMWEAVER · 꿈을 엮는 기록실

Card RPG의 기능을 재사용하는 모바일 세로 화면용 게임입니다. 하늘색과 잉크색 바탕에 은은한 보랏빛, 꿈을 엮는 마법서의 문구와 소환 연출을 더했습니다. 전투는 로그를 넓게, 음악감상은 한 번에 더 많은 곡을 볼 수 있게 구성했습니다.

## 빌드와 실행

저장소 루트에서:

```sh
npm ci
npm run build:card
```

결과물은 `card/dist/DREAMWEAVER.html`입니다. 약 5 MiB의 HTML 한 파일에 게임 코드, 학습 데이터, CSS, UI 배경과 아이콘이 포함됩니다. 서버, CDN, 외부 JS, 웹 폰트 없이 `file://`로 실행됩니다. 빌드한 `dist/DREAMWEAVER.html`도 Git에 함께 관리합니다. 소스를 변경하면 빌드를 다시 실행해 HTML을 함께 커밋하세요.

모바일 기기에는 아래처럼 배치하세요. 기존 파일명을 바꾸지 않습니다.

```text
CardRPG/
  DREAMWEAVER.html
  루미.png
  루나.png
  마시멜로.png
  ...기존 카드·적 초상화 PNG...
  ...기존 음악·리스닝 MP3...
```

HTML을 브라우저에서 여세요. 초상화·음원은 외부 로컬 파일로 유지되며 빌드나 Git에 복제하지 않습니다. 초상화가 없으면 카드 문양을 표시합니다. 별도 폴더를 사용할 때는 설정의 상대 경로나 폴더 선택을 사용할 수 있습니다. 폴더 선택으로 연결한 파일은 현재 실행 중에만 유지됩니다. 기기의 파일 뷰어나 브라우저가 인접 파일 접근을 제한하면 초상화 폴더 선택을 이용하세요. 음악과 리스닝 파일은 기본적으로 HTML과 같은 폴더에 둡니다.

로컬 HTTP 미리보기:

```sh
npm run serve --prefix card
```

`http://127.0.0.1:4179`를 엽니다. 기본 배포 방식은 HTML 파일이며, 개발 서버는 선택 사항입니다.

## 화면과 기능

- **로비:** 출전 파티 3장, 다음 상대, 소환과 출전. 빈 파티는 출전을 막고 다음 행동을 안내합니다.
- **편성:** 자리 선택 → 보유 카드 선택. 카드별 수량 제한과 기존 배치 효과를 유지합니다.
- **도감:** 보유/전체 전환, 이름·속성·역할 검색, 등급 필터, 카드 상세 정보. 전체 도감 열람은 카드를 지급하지 않습니다.
- **학습:** 문법 강의, 단어/연어 오답장, TOEIC, 루미 개인과외와 질문.
- **전투:** 기존 턴 처리·스킬·효과·보상, 읽기 쉬운 HP/MP와 하단 스킬 패널. 전투 중 다른 화면으로 빠지는 탐색 메뉴는 숨깁니다.
- **기타:** 16개 게임 모드, 미션, 축복, 아티팩트, 포춘쿠키, 음악, 기록과 전체화면을 유지합니다.

루미 AI 질문·과외·데이트 등 기존 Gemini 기능에는 네트워크와 사용자의 API 키가 필요합니다. 기본 전투와 내장 학습 데이터는 API를 요구하지 않습니다. 외부 서비스의 응답과 기기의 로컬 파일 접근 정책은 브라우저에 따릅니다.

## 저장 이동

기존 Card의 저장 키와 직렬화 형식을 유지합니다. 브라우저나 HTML 경로가 바뀌면 저장 공간이 달라질 수 있으므로 자동 이동을 가정하지 마세요.

DREAMWEAVER에서는 게임 메뉴에서 여정을 저장한 뒤 **설정 → 기록 파일 내보내기**로 백업할 수 있습니다. 새 기기에서는 **기록 파일 가져오기** 후 이어가기를 선택하세요. 내보내기는 저장된 기록을 읽으며, 현재 저장을 덮어쓰지 않습니다. 타이틀에서는 빈 여정으로 기존 저장을 덮어쓰지 않도록 게임 저장 메뉴를 비활성화합니다. API 키는 백업에서 제외합니다. 기존 `cardRpgSave` 형식의 JSON 파일도 가져올 수 있습니다. 새 버전이나 손상된 여정은 기존 마이그레이터의 검사를 거칩니다.

## 소스 구조

```text
card/
  game/                 게임 데이터·규칙·기존 화면 계약의 소스 오브 트루스
  src/shell.html       새 화면과 탐색 구조
  src/astra.css        디자인 토큰, 모바일/데스크톱 배치
  src/astra.js         화면 어댑터, 검색, 초상화, 백업, 접근성
  assets/observatory.png  새 관측소 배경
  build.mjs           공유 Card 소스를 단일 HTML에 조립
  tests/verify.mjs     오프라인·저장·화면·전투 회귀 검증
  tests/flows.mjs      모드·TOEIC·미디어·키보드 흐름 검증
  GAME_MANUAL.md      전투·모드·저장 구현 명세
  card_game_structure.md  모듈·화면 구조 지도
  CODING_GUIDE.md     수정 위치와 계약
  DESIGN.md           레퍼런스와 확정한 디자인 원칙
```

`card/game/`의 데이터·로직을 직접 읽어 빌드합니다. 학습 데이터를 별도 리마스터 복사본이나 런타임 오버레이로 관리하지 않습니다. 기존 컨트롤러와 보조 모드·다이얼로그는 기존 DOM ID를 유지하고, 주요 화면은 새 마크업과 렌더러를 사용합니다. 게임 소스의 스크립트 또는 화면 경계가 달라지면 빌드가 명시적으로 실패하게 해 계약 변경을 발견합니다. `card_legacy/`는 승격 시점의 보존본이며 활성 소스가 아닙니다.

규칙 재구현은 [GAME_MANUAL.md](./GAME_MANUAL.md), 모듈 연결은 [card_game_structure.md](./card_game_structure.md)와 [card_game_structure_visual.html](./card_game_structure_visual.html), 수정 위치는 [CODING_GUIDE.md](./CODING_GUIDE.md)를 봅니다.

## 검증

```sh
npm run verify
```

루트 변경 감지는 `card/` 변경 시 Card 정적 검사와 기존 게임 회귀 검사, DREAMWEAVER 단일 HTML 검증을 함께 실행합니다. Card만 변경했을 때 Defense 검증은 실행하지 않습니다.

검증은 실제 Chromium에서 `file://` 오프라인 부팅, 새 게임부터 저장/재로드, 소환·편성·필터·퀴즈, 16개 모드 초기화, TOEIC 파트 5/6/7 진행, 로컬 테스트 음원 재생과 배속 유지, 중첩 다이얼로그 포커스를 확인합니다. 360×800, 390×844, 412×915, 390×667 및 1440×960 화면을 검사하고 `test-results/`에 스크린샷을 남깁니다. 카드 이름 잘림과 로비 메뉴 겹침도 검증합니다.

실제 사용자의 모바일 기기, 비공개 초상화/음원 전체, 유료 또는 키가 필요한 실제 Gemini 응답은 자동 검증 환경에 없습니다. 테스트 음원과 작은 이미지로 로컬 로딩 경로를 검증하며, 화면 스크린샷의 카드 문양은 누락 초상화의 의도된 대체 표시입니다.
