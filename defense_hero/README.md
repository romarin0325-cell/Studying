# Hero Core Defense

`defense_hero/`는 모바일 가로 화면을 우선하는 독립형 캐릭터 중심 로그라이트 디펜스 프로토타입이다. Vanilla JavaScript ES Modules, Canvas 2D 전장, HTML/CSS 메뉴 UI만 사용하며 별도 빌드 단계나 런타임 의존성이 없다.

한 원정은 주인공 1명과 동료 4명으로 6개 스테이지를 진행한다. 다음 전장의 적 유형과 속성 비중을 먼저 확인하고 배치·성장 분기·보상을 선택하는 것이 핵심이다. 모든 절차형 선택은 문자열 시드에서 파생되므로 같은 시드와 같은 입력은 같은 지도·웨이브·속성·보상 후보를 만든다.

## 실행

ES 모듈을 사용하므로 `index.html`을 `file://`로 직접 열지 말고 정적 HTTP 서버로 제공해야 한다. 저장소 루트에서 프로젝트 전용 서버를 실행하는 방법이 기본이다.

```powershell
npm run serve:defense-hero
```

브라우저에서 `http://127.0.0.1:4173/`을 연다. 포트를 바꾸려면 실행 전에 `HERO_DEFENSE_PORT` 환경 변수를 지정한다.

Python 정적 서버도 사용할 수 있다. 저장소 루트에서:

```powershell
python -m http.server 8080
```

이 경우 `http://localhost:8080/defense_hero/`를 연다.

또는 앱 폴더에서 실행할 수 있다.

```powershell
cd defense_hero
python -m http.server 8080
```

이 경우 주소는 `http://localhost:8080/`이다. 메뉴는 세로·가로를 모두 지원하지만 전투는 가로 화면 기준이다. 작은 모바일 기기에서 세로로 전투에 들어가면 회전 안내가 표시된다.

## 화면 흐름

```text
타이틀
├─ 계속하기 ───────────────────────────────┐
├─ 새 게임 → 허브                         │
│            ├─ 원정 → 덱 편성 → 난도/시드·축복
│            │        → 원정 지도 → 위협 미리보기
│            │        → 배치/전투 → 성장 → 선택적 보상
│            │        → 다음 지도 … → 6스테이지 결과
│            ├─ 고정 도전 → 도전 선택 → 전투
│            ├─ 훈련장 → 영웅·적·속성·정예·상태·보스 선택 → 전투
│            ├─ 캐릭터 도감
│            ├─ 기록
│            └─ 설정
└─ 설정                                      │
                                             └─ 저장된 화면으로 복귀
```

- 타이틀의 `계속하기`는 유효한 `heroDefenseRun`이 있을 때만 나타난다.
- 원정 덱은 주인공 1명과 서로 다른 동료 4명이어야 한다. 공중·군집·중갑 대응 경고는 추천 정보이며 시작을 막지 않는다.
- 원정은 6스테이지이며 3스테이지와 6스테이지에 보스가 등장한다. 2·5스테이지는 전술 교본, 3스테이지는 유물 보상을 제공한다.
- 전투 중 앱이 백그라운드로 전환되면 자동으로 일시정지하고 체크포인트를 저장한다. 재개 시 투사체 단위 상태가 아니라 해당 스테이지의 준비 상태로 돌아갈 수 있다.
- 결과를 확정하거나 원정을 포기하면 현재 런과 런 백업을 삭제하고 메타 기록을 유지한다.

## 조작

메뉴에서는 카드나 버튼을 탭하고, 상단의 뒤로/홈 버튼 또는 브라우저 뒤로가기를 사용한다. 핵심 전투 조작은 다음과 같다.

| 행동 | 조작 |
| --- | --- |
| 동료 배치 | 하단 동료 초상화를 선택한 뒤 유효한 보드 칸을 탭한다. 경로·코어·장애물·중복 칸에는 배치할 수 없다. |
| 유닛 선택 | 하단 초상화나 전장에 배치된 유닛을 탭한다. 선택 정보, 사거리, 우선순위와 이동 쿨다운을 확인한다. 초상화나 전장 유닛을 0.55초간 길게 누르면 설명 모달이 열린다. |
| 재배치 | 배치된 유닛을 선택하고 `이동` 버튼을 누른 뒤 새 칸을 탭한다. 준비 중에는 자유롭게, 전투 중에는 유닛별 쿨다운에 따라 이동한다. |
| 회수 | 준비 중 `회수`로 배치 비용을 100% 돌려받는다. 스테이지 종료 시에도 모든 배치 비용이 자동 환급된다. |
| 주인공 이동 | 주인공을 선택하고 `이동`을 누른 뒤 세 개의 리더 거점 중 하나를 탭한다. |
| 주인공 액티브 | 우측 액티브 버튼을 누른 뒤 대상 지점을 탭한다. 조준 중에는 전투가 0.2배속이 되며, 발동하거나 같은 버튼으로 취소하면 이전 속도로 돌아간다. |
| 타깃 우선순위 | 선택한 유닛의 우선순위를 선두/강적/공중 중에서 바꾼다. |
| 전투 속도 | 상단 속도 버튼으로 1배속/2배속을 전환한다. |
| 일시정지 | 상단 일시정지 버튼을 사용한다. 전투 화면에서 뒤로가기를 누르면 준비 상태 저장 후 허브로 나갈 수 있다. |

아군은 자동으로 공격한다. 플레이어의 필수 판단은 위협 확인, 배치·재배치, 집중 성장, 주인공 액티브 타이밍이다.

## 구조와 상태 경계

```text
defense_hero/
├─ index.html                 앱 셸, 접근성 루트, 회전 안내
├─ css/app.css                메뉴·전투·모바일 가로 UI
├─ js/main.js                 GameApp 생성과 디버그 API 공개
├─ js/app/                    화면 라우팅과 원정 수명 주기
├─ js/core/                   루프, 이벤트, 시드 RNG, 속성 규칙
├─ js/state/                  MetaState, RunState, 저장소·백업
├─ js/data/                   캐릭터·적·상태·성장·스테이지 정의
├─ js/battle/                 스테이지 조립과 공용 전투 규칙/런타임
├─ js/render/                 Canvas 전장, 효과, 에셋 로더·실패 캐시
├─ js/ui/                     DOM 표현 보조 함수
└─ tests/                     Node 단위·통합 테스트
```

| 상태 | 수명과 내용 | 주 소유자 |
| --- | --- | --- |
| `MetaState` | 계정 영구 해금, 인연, 기록, 설정 | `SaveRepository`, `RunController`, `GameApp` |
| `RunState` | 덱, 시드, 현재 스테이지·노드, 코어 HP, 성장, 교본·유물, 통계 | `RunController` |
| Stage 상태 | 현재 맵, 변이, 특수 타일, 배치, 웨이브 큐 | 스테이지 빌더와 전투 런타임 |
| Entity 상태 | 아군·적 위치, HP, 쿨다운, 상태, 타깃 | 전투 런타임 |
| UI 상태 | 현재 화면, 선택 유닛, 모달, 액티브 대상 지정 | `SceneRouter`, `GameApp` |

경계 원칙은 다음과 같다.

- 렌더러는 상태를 읽어 그리며 피해·쿨다운·저장 상태를 직접 변경하지 않는다.
- `RunController`만 원정 phase와 메타 반영 시점을 관리한다.
- 앱과 원정 상태의 canonical RNG는 `js/core/SeededRng.js`이며 라벨 기반 `fork()`로 하위 스트림을 나눈다. `js/battle/SeededRng.js`는 같은 canonical 구현을 상속해 스폰 범위와 가중 선택 편의 메서드만 더한 전투 내부 어댑터다. 스테이지 조립·전투 스트림에만 사용하며 별도 난수 알고리즘이나 앱·저장 API로 취급하지 않는다. 어느 경계에서도 게임 판정에 `Math.random()`을 사용하지 않는다.
- `GameLoop`는 1/60초 고정 업데이트, 프레임 delta 최대 0.1초, 프레임당 catch-up 최대 5회를 적용한다.
- 속성은 역할·적 유형과 별도 축이다. 물→불, 불→자연, 자연→물, 빛↔어둠 우위에만 기본 최종 피해 ×1.20을 적용하며 불리 감산은 없다.

## 콘텐츠 추가

캐릭터별 전용 클래스는 만들지 않는다. 새 콘텐츠는 데이터 정의와 공용 효과 처리의 조합으로 추가한다.

### 캐릭터

1. `js/data/characters.js`의 `CHARACTER_DEFINITIONS`에 정의를 추가한다.
2. 안정된 내부 `id`, `kind`(`leader`/`companion`), `element`, `rolePrimary`, `roleTags`, `damageTypes`, `attackTags`, `targetPolicy`, `baseStats`를 지정한다.
3. 기본기·패시브·액티브는 `basicSkillId`, `passiveId`, `activeSkillId`와 `skills` 데이터로 연결한다. 성장 분기는 `upgrades`의 `level`, `branch`, `requiredUpgradeId`, `cost`로 표현한다.
4. 이미지 논리 키는 `assetIds.portrait`와 `assetIds.battle`에 기록한다.
5. 기존 공용 mechanics/effect로 표현할 수 없는 동작은 특정 캐릭터 ID 분기 대신 공용 효과 처리기에 재사용 가능한 효과 ID로 한 번만 추가한다.
6. `js/data/content.js`가 새 정의를 재수출하도록 연결하고 `validateContent({ throwOnError: true })`로 중복 ID, 없는 참조 ID, 잘못된 레벨·분기 비용과 맵 좌표를 검사한다.

### 적·웨이브·성장

- 적 유형·정예·보스: `js/data/enemies.js`
- 맵, 특수 타일, 웨이브 패키지, 스테이지 구성: `js/data/stages.js`
- 상태와 전역 필드버프: `js/data/statuses.js`
- 난도, 전술 교본, 유물, 변이, 시작 축복, 고정 도전: `js/data/progression.js`
- 속성 표시 메타데이터: `js/data/elements.js`; 실제 우위 규칙은 `js/core/ElementRules.js` 한 곳을 기준으로 유지한다.

새 보상·원정 후보는 canonical `SeededRng`의 명시적 fork 라벨에서 뽑고, 새 웨이브·전투 난수는 전투 경계의 deterministic helper와 명시적 namespace에서 뽑는다. 같은 시드에서 호출 순서가 흔들리지 않도록 지도, 웨이브, 적 속성, 보상처럼 독립된 하위 스트림을 사용한다.

## 에셋 규격과 폴백

에셋 계약은 정적 투명 PNG/WebP와 Canvas 코드 이펙트의 조합이다. `js/data/assets.js`에는 캐릭터 초상·전장 20개, 적 9개, 보스 2개의 논리 ID 31개와 경로·피벗·타입이 선언되어 있다. 아직 최종 미디어 파일은 없으므로 모든 항목은 `optional: true`, `fallbackAllowed: true`다. `validateContent()`는 로스터의 `assetId`가 이 manifest에 없으면 콘텐츠 오류로 보고한다. `js/render/AssetManager.js`는 manifest와 preload group, 이미지·오디오 성공 캐시, in-flight 요청 공유, 실패 URL 세션 캐시를 제공한다. 선택 미디어의 로드 실패는 `null`로 격리되며 앱 초기화를 막지 않고, 전장은 Canvas 코드 토큰과 도형 폴백을 사용한다.

| 종류 | 권장 규격 | 용도 |
| --- | --- | --- |
| 캐릭터 초상화 | 512×512 PNG/WebP | 덱, 도감, 결과 |
| 아군 전장 스탠디 | 256×256 투명 PNG | 발밑 피벗을 통일한 전장 표현 |
| 적 유형 | 128×128 투명 PNG | 일반 적 9유형 |
| 보스 | 256×256 투명 PNG | 보스 2종 |
| 공용 투사체 | 32~64px PNG 또는 코드 도형 | 별탄, 화염, 암흑, 수정 등 |
| 속성·상태·적 유형 아이콘 | 64×64 SVG/PNG | 색상과 함께 형태로 판독 |
| 배경·타일 | 128~256px 반복 타일 | 바이옴 바닥, 길, 장애물 |

- 속성별 적 이미지를 다섯 벌 만들지 않는다. 적 유형 원본 하나에 속성 아이콘·링·외곽광을 합성한다.
- 이미지가 없거나 로드에 실패하면 이름 첫 글자, 속성색, 역할/유형 아이콘이 있는 현재 코드 토큰으로 되돌아간다. 실패 URL은 세션 동안 캐시해 반복 요청하지 않고, 폴백 상태에서도 모든 판정과 화면 흐름이 동작한다.
- 공격 반동, 대기 바운스, 피격 플래시, 사망 페이드는 코드 애니메이션으로 처리하며 초기 프로토타입에는 스프라이트시트가 필요하지 않다.
- 생성·가공 에셋은 모델/출처, 생성일, 프롬프트 요약, 후처리 담당, 사용 범위를 `asset_sources.csv`에 기록한다.

## 저장과 호환성

저장은 주입 가능한 Web Storage 호환 인터페이스(`getItem`, `setItem`, `removeItem`)를 사용하는 `SaveRepository`가 담당한다. 브라우저에서는 `localStorage`를 사용하고 단위 테스트나 미래 버전 격리 세션에서는 `MemoryStorage`를 사용할 수 있다.

| 키 | 내용 |
| --- | --- |
| `heroDefenseMeta` | 해금, 인연, 기록, 최근 시드, 설정 |
| `heroDefenseRun` | 현재 원정의 덱, 시드, 노드, 코어, 성장, 보상, 통계 |
| `heroDefenseMeta_backup` | 검증된 메타 백업 |
| `heroDefenseRun_backup` | 원정 체크포인트 백업 |

- 현재 메타와 런은 각각 정수 `metaSchemaVersion`, `runSchemaVersion`을 저장한다.
- 손상된 기본 JSON은 유효한 백업으로 폴백한다. 둘 다 손상된 메타는 기본값으로 시작하고, 런은 없는 것으로 처리한다.
- 지원 버전보다 큰 저장은 읽거나 덮어쓰지 않는다. 앱은 해당 저장을 보존한 채 임시 메모리 세션으로 열고 경고를 표시한다.
- 읽고 다시 저장할 때 알 수 없는 추가 필드를 보존한다. 필드를 제거하거나 이름을 바꿀 때는 명시적 마이그레이션이 필요하다.
- 현재 버전이라도 덱·배열·중첩 객체 형태가 잘못되거나 수치가 음수/비유한 값이면 검증된 백업으로 폴백하거나 기본값으로 보정하고 경고한다.
- 새 메타의 해금 수·최고 기록 또는 같은 런의 진행도가 백업보다 명백히 낮으면 백업을 덮어쓰지 않는다.
- `clearRun()`은 기본적으로 현재 런과 런 백업을 함께 제거한다.

## 테스트

저장소 루트에서 Hero Core Defense의 단위·통합 테스트 전체를 실행한다.

```powershell
npm run test:defense-hero
npm run test:defense-hero:browser
```

필요하면 Node 테스트 러너로 범위를 직접 나눠 실행할 수 있다.

```powershell
node --test "defense_hero/tests/unit/*.test.mjs"
node --test "defense_hero/tests/integration/*.test.mjs"
```

콘텐츠 정의를 수정했다면 통합 데이터 검증도 실행한다.

```powershell
node --input-type=module -e "import('./defense_hero/js/data/content.js').then(m=>console.log(m.validateContent({throwOnError:true})))"
```

## 디버그 API

개발자 도구 콘솔에서 `window.__heroDefenseDebug`를 사용할 수 있다. 배포 화면에는 별도의 치트 버튼을 노출하지 않는다.

| API | 동작 |
| --- | --- |
| `getState()` | 현재 route, 메타, 런, 전투 스냅샷, 스테이지 계획의 복제본을 반환한다. |
| `completeStage()` | 전투 화면에서 현재 스냅샷을 성공으로 처리한다. 전투 밖에서는 `false`다. |
| `failStage()` | 전투 화면에서 현재 스냅샷을 실패로 처리한다. 전투 밖에서는 `false`다. |
| `setTimeScale(value)` | 전투 시간 배율을 0~20 범위로 설정하고 적용값을 반환한다. |
| `app` | 고급 진단용 현재 `GameApp` 인스턴스다. 저장 데이터 직접 변조 용도로 사용하지 않는다. |

예:

```js
window.__heroDefenseDebug.getState();
window.__heroDefenseDebug.setTimeScale(4);
window.__heroDefenseDebug.completeStage();
```

## 현재 프로토타입 범위

현재 데이터 범위는 주인공 4명, 동료 6명, 물·불·자연·빛·어둠 5속성, 적 유형 9종, 보스 2종, 4개 맵 골격, 12개 웨이브 패키지, 3개 특수 타일과 6스테이지 원정이다. 초기 해금은 루미·지크와 가디언·은토끼·눈토끼·그레이이다. 나머지 캐릭터와 월식 난도는 원정 클리어로, 고정 도전은 스테이지 3 도달→앞 도전 1별 달성 순서로 해금한다.

이 저장소의 코드는 전체 제품이 아니라 규칙·재현성·모바일 조작을 검증하는 수직 슬라이스다.

- 최종 일러스트·오디오가 없어도 코드 토큰과 Canvas 이펙트로 실행되는 것이 정상이다.
- 최종 PNG/WebP·녹음 오디오는 아직 없다. 에셋 로더와 코드 토큰 폴백, 코드 생성 경고/액티브/코어 SFX, 화면 흔들림·번쩍임·피해 숫자 토글은 작동한다.
- 성능 오버레이는 FPS, update/render 시간, 적·투사체·장판·재사용 풀 수를 표시한다. 평균 55fps 수치는 실제 목표 Android 기기에서 별도로 계측해야 한다.
- 서버 계정, 클라우드 저장, 온라인 랭킹, 결제, 멀티플레이는 범위 밖이다.
- 데일리 시드, 엔드리스, 추가 로스터, 풀 프레임 애니메이션, Android 네이티브 패키징은 프로토타입 승인 이후 범위다.
- 새 캐릭터나 효과를 늘리기 전에 결정론, 저장 무결성, 전투 상태 경계와 현재 4+6 로스터의 분기 동작을 우선 검증한다.
