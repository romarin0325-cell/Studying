# 코스튬 비율과 피격점 검증

2026-09-30. 기본 수호자 6명과 코스튬 12벌을 다시 비교했다. 최초 적용 당시 의상의 불투명 경계를 기본 의상의 가로·세로 경계에 각각 맞추면서 비균등 리사이즈가 발생했다. 특히 폭이 좁은 루미·루나·밤토끼 의상의 얼굴이 가로로 늘어났다. **실루엣 경계가 같다는 기존 검사는 비율 보존을 보장하지 못했으며, 해당 처리와 검사를 교체했다.**

## 원본 복원과 등록 방법

- 제공 폴더 `C:\Users\romar\Downloads\코덱스코스튬`의 의상 시트 4장에서 인접 칸을 제외한 각 캐릭터를 다시 분리했다. `assets/costumes/`에는 크기를 변형하지 않은 독립 투명 PNG를 저장한다.
- 기본 게임용 WebP와 원본 의상의 양쪽 눈 중심을 직접 확대해 측정했다. 눈 간격으로 하나의 축척을 정하고, 눈의 중점을 기본 의상과 같은 위치로 이동한다. 좌표는 `prepare-assets.mjs`의 `REFERENCE_EYES`, `COSTUME_REGISTRATION`에 기록했다.
- `sharp.resize({width})`로 가로·세로를 같은 배율로 처리한 뒤 512×512 투명 캔버스에 배치한다. 정수 픽셀 반올림 외의 축별 크기 변경은 없다. 옷·머리·무기의 자연스러운 폭과 길이는 유지한다.
- 새로운 캔버스도 중심 `(256,256)`을 사용한다. 눈 간격과 눈에서 피격점까지의 상대 위치가 기본 의상과 같으므로 얼굴을 넓혀 옷의 외곽 폭을 맞출 필요가 없다.
- 전체 분리 이미지가 캔버스 밖으로 나가면 빌드가 실패한다. 독립 이미지이므로 렌더러가 아틀라스의 이웃 칸을 읽지 않는다. 최종 WebP 비교 이미지에서도 다른 캐릭터 조각이나 잘림이 없는지 확인했다.

원본을 복원해 비교한 결과, 동일 컨셉의 이미지를 새로 생성할 필요는 없었다. 새 그림을 만드는 대신 제공된 얼굴·의상·장식의 비율을 보존했다. 눈 좌표는 수동 랜드마크이며, 모든 의상의 윤곽이나 포즈가 기본 의상과 완전히 같다는 뜻은 아니다.

## 기존 피격점과 실제 표시

기본 의상을 캔버스 중심에 겹쳐 확인한 피격점은 루미·지크·자스민·눈토끼의 상체/가슴 부근, 루나의 목 아래 장식 부근, 밤토끼의 목·옷깃 부근이다. 다음 비교에서 청록색 점이 동일한 `(256,256)`이다. 얼굴과 점 사이의 관계를 유지하며 옷의 외곽은 각 그림을 따른다.

![최종 WebP 비교: 기본, 첫 의상, 두 번째 의상. 청록색 점은 피격 중심](costume-size-comparison.webp)

행 순서: 루미, 루나, 지크, 자스민, 눈토끼, 밤토끼. 모든 칸은 같은 512×512 캔버스를 같은 크기로 표시했다.

타이틀·의상실은 정사각형 이미지 영역에 `object-fit: contain`을 사용한다. 전투에서는 기존 82×82 게임 좌표로 그리며 이미지 중심을 `player.x, player.y`에 둔다. 피격점과 그림을 분리시키던 상하 흔들림·반동 이동, 반동에 따른 세로 압축을 제거했다. 이동 기울기·피격 반짝임·공격 효과는 유지된다. 피격 반경과 전투 수치는 변경하지 않았다.

다크페어리와 아스테아는 앞선 패치의 교체 에셋을 유지한다. 이번 재처리 후에도 다크페어리의 경계 `(62,70,387,371)`, 아스테아의 경계 `(46,3,291,363)`이 유지됨을 검사한다.

## 검증

- `tests/costumes.test.mjs`: 실제 디코딩한 12개 WebP의 알파 경계와 원본 비율 비교, 눈 사이 거리 오차 1.2px 미만, 얼굴 중점 오차 각 축 1.5px 미만, 캔버스 잘림 없음. 이전처럼 옷 전체의 폭을 강제로 같게 만드는 검사는 사용하지 않는다.
- `tests/costumes-flow.mjs`: 12벌 모두 실제 의상실에서 착용하고 메인 화면·전투에 적용한다. Canvas `drawImage` 호출에서 82×82 크기와 피격점에 일치하는 이미지 중심을 검사한다. 발사 반동과 이동 기울기가 있는 상태에서도 검사한다.
- 320×568, 390×844, 430×932, 844×390 오프라인 Chromium: 메뉴 경계·고정 닫기·상점 카드·획득 이미지/문구 분리·구매 및 저장 동작을 검사한다.
- 실제 Android/iOS 하드웨어, Safari, 장시간 플레이 성능은 이번 검증에 포함하지 않았다.
