# 필살기 연출 제작 절차 (재사용용, 2026-11-06 · 3차 보강 2026-11-07)

1차(체리프린스·루나·혹한의마녀·하모니어스), 2차(자스민·여왕·시간의마술사·은하고래·시간의지배자), 3차(신데렐라·베놈·둠·루미와 꿈의 형태·레드드래곤·아우로라·별똥별소년)를 만든 방법을 다음 동료에게 그대로 쓰도록 정리한 문서다. 무엇을 보여 줄지는 [연출 기획서](plans/VFX_DIRECTION_PLAN.md), 왜 이 구조인지는 [제작 파이프라인](plans/VFX_PRODUCTION_PIPELINE.md)에 있다. 코드는 `src/combat/ur-vfx.js` 한 파일이다.

## 1. 먼저 정할 것

1. **정체성 확인.** `src/combat/engine.js` `cast()`에서 그 필살기가 실제로 하는 일을 읽고, 무엇이 주인공인지 정한다. 즉시 전체 타격은 대개 곁가지다.
   - 자스민: 전역 버프와 해제
   - 여왕: 골드
   - 시간의마술사: 변신
   - 은하고래: 끌어당김과 수확
   - 시간의지배자: 되감기와 정지

   스킬 이름, 설명, 자동 전투의 가치 계산(`smart-auto.js` `ultValue`)이 같은 답을 주는지 본다.
2. **읽히는 정보만 보여 준다.**
   - 고정 골드를 적마다 금화로 보여 주면 "적 수만큼 받는다"로 잘못 읽힌다. 여왕은 금화 분수 한 번이다.
   - 전역 버프의 지속시간은 우측 상단 HUD 타이머가 보여 준다. 아군마다 남는 표식은 두지 않고, 발동 순간의 판 전체 분위기에 투자한다.
   - 변신처럼 그 유닛만 바뀌는 것은 형태 자체가 표식이다.
3. **컷인 띠를 계산에 넣는다.** UR 컷인은 판 위쪽 5~31%를 1.6초 가린다(R·SR은 7~29%, 1.1초). 핵심 순간은 띠 아래에 두거나, 띠가 걷히는 1.3~1.7초에 맞춘다. 자스민의 날개가 그 예다.
4. **색 정체성.** 캐릭터 컨셉 색이 판 전체를 물들여야 한다. 흰색은 가장 뜨거운 심에만 쓴다. 은빛은 그것이 컨셉일 때만 쓴다(루나의 보름달, 혹한의마녀의 서리).

## 2. 에셋: 공용 키트를 먼저 본다

| 시트 | 칸 | 쓰는 곳 |
|---|---|---|
| `ur-kit` (1024×768, 4×3, 빛) | 베기 줄, 초승달, 고리, 안개, 파편, 섬광, 벚꽃잎, 얼음 가시 묶음, 가시, 보름달, 서리, 파편 폭발 | 모든 동료의 섬광·파동·조각, 일반 공격 접촉 불꽃 |
| `ur-kit2` (1024×1024, 4×4) | 빛: 마법진, 날개, 깃털, 시계판, 시계바늘, 빛기둥, 별빛 고래, 은하, 톱니, 모래시계. 물체: 유리구두, 장미, 장미 꽃잎, 가시 덩굴, 금화, 왕관 | 성스러운 빛, 시간, 왕실, 우주 |
| `ur-kit3` (1024×1024, 4×4, 14칸) | 빛: 나비, 불꽃, 불 숨결, 별똥별, 손거울, 유리 균열, 해, 초승달, 별, 종. 물체: 피안화, 봉투(2026-11-07부터 쓰지 않음), 단검, 뿌리 | 독·불·별·거울·꿈·밤의 거래 |
| `ur-sweets` (칠한 색) | 하모니어스 디저트 | 색을 색 지도로 만들 수 없는 것만 |

- 새 조각은 **키트로 만들 수 없을 때만** 만든다.
  - 균열, 리본, 빛줄기, 궤적처럼 선으로 되는 것은 코드로 그린다.
  - 같은 조각을 회전, 크기, 개수, 시간차, 합성으로 다르게 쓴다(벚꽃잎은 꽃잎 폭풍도 되고 상처의 꽃잎 폭발도 된다).
- 색은 `RAMPS`(색 지도)로 입힌다. 새 캐릭터에는 지도 하나를 더한다. 0 = 어두운 테두리, 0.3~0.55 = 채도 높은 컨셉 색, 0.78 = 밝은 색, 0.93 이상 = 흰 심.
  - 빛 조각은 밝기에 톤 곡선(`TONE`, 제곱)을 걸어 몸통을 컨셉 색 구간으로 옮긴다.
  - 물체 조각은 회색 음영으로 지도를 읽는다.
- 원본 크기와 디코딩 메모리는 시트 단위로 잰다. 2차 키트는 배포본 213KB, 디코딩 4MiB다.

## 3. 생성 (GPT 이미지, Codex)

폴더마다 `prompt.txt`와 참조(`style-ref.png`, 선택 `character.png`)를 두고 실행한다. 후보는 시트당 3장, 동시에 돌린다(장당 약 2~5분).

```bash
codex exec --skip-git-repo-check -s workspace-write -c model_reasoning_effort=low -C <폴더> -i style-ref.png -i character.png -o last.txt "$(cat prompt.txt)" < /dev/null
```

- **빛 조각**: 검은 바탕에 흰색·회색으로만("luminance maps", 색 금지). 칸 수와 배치, 여백 10%, 글자·사람 금지를 적는다. 참조 1은 기존 이펙트 스타일 판, 참조 2는 그 캐릭터의 기존 엠블럼을 모은 판이다.
- **물체**: "투명 배경 옵션을 켜라"고 적고, 회색 음영만 쓰게 한다. 결과 PNG에 실제 알파가 있는지, 색 픽셀이 0인지 확인한다. 검은 바탕을 지워 만든 물체는 밝은 바탕에서 검은 테두리가 남는다.
- 문구 견본은 `docs/art/ur-vfx2-20261106/kit{L,O,C}.prompt.txt`에 있다. 후보는 무손실 WebP(`exact`)로 출처 폴더에 보관한다.

## 5. 코드: 시퀀스 하나

`ur-vfx.js`에 객체 하나를 쓰고 `UR_SPECS`·`NEEDS`에 등록한다. 그 영웅의 아틀라스가 하나라도 없으면 이전 연출로 돌아간다.

| 항목 | 역할 |
|---|---|
| `life(skill)` | 연출 길이(초) |
| `plan(fx, skill)` | 시전 이벤트를 받아 `skill.ur`을 만들고, 적 uid → 화면상 타격 시각 `Map`을 돌려준다. 렌더러가 숫자·사망·체력바를 그 시각까지 보류한다. `skill.ur.moves`(적이 길을 따라 미끄러지는 표시), `skill.ur.gold`(HUD 골드 보류)도 여기서 넣는다 |
| `field` / `over` | 유닛 아래 / 위에 그리는 층 |
| `body` | 시전자의 몸 동작(dy, angle, squash, alpha, `form`)과 바라보는 방향(`direction`: down·up·left·right) |
| `unitBody` | 시전자 외에 이름이 오른 모든 유닛의 몸 동작(변신 전까지 `form:null`) |
| `persistent` / `persistentOver` | 지속 효과(서리 길, 트라우마 아래 빛) |
| `formChange` | 형태가 바뀐 순간(변신 해제) |
| `finisher` | 지연 일격의 엔진 임팩트를 받는다(체리프린스) |
| `impact`, `impactLife` | 지연 일격의 임팩트를 시전과 따로 그린다. `effects.js`가 엔진의 `finisherImpact`/`finisherFizzle` 때 효과 하나로 붙이므로 시전 연출이 끝난 뒤에도 남는다(아우로라 5초 거울, 별똥별소년). 이런 영웅의 옛 조준·비행 표시는 `drawFinisherLocks`/`drawFinishers`가 건너뛴다 |

- **엔진**에는 표시용 정보만 더한다. `look`이나 `marks`에 넣고 판정과 수치는 바꾸지 않는다.
  - 해제된 아군, 맞은 적, 이동 전 위치 `p0`, 거둔 성광 수, 세금과 칙령 금액
  - 3차: 숨결 중심점과 반경(`blast`, `radius`), 둠의 보너스(`bonus`), 별똥별에 쓴 별빛(`spent`)
- **도구 함수**: `kit`/`kit2`/`kit3`(색 입힌 조각), `glint`·`stardust`(골드드래곤식 별가루 반짝임, 선으로 그린 리본 대신), `slash`(베기 줄을 늘이고 굵혀 한 획), `butterfly`, `kitStanding`(땅에 서는 조각), `disc`(바닥에 누운 원), `clockHand`, `pillar`, `drawGhost`(실제 SD를 물들인 잔상·실루엣, 변신 형태 포함), `wash`, `vignette`, `skyLight`, `stars`, `snow`, `label`.
- **타격감**: `stun(fx, 흔들림, 히트스톱)`은 마지막 타격 한 번에만 크게 준다. 히트스톱은 시뮬레이션만 멈춘다.
- **연출 줄이기**(`fx.reduced`): 파티클·씻기·흔들림을 뺀다. 정보(누가 맞았나, 누가 정지했나)는 남긴다.
- `effects.js`에서 옛 표시를 끄는 곳:
  - 전역 버프 발밑 도장: `quiet`
  - 부분 오라 고리: 트라우마
  - 기절 별: `drawTimeStop`
  - 3차: 베놈 적 발밑 문양(`plagueBloom`)과 "플래이그" 글자, 자정의 종 문양(`drawMidnightBell`), 꿈의 형태(`DREAM`)
- **시퀀스가 아닌 필살기**(루미 꿈의 형태처럼 `urSpec`이 다루지 않는 종류)는 `effects.js`가 직접 부른다. 엔진이 나눠 치는 타격(`s.volleys`)의 남은 시간을 읽어 준비 동작을 그리면 UR 슬로·배속에서도 엔진 타격과 맞는다. 렌더러 시계로 그리면 슬로 동안 0.3초가량 어긋난다.
- **글자**: 컷인이 이름을 보여 주므로 시전 때 판 위에 이름을 다시 띄우지 않는다.
- **유닛에서 나가는 연출**(숨결, 발사): 유닛 그림은 방향 4장(정면·뒷모습·좌우 옆모습)이고 입이 열리지 않는다. 그래서 다음처럼 한다(레드드래곤, 2026-11-07).
  - 시전 동안 `body`가 `direction`으로 대상 쪽을 보게 한다. 골드드래곤도 숨결 때 대상을 본다.
  - 시작점은 머리 중심이 아니라 그 방향 그림의 실제 입·손 위치다. 아트 칸(512)에서 재서 상수로 둔다(`RED_MOUTH`). 머리 꼭대기에서 나가면 "머리에서 나간다"로 읽힌다.
  - 시작점은 작은 섬광으로 덮어, 입이 열리지 않는 것을 가린다.
  - 뒷모습(위쪽 대상)일 때는 `field` 층에 그려 머리 뒤에서 앞으로 나가게 한다.
- **소품은 캐릭터 컨셉에 맞춘다.** 키트 물체가 그 캐릭터의 세계관에서 어색하면 쓰지 않는다. 둠의 검은 봉투는 가죽 지갑으로 읽혀 레이피어 첩자와 맞지 않았다. 그래서 게임의 왕관 금화를 튕겨 레이피어로 가르는 연출로 바꿨다.

### 5.1 테스트와 예열

- `tests/ur-vfx.test.mjs`는 `UR_SPECS`의 모든 항목을 비교 도구의 실제 엔진 장면으로 시전해 전 구간을 그린다.
  - 검사: 예외 없음, `plan`이 돌려준 타격 시각이 연출 길이 안, `save`/`restore` 짝, 연출 줄이기 모드.
  - 예열이 만들지 않은 색 입힌 캔버스가 실제 시전에서 생기면 실패한다.
  - 그래서 새 영웅은 `scene.js`에 `mode:'skill'` 장면부터 더한다.
- `src/combat/ur-warm.js`는 전투 화면이 열린 뒤 유휴 시간에 덱의 시퀀스를 화면 밖에서 한 번 그려 색 입힌 조각을 미리 만든다. 첫 시전 끊김(데스크톱 실측 최대 122ms)을 없앤다.
  - 새 시퀀스가 엔진 상태(`finishers`, `volleys` 등)를 읽으면 예열의 가짜 상태에도 그 값을 넣는다.

## 6. 비교 도구와 검수

- 장면: `docs/review/ur-vfx-20261106/scene.js`에 `ENTRIES`(묶음 번호, 순간, 옵션, 의도 설명)와 `ROSTERS`(배치)를 더한다. 옵션이 필요하면 `reviewScene`과 `review.js`·`template.html`의 체크 상자에 넣는다.
- 빌드: `node defense/scripts/review-ur-vfx.mjs [--page <폴더>] [--base origin/main]`. 왼쪽은 main 렌더러, 오른쪽은 이번 렌더러다.
  - 왼쪽은 main의 `render.js`·`effects.js`·`ur-vfx.js`를 `before/`에 복사해 쓴다.
  - 그 밖의 공유 `src/` 모듈이 main과 다르면 빌드가 멈춘다. 예외(엔진의 표시용 필드, 에셋 경로)는 스크립트의 허용 목록에 이유와 함께 둔다.
  - 3차 첫 빌드는 `ur-vfx.js`를 복사하지 않아 왼쪽에도 새 연출이 그려졌다. 빌드 뒤에는 바꾼 장면 하나를 캡처해 두 열이 실제로 다른지 본다.
- 자기 검수 캡처:

```bash
node defense/scripts/review-capture.mjs --key queen --times 0.3,0.9,1.4 --only after --scale 0.5 --config "{\"theme\":\"bright\"}"
```

  - 상태 줄에는 보류 중인 숫자·잔상·히트스톱 누적·HUD 보류 골드·미끄러지는 적 수가 나온다.
- 볼 것:
  1. 정체성이 첫눈에 읽히는가
  2. 기존 연출보다 약하지 않은가
  3. 컷인 띠 아래에서 핵심이 보이는가
  4. 휴대폰 크기, Bright·새벽 정원, 연출 줄이기에서 괜찮은가
  5. 유닛 얼굴·체력바·위험 칸을 오래 가리지 않는가(여러 유닛을 동시에 하얗게 만들지 않는다)
  6. 25칸 밀집 일반 공격이 더 화려해지지 않았는가
  7. 색이 컨셉 색으로 읽히는가(비교 도구의 색 전환으로 은빛 v1과 비교)
  8. 한 장 비교표에서 판 전체를 하얗게 덮는 순간이 없는가(색과 편성이 함께 지워진다)
- 한 장 비교표: 모든 시퀀스의 절정 순간과 기준(애쉬·지크·팬텀)을 한 장에 모은다. 색 정체성과 일관성은 이것으로 판단한다.

```bash
node defense/scripts/review-sheet.mjs --theme night
```

- 구·신 한 장 비교표: 바꾼 장면마다 한 줄에, 장면의 순간들에서 기존과 적용 후를 나란히 놓는다.

```bash
node defense/scripts/review-sheet.mjs --pairs --theme night
```

- 빌드된 게임 확인: 배포 빌드(390×844)에서 저장 전투를 넣고 덱별로 필살기 버튼을 눌러 시전한다. 실제 컷인과 함께 화면을 남기고, 오류 수와 여왕 금화 때의 HUD 골드를 보고한다.

```bash
node defense/scripts/ur-game-smoke.mjs
```
