## 새 작업에서 읽을 순서

1. 이 문서와 [상세 제작 지침](art/sol-cast-v2/ART_PIPELINE.md)을 읽는다. 원화와 최신 설치 그림을 직접 본다.
2. 체형은 여성형·중립형·남성형, 키는 작게·보통·크게의 **9개 구조 틀**에서 고른다. 원본 의상과 정체성을 성별·체형 분류 때문에 재해석하지 않는다.
3. 동결된 `structure-masters/style-siren.webp`는 선·명암·SD 얼굴과 재질의 기준이다. 최근 생성한 다른 캐릭터를 매번 새로운 화풍 기준으로 바꾸지 않는다. 구조는 해당 마스터 또는 캐릭터 가이드를 실제 참조로 넣는다. 팬텀의 원래 가이드는 `structure-masters/phantom.png`다.
4. 공통 프롬프트의 원칙과 **원화를 보고 교정한 캐릭터 명세**를 함께 사용한다. 과거 프롬프트에도 원화 해석 오류가 있을 수 있다. 팬텀의 남색 코트·스타킹·부츠 명세가 실제 사례다. 원화의 별무늬 후드 잠옷·긴바지·맨발로 바로잡는다.
5. 생성 전에 실제 입력 순서·역할·해시와 정확한 프롬프트를 기록한다. 생성 뒤 원본·후보·선택 이유와 측정점을 남긴다. 구조 가이드를 보지 않았거나 입력에 넣지 않았다면 넣었다고 기록하지 않는다.

## 머리·몸·방향의 공통 기준

- **머리는 해부학적 두개골과 얼굴**이다. 뻗친 머리, 머리카락의 부피, 토끼귀, 모자, 뿔, 왕관, 후광, 무기와 배경 물체는 제외한다. 알파 외곽에 맞춰 전신을 자동 축소하지 않는다.
- 512px 셀에서 정면 두개골 목표 160×150px, 측면 깊이 목표 144px, 발 기준점 (256,480). 턱 아래 길이 목표는 작은 키 176·보통 188·큰 키 200px다. 이 값은 V2 제작 목표이며 가려진 해부학의 정확한 실측 결과를 의미하지 않는다. 기존 `HEAD_PROFILE.json`의 옛 후보별 배율 예외를 승인된 V2에 다시 적용하지 않는다.
- 고개를 기울인 그림은 회전 타원의 축·면적으로 추정하고, 턱·눈의 위치와 얼굴 인상을 별도로 본다. **같은 면적이 나오도록 패킹한 뒤 그 면적을 일관성의 독립 검증이라고 부르면 안 된다.** 눈 사이 거리·눈~턱·볼의 크기를 같은 키 동료 옆에서 대조한다. 머리카락으로 피부가 가려진 정도를 얼굴 크기로 치환하지 않는다.
- 한 캐릭터에는 전신 등방 배율 하나만 적용한다. 네 방향에서 발 위치를 맞추는 평행 이동은 허용한다. 머리나 다리만 늘이기, 가로·세로 별도 확대, 방향별 배율 변경으로 통과시키지 않는다. 비율 문제는 새 후보를 생성해서 해결한다.
- 정면·후면·실제 좌측·실제 우측을 만든다. 자연스러운 서기 또는 가벼운 전투 준비, 작은 시선·표정 변주를 사용한다. 물리적 장비의 고정 손·가림 관계를 유지한다. 모든 캐릭터를 공격 직전 포즈로 만들지 않는다.

## 통과에 필요한 증거

원화·수정 전·후를 같은 배율로 놓고, 4방향과 64/96px·밝은/어두운 바닥을 실제로 확인한다. 방향별 두개골·턱·발, 추정 불확실성을 남긴다. 실제 적을 좌우에 둔 게임 화면, Chromium 390×844 두 테마, 얼굴 아이콘 사용처를 확인한다. 방향 자동 검사와 해시 통과는 시각 품질 검수를 대신하지 않는다.

가려진 두개골은 수동 추정이다. 기존 원본 좌표의 ±18px·후면 ±26px·발 ±5px는 경계 불확실성을 표시한 값이며 통계적 신뢰구간이 아니다. 실제 캐릭터 리그를 돌린 결과가 아니므로 완벽한 해부학·회전 연속성을 보장한다고 표현하지 않는다.

UI 초상화는 [portrait-layout.js](../src/portrait-layout.js)의 작은 시각적 이동을 사용한다. 이것은 두개골 크기·전장 배율과 별개다. 편성뿐 아니라 목록·스킬·기록·파견·소환 결과 등에서 같은 `portraitFrame()`을 사용한다. 초상화가 작아 보인다고 유닛 전체를 키우지 않는다.

## 이번 팬텀의 실제 이력

[팬텀 기록](art/phantom-20261024/README.md)에 원화 오류, 실제 참조와 프롬프트, 생성 원본, 패킹·검수 결과를 남긴다. `candidate-v1/`은 의상 교정만 하고 구조 가이드를 생성 입력에 넣지 않았던 중간 후보다. 이를 최종 승인본이라고 부르지 않는다. 구조 가이드를 실제 입력으로 넣은 후속 생성은 별도 기록과 원본으로 구분한다.
