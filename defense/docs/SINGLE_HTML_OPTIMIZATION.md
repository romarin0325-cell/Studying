## 압축 패스와 사용처

| 패스 | 설정·대상 | 배포 사용처 |
| --- | --- | --- |
| 1. 미사용 내장 제외 | `blessings`, `relics`, `relics-expansion`, `relics-new` 4장 | 빌드 원본으로 보존; HTML·전투 preload에서 제외 |

| 3. 정적 이미지 | 필살기 WebP q90, 다른 아틀라스·밝은 배경 q85, 서재 그림 q82 / effort6 | 전투 이펙트·보스·배경·홈·소환·온실·서재 |

| 6. 텍스트·빌드 | CSS minify, JS minify 유지, 일반/Bright 공통 에셋·JS 한 번 처리 | 정식 단일 HTML 두 파일. 폰트·음악은 기존 WOFF2·Ogg Opus 유지 |

출력이 입력보다 작을 때만 별도 압축본을 채택한다. 현재 이미지 입력 158개 중 4개는 빌드 전용, 148개는 더 작은 별도 파일, 6개는 기존 바이트 유지다. 한 HTML에 본편 AVIF와 본편 WebP를 동시에 넣지 않는다. 압축 문자열 내장과 실제 이미지 디코딩은 별개다.

## 원본 보존과 경로 색인

제작 PNG가 Git에 없으므로 기존 `assets/merge`, `moonlit`, `bright`, `library`, `memorial`, `memorial-webp` 파일 전부를 압축 전 보관본으로 그대로 남겼다. 압축본은 `assets/optimized/` 아래 같은 하위 경로에 둔다. 소스·압축본을 둘 다 Git에 보관한다. 이는 원본 삭제나 Git 이력 재작성으로 용량을 줄이는 작업이 아니다.

- [전체 이미지별 경로·용도·설정·해시·해상도·바이트](ASSET_OPTIMIZATION.json): 실제 파일 검증에 사용하는 단일 목록.
- [압축 전후 비교 페이지](asset-optimization-review.html): 두 파일 링크, 밝은/어두운 바닥, 동료 정면 비교. `docs` 폴더 위치에서 열어야 상대 경로가 맞는다.
- `scripts/image-policy.mjs`: 압축 프로필, UI 파생 설정, Bright 교체 경로와 각 원본의 사용처.
- `src/asset-policy.js`: 빌드 전용 4장과 런타임 목록을 구분한다. 내장 제외 파일을 preload가 상대 경로로 요청하지 않게 한다.
- 폰트 원본 `assets/Jua-Regular.ttf`, 배포 `Jua-Regular.woff2` 둘 다 유지. BGM `assets/audio/*.ogg`는 그대로다.

## 변경 종류별 빌드 판단

| 바뀐 입력 | 실행과 커밋 |
| --- | --- |
| 원본 이미지·정적 압축 프로필·이미지 목록 | `node defense/scripts/optimize-images.mjs` 한 번; 정적/UI 압축본·목록·비교 HTML을 함께 커밋하고 게임 빌드 한 번 |
| UI 자르기/유물 그리드·UI 압축 프로필만 | `node defense/scripts/optimize-images.mjs --derived-only`; 바뀐 UI 출력과 목록을 커밋하고 게임 빌드 한 번. 입력·설정·인코더가 같고 검증된 출력은 재사용 |
| 게임 코드·CSS·문구 | 압축 패스 생략. 게임 빌드 한 번 |
| 일반 문서 | 제품 빌드·테스트 생략 |
| 원본 수치·그림·폰트 자체 | 해당 원본 provenance/수치 보고서만 갱신. 배포 압축만 바꾸면 과거 보고서 재생성 불필요 |

정식 빌드는 `node defense/scripts/build.mjs` 한 번으로 일반판과 Bright를 둘 다 출력한다. 공통 사전 생성 그림·음악·JS를 읽고 테마 CSS와 배경만 바꾼다. 날짜별 로컬 캐시 대신 Git에 보관한 고정 경로 UI 배포본을 사용한다. CI의 자동 비교는 정식 일반/Bright 출력만 대상으로 하고 불일치하면 실패한다. `--solo`, `--compat`, `--web`, `--unlocked`는 CI에서도 테스트 파일을 생성한다. 명시적 `--check`는 해당 출력의 비교 검사다. 줄바꿈은 LF로 정규화한다. 기존 `--bright`, `--solo`, `--compat`, `--web`, `--unlocked` 모드는 유지한다. 호환판 Base64 예산은 기존 WebP 바이너리 4 MiB 예산에 맞춰 5.5 MiB로 분리했다.

일반 빌드는 정적/UI 압축본과 보관본의 해시·코덱·해상도·알파·이미지 목록/프로필 일치를 검사한다. UI 목록은 원본 해시와 자르기/그리드 좌표도 비교한다. 누락·오염·설정 불일치가 있으면 수동 준비 명령을 안내하고 실패하며 자동 재인코딩으로 검사를 통과시키지 않는다. 변경된 원본을 이전 압축본과 섞지 않으며 갱신 명령을 안내하고 중단한다. 메모리얼 수동 준비 도구의 31명 고정 검사를 현재 HEROES 목록 비교로 바꿨다.

## 측정과 확인 범위

2026-10-24 로컬 실측: 정식 일반/Bright 공통 빌드 0.98초, CI solo 0.770초(수정 전 202.443초), compat 0.825초, web 0.908초, solo-compat 0.813초, unlocked 1.022초, Bright-unlocked 0.869초. 선택된 빌드/회귀 검사/선택기 검사 전체는 12.29초였다. UI 출력은 144개 / 3,245,812 B이며 기존 릴리스 내장 바이트와 동일하다. 준비 명령의 재실행도 인코딩을 막은 상태에서 144개 재사용 / 0개 재인코딩으로 통과했다. 기기·실행 조건에 따라 시간은 달라질 수 있으며 게임 FPS 측정은 아니다.

2026-10-24 회귀 검사는 `node --test defense/tests/build.test.mjs`로 실행한다. 인코딩 API를 실패시키는 상태에서 빈 임시 폴더에 CI solo/compat/web/solo-compat/unlocked/Bright-unlocked 출력을 생성하고, 명시적 `--check` 및 기본 CI의 Bright 비교가 오염된 파일을 거부하는지 확인한다. 검증 출력은 `--outdir`로 격리하며 검사 후 삭제한다. 준비 이미지 144개의 바이트가 기존 릴리스에 내장된 바이트와 같은지도 검사한다.

`npm run verify`의 빌드·에셋 검사 4개가 통과했다. 빌드 판단 변경은 선택기 검사 35개로 확인했다. `docs/ASSET_OPTIMIZATION.json`은 일반 문서가 아닌 배포 입력이며, `image-policy.mjs`, `image-pack.mjs`, `theme-bright.mjs`만 바뀌어도 해당 게임 빌드 한 번을 선택한다. 일반 Markdown와 과거 분석 JSON은 여전히 제품 검증을 선택하지 않는다.

과거 측정 `MEDIA_EFFICIENCY.md`, `FONT_OPTIMIZATION.md`, `MEMORIAL_MEDIA.md`는 당시 결과로 유지하고 현재 수치의 근거로 사용하지 않는다. 일반 문서·빌드 규칙 변경 때문에 과거 시뮬레이션이나 다른 게임 검증을 실행하지 않는다.
