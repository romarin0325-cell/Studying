# SD 캐릭터 머리 크기 교정 기준 — 2026-09-27

## 먼저 잘못된 판단을 수정한다

기존 21인 비교표에서 밤토끼·루미·머쉬룸킹의 머리는 지크·번개의 현자보다 크게 보였다. 파일 크기, 알파, 네 방향의 존재 여부를 확인한 것만으로 비율도 통일됐다고 판단한 것은 잘못이었다. 이전 기록의 `reviewed`, `accepted`는 사용자의 비율 승인을 뜻하지 않는다.

**머리란 정수리부터 턱까지의 두개부와 얼굴이다.** 토끼 귀, 뿔, 후광, 모자, 솟은 앞머리, 풍성한 머리카락, 뒷머리·포니테일은 두개부의 크기에 포함하지 않는다. 피부가 드러난 얼굴만 좁게 잘라 측정하는 것도 아니다. 이 기준을 사용자에게 다시 정의해 달라고 요청하지 않는다.

머리카락 아래 두개골은 그림에서 직접 보이지 않는다. 관자놀이, 볼, 턱선, 이마와 다른 방향의 그림을 함께 보고 복원한 **수동 추정**을 사용한다. 추정 좌표를 측정 정답처럼 포장하지 않는다. 특히 머쉬룸킹은 높은 옷깃이 턱을 가리므로 불확실성이 더 크다. 좌표와 그 좌표가 놓인 비교표를 함께 남겨 사람이 잘못된 판단을 고칠 수 있게 한다.

Scenario와 VNCCS는 도구 제작자의 기능 설명이다. 결과의 완벽한 일관성을 보증하는 독립 실험으로 인용하지 않는다. 내장 이미지 도구에 ControlNet 옵션이 노출되어 있다고 주장하지 않는다. 마네킹 참조도 생성 결과를 픽셀 단위로 강제하지 못하므로 사후 검수가 필요하다.

다음 제안은 그대로 채택하지 않는다.

- 키 설정에 비례해 캐릭터 전체를 확대하면 머리도 커진다. 머리 크기를 고정하라는 사용자 지시와 충돌한다.
- OpenPose 관절점만으로 두개골 폭과 높이가 같아진다고 보지 않는다.
- 실사 얼굴·포즈 검출기가 이 SD 그림의 가려진 정수리를 정확히 찾는다고 가정하지 않는다.
- 첨부 답변의 세부 모델 추천·강도 숫자·“업계 표준 오차”는 검증 없이 사용하지 않는다.
- 전체 이미지의 세로축만 눌러 몸 길이를 맞추지 않는다. 얼굴과 눈, 소품까지 찌그러진다.

## 현재 교정 방법

숫자의 원본은 [HEAD_PROFILE.json](HEAD_PROFILE.json) 하나다. 512px 셀, 발 기준점 `(256,480)`, 정면 두개부의 기준 높이 150px·폭 160px를 사용한다. 이는 **이 게임의 프레임 여백과 작은 화면에 맞춘 내부 규격**이다. 실제 의학적 비율이나 업계 표준을 뜻하지 않는다. 측면은 정면보다 좁게 투영될 수 있다.

[ANATOMICAL_LANDMARKS.json](ANATOMICAL_LANDMARKS.json)은 캐릭터마다 원본 SHA-256, 원본 정면의 두개부 좌우·정수리·턱 좌표, 네 방향 발 기준점, 추정의 한계를 기록한다. 파일이 바뀌면 좌표 승계를 차단한다.

배율은 정면 두개부의 폭과 높이의 곱으로부터 계산한다.

`scale = sqrt((기준 폭 × 기준 높이) / (추정 두개부 폭 × 추정 두개부 높이))`

이 값은 가로·세로에 같은 비율로 적용한다. 머리 모양을 억지로 늘이거나 줄이지 않는다. 단순 면적 대리 지표이므로 출력의 **폭과 높이도 각각 확인**한다. 두 값이 크게 어긋나는 원본은 이 계산으로 합격시킬 수 없다. 동일 캐릭터의 네 방향에는 하나의 배율을 공유한다.

포장 도구는 모자·귀·무기까지 포함한 외곽 크기로 자동 축소하지 않는다. 외곽은 잘림 검사에만 쓴다. 발은 소품 끝이나 그림자 아래가 아니라 기록된 발 기준점에 정렬한다. 실행 중 픽셀 분석은 하지 않는다.

현재 교정은 **머리 크기 통일을 우선하며, 키 등급에 따른 추가 전체 배율을 적용하지 않는다.** 사용자가 작은 SD에서 키 차이의 중요도를 낮추었기 때문이다. 키 차이를 추가할 경우 머리를 고정하고 턱 아래 몸통·다리만 다시 그려야 한다. 머리 정규화만으로 몸 길이까지 같아졌다고 주장하지 않는다. 기준 마네킹의 몸 길이와 기존 그림의 몸 길이는 별도 항목이다.

## 검수 순서

1. 동일 배율과 발 기준선에서 정면 21명을 나란히 확인한다. 두개부 추정선을 켜서 귀·모자·머리카락을 잘못 포함한 곳을 찾는다.
2. 추정선을 끄고 실제 얼굴·머리의 인지 크기를 확인한다. 숫자가 비슷해도 시각적으로 어긋나면 원본 또는 좌표를 다시 검토한다.
3. 네 방향을 비교한다. 뒤통수나 측면의 크기가 튀면 개별 방향을 몰래 자동 축소하지 않고 원본 그림을 수정한다.
4. 밝은 배경·어두운 배경, 작은 표시 크기, 25칸 전장으로 확인한다. 그림의 빈 여백까지 같은 크기로 표시한다.
5. 가려진 정수리·턱의 불확실성과 아직 확인하지 않은 방향을 기록한다. 알파·해시·파일 수 검사는 별도 기술 검사다.

## 이번 생성 실험의 처리

지크·밤토끼에 기존 그림과 공통 마네킹을 나눠 참조하는 내장 이미지 편집 실험을 했다. 첫 출력은 실제 투명이 아닌 체크무늬였고, 배경 수정본도 마네킹의 위치·몸 길이를 정확히 보장하지 않았다. 따라서 **새로 생성됐다는 이유만으로 게임에 채택하지 않는다.** 기존 원본의 정체성을 보존한 배율 교정 결과와 같은 기준에서 비교한다. 새 실험 시트는 캐릭터 비율의 승인 기준이 아니다.

## 새 캐릭터를 추가할 때

- 정체성 원본: 사용자 디자인·설정·성별·필수 의상.
- 화풍 원본: 고정된 선·명암·광원 샘플. 가장 최근 생성물을 무조건 다음 참조로 연결하지 않는다.
- 구조 원본: `make_defense_geometry_reference.mjs`로 만든 공통 마네킹. 숫자는 프로필 파일에서만 바꾼다.
- 방향: 정면·후면·좌·우의 같은 중립 자세. 공격은 기존 반동과 별도 이펙트로 표현한다.
- 생성 뒤 두개부 좌표, 발 기준점, 원본 해시를 등록하고 같은 비교표에서 재검수한다. 좌표가 없거나 출처 이미지가 바뀌면 자동 배율을 승인하지 않는다.

```sh
node scripts/make_defense_geometry_reference.mjs
node scripts/pack_defense_directions.mjs --source-dir SOURCE_DIRECTORY --landmarks defense/docs/art/ANATOMICAL_LANDMARKS.json --proof-dir PROOF_DIRECTORY
node scripts/export_defense_directions.mjs OUTPUT_DIRECTORY
```
