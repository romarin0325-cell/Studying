## 적용과 전처리

- 새 원본은 `assets/cast-selected-20261108/`의 1024×1024 PNG와 무손실 WebP다. PNG와 WebP의 보이는 RGBA 픽셀 차이는 다섯 명 모두 0이다. 선택 원본의 SHA-256도 복사 전후 동일하다.
- 전투 배포본은 이 무손실 원본에서 각각 640×640, WebP quality 90으로 만들었다. 다섯 파일 합계는 353,894B다. 무손실 WebP 합계 2,284,470B 대비 약 84.5% 작다. 손실 배포본을 새 마스터로 쓰지 않는다.
- 초상화·전신 UI 10개는 고해상도 원본에서 별도로 준비했다. `ASSET_OPTIMIZATION.json`에 원본·크롭·옵션·출력 해시를 연결했다. 다른 캐릭터의 152개 파생본은 재사용했다.
- 해부학적 머리 중심은 `data.js`, 작은 시각적 중앙 보정은 `portrait-layout.js`에 나누었다. 초상화 보정이 두개골 측정 좌표를 덮어쓰지 않는다. 전신은 한 캐릭터 안에서 공통 등방 배율이며 뷰별 늘이기나 모자·뿔의 외곽 맞춤 축소를 하지 않는다.
- 일반판·Bright·밸런스 랩과 추적 중인 Bright 테스트판을 새 이미지로 다시 묶었다. 실제 일반/Bright HTML 안의 전투 아틀라스·초상화·전신 15개씩이 최적화 매니페스트와 일치하는지 확인했다.

## 팬텀 대사

팬텀의 로비 대화·인사·합류·선물·메모리얼·의뢰·후일담에 남은 `크하하` 8곳을 `크큭...`으로 변경했다. 다른 캐릭터의 웃음은 보존했다. 메모리얼 본문이 달라져 해당 본문 무결성 해시도 함께 갱신했다. 팬텀 그림이나 게임 수치는 바꾸지 않았다.

## 실제 통합 검증

재현 명령은 `node defense/scripts/review-selected-cast.mjs`다. 별도 Chromium 문맥과 가상 저장 상태를 사용하며 플레이어 저장을 읽거나 변경하지 않는다. 실제 엔진의 타깃 선택으로 적을 상하좌우에 두고 다섯 캐릭터의 방향을 검증한다.

## 다음 제작부터 사용하는 정식 진입점

저장소 스킬 [star-garden-sd-art](../../../../.agents/skills/star-garden-sd-art/SKILL.md), [A–G 실행서](../sd-pipeline/RUNBOOK.md), [시각 도구](../sd-pipeline/index.html)를 사용한다. 루트와 Defense의 `AGENTS.md`에서도 이 경로를 안내한다. 참조 이미지는 명시적 입력이며 코드·의존성·기준 분포는 저장소에 버전 관리한다. 실제 독립 검사용 CPU 환경을 새 저장소 경로에 설치하고 세이렌 설치본을 측정해 실행 의존성을 확인했다.

그 [새 경로의 실제 측정](evidence/portable-siren-audit.json)에는 CCIP 정면/측면 거리 0.037이 동결 캐스트 p80 0.036을 소폭 넘는 원시 경고도 보존했다. 이 분류 거리의 경고가 얼굴 크기 불일치의 정답이 되거나 기존 그림 판정을 자동으로 뒤집지는 않는다. 코드·패키지·모델 캐시를 실제로 준비하고 측정했다는 근거로 사용한다.

기존 머리 크기·네 방향·몸 비율·원화·화풍·외곽선 검수를 누적 정책으로 유지한다. 픽셀·좌표·정책·실행 코드가 바뀌면 이전 판정은 무효화된다. 정식화는 새 작업의 순서와 증거를 강제하는 것이며 모든 생성 결과의 미적 성공을 자동 보장한다는 뜻은 아니다.
