# 유물 아이콘 화풍 복원 (2026-11-18)

유물 30종의 아이콘을 캐릭터 SD·선물 아이콘과 같은 화풍으로 다시 그렸다. 그림은 GPT(Codex image_gen)가 그렸고, 지시·채점·선택은 Claude가 맡았다. 전후 비교 도구는 [review/relic-restyle-20261118](../../review/relic-restyle-20261118/index.html)에 있다.

## 1. 진단: 왜 기존 유물이 "GPT 그림"으로 보였나

| | 캐릭터·선물 아이콘 | 기존 유물 |
|---|---|---|
| 선 | 따뜻한 짙은 갈색 외곽선 한 줄, 굵기 일정 | 외곽선이 약하고, 표면 안에 판화 같은 가는 선 수십 개(조각·문양) |
| 칠 | 셀 그림자 1단, 하이라이트 1개. 여왕 후광의 금색도 평평함 | 에어브러시 그라데이션, 젖은 듯한 광택, 림라이트, 4각 별 반짝이, 보석 안 은하 질감 |
| 디자인 | 장미 화관·호랑가시·털 장식처럼 형태와 부품에 디테일 | 30종 중 약 25종이 "금테 + 보석" 장신구 한 가지 틀 |

GPT에 "게임 유물 아이콘"을 주면 나오는 기본값이다. 이전 지시문(relic-patch-20261030)도 "ornate polished gold metalwork, luminous gems, warm rim light, soft inner glow"를 요구해 이 기본값을 굳혔다.

화풍(칠)과 디자인(형태·부품·모티프의 수)은 별개의 축이다. 캐릭터는 단순하지 않다(여왕 머리에만 장미 다섯 송이 가시 화관·살 18개 후광·빨간 브릿지). 디테일이 칠이 아니라 형태에 있다. 이번 작업은 칠을 캐릭터에 맞추고, 디자인 밀도는 등급에 따라 올렸다.

## 2. GPT 지시 방법

- 참조는 화풍만 준다: 여왕·산타 SD 정면, 선물 아이콘 시트, 같은 세트의 이미 만든 유물 시트. 기존 유물 그림은 주지 않는다(광택과 장식이 그대로 돌아온다).
- 형용사 대신 그리는 규칙을 쓴다: 외곽선 색·굵기, 셀 그림자 1단, 하이라이트 1개, "금속은 여왕 후광처럼 평평한 노랑+황토 그림자 하나+작은 하이라이트 하나". 원문은 [style.txt](style.txt).
- GPT 기본값을 이름으로 금지한다: engraving, filigree, gloss, rim light, sparkle stars, glints, glow halo, particles, galaxy texture, gem-in-gold-frame. 반대쪽 실패(굵은 선 스티커 클립아트)도 금지한다(첫 시험이 그쪽으로 넘어갔다).
- 디자인 밀도는 등급별로 따로 준다: C는 주 물건+부품 1~2개, R은 2~3개([design-common.txt](design-common.txt)), SR·UR은 4~6부품·3~4재질·세계관 모티프(장미·수국·달·리본)([design-high.txt](design-high.txt)). 등급의 빛·후광은 그림에 넣지 않는다(48px에서 물건이 작아진다). 그 몫은 UI 연출이다.
- 2×2 시트로 4종씩 그려 세트 일관성을 얻고, 투명 배경 옵션을 켠다. 실행은 [generate.sh](generate.sh): Codex에 셸·파일 쓰기를 시키지 않고, 세션 id 폴더(`~/.codex/generated_images/<id>/`)에서 직접 가져온다. 병렬 작업에 "결과를 복사하라"고 하면 서로의 최신 파일을 가져간다.

## 3. 품질 기준과 시도

기준과 후보별 점수·메모는 [scores.json](scores.json)(비교 도구의 "후보·채점" 탭). 통과 조건은 기술(T) 전부, 화풍(S) 6개 중 5개 이상, 디자인(D) 3개 이상. 고등급과 C·R 보강 회차부터는 등급 위계(D5)를 더했다.

| 회차 | 내용 | 결과 |
|---|---|---|
| 파일럿 | 화풍 A·B 각 2회, 4종 | 광택 제거는 성공, 선이 굵은 스티커 쪽으로 넘어감 → 가는 선·손맛 디테일로 보정 |
| 1차 | 30종(8시트) | 불씨 하트가 돌처럼, 프리즘 무지개 잘림, 금속 광택 잔존, UR이 수수함 |
| 2차 | 30종, 1차 지적 반영 + 1차 결과를 세트 참조로 교차 제공 | 음표 머리가 달걀처럼 보임 |
| 3차 | 금속 4종·뿌리·달조각·리본·음표 | 금속 광택 해결 |
| 고등급 | SR·UR 12종, 후광판(H)·부품판(P) 각 3시트 | 48px에서 H는 후광 때문에 물건이 작아져 P 채택 |
| C·R 보강 | 18종, 5시트×2회 | 17종 교체. 불씨 하트는 받침 접시가 판독을 해쳐 단순판 유지. 1장은 배경이 칠해지고 GPT 광택으로 회귀(탈락) |
| 사용자 수정 | 시간의 보석·꿈의 조각을 귀여움 대신 신비하게, 음표는 원래처럼 떨어진 두 개 | 3회 시도. 어두운 결정은 밤 테마 대비 때문에 가장 밝은 판 선택 |

총 GPT 이미지 41장, 후보 164개. 채택본이 들어 있는 원본 시트 13장은 [sheets/](sheets/)(무손실 WebP), 각 시트의 지시문 원문은 [prompts/](prompts/).

## 4. 게임 적용

- `assets/merge/relics-v2.webp`: 채택본 30종을 6×5(칸 512) 아틀라스로 묶은 빌드 전용 원본. `node defense/scripts/art/pack-relic-atlas.mjs defense/docs/art/relic-restyle-20261118/atlas-spec.json`이 위 시트에서 그대로 다시 만든다(칸 i = spec의 cells[i] = data.js의 icon).
- 기존 `relics`, `relics-new`, `relics-patch`, `relics-expansion` 아틀라스는 지우지 않고 빌드 전용 보관본으로 남겼다(`src/asset-policy.js`).
- 배포 아이콘 `assets/optimized/ui/relics/*.webp`(240px)는 `scripts/optimize-images.mjs`로 새 아틀라스에서 다시 잘랐다.
- 유물 이름은 바꾸지 않았다. 아래는 제안이다.

## 5. 이름 제안 (미적용)

현재 이름은 "~의 ~" 소유격이 14개이고, "꺼지지 않는·영원의·기적의" 같은 분위기 수식어가 물건이 아니라 분위기를 말해 효과를 짐작하기 어렵다. 구체적인 물건 이름에 효과의 손맛을 한 단어 얹는 방향으로 30개를 제안했다. 전체 목록과 이유는 [names.json](names.json)과 비교 도구의 "이름 제안" 탭.

예: 파도의 소라 → 밀물 소라, 쌍성의 거울 → 메아리 거울, 기적의 리본 → 덤 리본, 동행의 악수 → 짝꿍 장갑, 로열 크라운 → 저당 왕관, 시간의 보석 → 느림보 회중시계(그림이 신비한 쪽으로 바뀌어 다시 볼 것), 꿈의 조각 → 루미의 별조각.

## 6. 확인한 것과 못 한 것

- 확인: 아틀라스 칸 순서와 data.js 연결, 30종 240px 아이콘 재생성, 일반·Bright 빌드, 관련 테스트, 390×844에서 유물 화면(PR 본문 참조).
- 못 한 것: 등급 테두리·카드 프레임과의 조합을 사용자가 직접 승인하지 않았다. 축복 그림(`blessings.webp`, 미사용 빌드 전용)도 같은 GPT 광택 화풍이다.
