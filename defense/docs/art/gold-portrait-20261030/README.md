# 골드드래곤 · UI 초상화 소폭 보정

2026-10-30 사용자 요청. 최신 main의 동료 목록·편성·쌍성에서 골드드래곤의 눈·볼·턱이 작고 낮게 읽히는 점을 조정한다. 뿔·머리카락 외곽을 머리 크기로 취급하지 않는다.

| UI 프레임 | 이전 | 적용 |
|---|---:|---:|
| 512px 원본 내 크롭 중심 | (250,209) | (250,215) |
| 크롭 크기 | 250×250 | 240×240 |
| 준비된 초상화 | 240×240 | 240×240 |
| 보이는 배율 | 1 | 250/240 = 1.041667 |

확대만 한 후보와 중심을 함께 옮긴 후보,6.38% 확대 후보를160·96·64px에서 비교했다.4.17% 확대와y+6px 중심을 선택했다. 얼굴을 조금 위로 옮겨 낮게 읽히는 점을 줄이면서 기존 용족의 얼굴형과 표정을 유지한다. 둠을 비롯한 다른 동료의 크롭은 변경하지 않는다.

`portrait-layout.js`의 UI 프레임만 바꾼다. 원본1024px SD, 방향별 얼굴/발 기준, 실제 전장 아틀라스와 배율, 전신 그림·밸런스·이펙트는 그대로다. 기존 제작 기록의 두개골 타원과250px 초상화 기준을 소급 수정하지 않는다. `faceVars()`를 쓰는 소환 얼굴 크롭과 사전 준비 초상화가 같은 새 프레임을 사용한다.

`before.webp`는 base `d2d2d763e84cf4311202a76efb72cd327875d1ab`의 실제 UI 초상화 바이트다. `after.webp`는 새 고정 UI 초상화다. 원본 WebP SHA-256은`e7083366c6abc9e35d789625415e212380e98b231293fadfd03f7768acb3ba52`다. Before 자료는 당시의 프레임·이미지를 고정해서 사용한다.

검수는 동료 목록·일반 편성·선택 행과 최신 Bright 테스트 빌드의 쌍성 요약·편성·후보·출격 준비를390×844에서 수행한다. 뿔 끝의 일부는 기존처럼 초상화 프레임 밖에 있으며, 눈·볼·턱이 잘리거나 배지에 가리는지 확인한다. 눈 사이 거리나 목표 두개골 면적만으로 얼굴이 완전히 같다고 판정하지 않는다.

검증 결과·변경 파일 해시는`verification.json`, 실제 화면 치수와 오프라인 결과는`browser-verification.json`, 선택 후보는`selection.json`에 보관한다. 비교 페이지는`build-review.mjs`로 재생성한다.

## 검증 결과

- `npm run verify -- --only defense`: 이번 변경에 선택된 에셋·배포 계약10개 통과. 일반판·Bright·밸런스 랩 갱신, 별도`--preview`로 쌍성 테스트본도 갱신했다.
- 기존 정적 이미지186개와 나머지 UI 파생본158개의 해시 유지. 골드드래곤 초상화1개만24,778B에서24,952B로 바뀌었다(+174B).
- Chromium390×844·DPR2 실제 HTML19캡처: JS 오류0·외부 요청0·가로 넘침0·누락 이미지0. 동료·일반 편성·쌍성·전투 정보·필살기 원형 초상화를 확인했다.
- 검수 페이지는1280px·390px 및64·96·160·240px 표시에서 가로 넘침과 종횡비 왜곡이 없는지 확인한다. 실제 휴대폰 FPS나 완벽한 얼굴 크기 동일성을 보증하는 검사는 아니다.
