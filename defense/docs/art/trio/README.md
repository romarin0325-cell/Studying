## 원본 의상과 방향

원본은 사용자 폴더의 `혹한의마녀.png`, `하모니어스.png`, `퍼펙트아우로라.png`와 `컨셉.txt`를 직접 확인했다. 원본 파일 해시는 [REFERENCE_HASHES.json](REFERENCE_HASHES.json), 채택한 생성본과 전체 생성·교정 프롬프트는 [GENERATION.json](GENERATION.json)에 있다. 기존 승인된 루미 아틀라스를 고정된 그림체/체형 참고로 사용했다.

- 마녀: 얼음 왕관, 은청색 머리, 푸른 눈, 흰 의상과 푸른 가슴 보석, 열린 어깨, 긴 반투명 소매와 갈라진 옷자락, 흰 발목끈 구두.
- 하모니어스: 민트색과 노란 끝의 양갈래, 산호색 리본, 흰 짧은 블라우스, 금방울·딸기, 과일 무늬 치마, 민트색 샌들과 발가락. 하트 장식은 해부학적 왼쪽 허리, 솜사탕은 오른손.
- 아우로라: 은보라색 긴 머리, 오른쪽 머리 말이와 장식, 보랏빛 눈과 장난스러운 미소, 옅은 보라색 겹옷, 은장식·푸른 보석 목걸이, 허벅지 장식, 맨발. 정면의 화면 왼쪽 장식은 후면의 화면 오른쪽에 오며, 좌측면에서는 가려지고 우측면에서 드러난다.

[원본/SD 의상 비교](review/costume-reference.png). 원본에 없는 후면의 봉제·겹침은 확인 가능한 앞/측면 구조를 이어 추정했다. 약 2등신과 작은 실제 표시 크기에 맞춰 자수 밀도, 얇은 장식과 주름을 단순화했다. 원본과 픽셀 단위로 동일한 복제 또는 작가 승인을 주장하지 않는다.

## 머리와 체격 검수

머리는 **두개골과 얼굴**이다. 노출 피부의 경계만 머리로 삼지 않으며, 귀·왕관·머리 말이·양갈래·리본·솜사탕·옷자락은 측정하지 않는다. 관자, 턱, 귀의 부착 위치와 가르마를 단서로 가려진 두개부를 추정했다.

[LANDMARKS.json](LANDMARKS.json)은 각 방향의 두개부 사각형·턱·발 기준점과 불확실성을 원본 SHA-256에 묶는다. 정면 두개부 면적에서 하나의 균일 배율을 구해 네 방향 모두에 사용하고, 발을 (256,480)에 맞춘다. X/Y를 별도로 늘리지 않고, 머리카락 외곽 때문에 몸을 자동 축소하지 않는다. 넘치는 불투명 픽셀은 패킹 오류다.

| 동료 | 정면 두개부 W×H / 512 셀 | 턱~발 | 판단 |
| --- | --- | --- | --- |
| 혹한의마녀 | 159.5 × 150.5 | 194.7 | 조금 긴 몸 |
| 하모니어스 | 165.1 × 145.4 | 182.3 | 조금 짧은 몸 |
| 아우로라 | 157.6 × 152.3 | 185.3 | 중간 |

가려진 경계 오차는 원본에서 약 ±8~12px(후면 약 ±12px), 패킹 후 약 ±6~9px다. 작은 키 차이의 정밀한 순위를 이 숫자만으로 인증할 수는 없다. 정면 머리 폭은 공통 목표 160의 ±3.2%, 높이는 목표 150의 ±3.1% 안이다. 측면은 원근상 좁은 별도 목표 144와 비교하며, 각 방향은 기존 프로젝트 검수 허용 범위 안이다. 이는 업계 표준이나 자동 해부학 판정이 아니다.

## 에셋과 빌드

선택한 4방향 PNG 원본은 `sources/`에 보존했다. 미채택 이미지 생성 결과는 사용자의 원래 generated_images 폴더에 남아 있다. PNG는 런타임 배포에 포함하지 않는다.

| 에셋 | PNG 원본 | 준비된 WebP |
| --- | ---: | ---: |
| 혹한의마녀 4방향 | 1,325,015 bytes | 230,260 bytes |
| 하모니어스 4방향 | 생성 원본 보존 | 307,090 bytes |
| 아우로라 4방향 | 1,221,781 bytes | 204,778 bytes |
| 신규 효과 6셀 | 생성 원본 보존 | 49,942 bytes |

캐릭터 시트는 1024×1024, 512px 셀 4개다. 알파 250 이상만 불투명으로 정규화하며 RGB와 부드러운 외곽 알파를 유지한다. 흰색을 지우는 키 처리는 하지 않는다. 효과는 검정 screen 합성용 3×2 시트이며 셀마다 20px 여백을 둬 이웃 셀이 섞이지 않는다. 이펙트의 셀 맞춤은 캐릭터 배율 산정과 별개다.

43개 WebP를 내장한 통합 HTML은 `defense/dist-local/HeroCoreDefense.html`이다. 런타임 이미지 전처리는 없고, 해시 캐시는 알파 에셋 37개를 재사용하며 재빌드 시 디코딩 0개를 확인했다.

## 재현과 확장 절차

```powershell
node defense/tools/pack-trio-art.mjs
node defense/tools/build-trio-review.mjs "C:\Users\romar\Downloads\캐릭터"
npm run prepare:defense-art
npm run verify
npm run verify -- --only defense
node defense/tools/check-trio-browser.mjs
```

1. 새 캐릭터마다 원본 컨셉·의상 구조·비대칭을 먼저 기록한다. 고정된 승인 스타일 참조를 사용하고 앞선 생성의 드리프트를 새 기준으로 삼지 않는다.
2. 머리 크기를 유지한 채 짧은 몸을 **다시 그린다**. 몸이 길다는 이유로 전신을 축소하거나 비균일 압축하지 않는다.
3. 4방향의 얼굴/두개부, 턱, 발 기준점을 직접 읽고 가려진 부분의 오차를 기록한다. 새 이미지가 나오면 해시와 좌표를 새로 검수한다.
4. 하나의 배율·발 앵커로 패킹한다. 실루엣이 넘치면 원본 구도/장식을 다시 그리며 머리 목표를 몰래 바꾸지 않는다.
5. 64/96px 어두운·밝은 배경, 기존 동료, 실제 5×5 전장에서 비교한다. 숫자 통과를 시각 승인으로 대체하지 않는다.
6. 고유 능력·현재 능력치·편성·합성·강화·진행 저장·알파 실패 시 동작·오프라인 HTML까지 연결하고 필요한 검증을 수행한다.

## 검증과 한계

- 기존 및 신규 전투 단위 검사 69개 통과. 별도로 아트 해시·알파·124개 방향·효과 여백을 검사했다.
- 루트 `npm run verify`와 명시적 `npm run verify -- --only defense`의 선택된 필수 검증 통과. 루트만으로 Defense 검증을 대신하지 않았다.
- [브라우저 결과](review/gameplay/results.json): 실제 `file://` 통합 HTML에서 320×568 / 390×844, 일반 / 효과 감소, 세 필살기 12조합. 추가 네트워크 요청 전부 차단. 별도로 편성, 현재 스펙, 일반 공격/반사, 25칸 네 방향을 확인했다.
- 저장 중인 반사·거울이 같은 결과로 재개되며, 기존 저장 필드를 유지하고 새 서리 필드만 보충한다.
- Chromium 데스크톱의 모바일 뷰포트 검증이다. 실제 Android/iPhone, Safari/Firefox, 발열·메모리와 장시간의 재미/밸런스 인증은 아니다. 보이는 방향별 원근·표정의 미세한 차이와 가려진 후면의 추정은 남아 있다.
