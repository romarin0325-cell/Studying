# STAR GARDEN · Sol 전체 캐스트 제작·검수 지침

이 문서는 사용자에게 전달한 `Downloads/캐릭터/에셋/gpt/cast-v2-20261024` 전체 제작 아카이브에서 가져왔다. 본문의 `originals/`, `baseline/`, `masters/`, `guides/`, `records/` 등은 그 아카이브 기준이다. 현재 Git 설치본은 `defense/assets/cast-v2/`의 최종 PNG·WebP, 이 폴더의 `manifest.json`, 별도 배포 압축본과 UI 파생본을 보관한다. 현재 통합 검증은 [설치 기록](../../CAST_V2_AND_BALANCE.md)을 본다.

이 폴더는 기존 Defense Test 에셋과 새 제작본을 비교하는 독립 아트 패키지다. 대상은 플레이어 동료39종과 트라우마 변신1종, 총40종·160방향이다. 비교 기준은 로컬 게임 스냅샷 `fa6fcff4bdb225433ad044b4f7ae68b547509192`이다. `catalog.json`에 원화와 기존 에셋의 출처·동결 해시가 있다. 새 캐릭터를 추가할 때도 이 기록을 남기고, 기존 검토본을 덮어쓰지 않는다.

## 1. 원본·화풍·구조의 역할을 분리한다

- **정체성**: `originals/`의 원화를 직접 본다. 설정 텍스트만으로 의상·머리 장식·무기를 추측하지 않는다. 원화의 얼굴, 색, 소재, 의상 구조와 문양을 우선하고 SD에 필요한 만큼만 단순화한다.
- **화풍**: 동결된 `baseline/siren.webp` 한 장을 공통 선·명암·재질 기준으로 쓴다. 매번 직전에 생성한 다른 캐릭터를 새 화풍 기준으로 삼지 않는다.
- **구조**: `masters/`, `guides/`, `combat-guides/`의 실제 절차적3D 메시 렌더를 쓴다. 이 회색 모델은 머리·몸·시점·가림 관계의 참고이며, 완성 캐릭터 모델이나 장비 디자인이 아니다.
- **최종 판정**: 원화와 같은 크기 비교, 네 방향, 64·96px, 밝고 어두운 배경을 실제로 눈으로 확인한다. 프롬프트를 지켰다는 문장이나 동일한 파일 크기를 검수 결과로 대체하지 않는다.

이미지 생성·수정은 이 작업에서 사용한 내장 `image_gen`으로 진행했다. 캐릭터 해석·선택은 Sol이 수행했다. 도구가 실제 이미지 백엔드의 세부 버전은 노출하지 않아 추정해서 이름을 붙이지 않았다.

## 2. 머리는 두개골과 얼굴이다

토끼귀, 머리카락의 부피, 모자, 왕관, 뿔, 후광, 머리 장식, 무기와 배경 물체는 머리 크기가 아니다. 외곽 알파 바운딩 박스를 얼굴 크기로 쓰면 안 된다. 머리 위 부속물 때문에 몸 전체를 셀에 자동 축소하는 처리도 금지한다.

두개골은 머리카락·모자 아래의 해부학적 덩어리를 추정한다. 앞머리 때문에 노출 피부가 적다고 머리를 키우거나, 턱을 가린 목깃 때문에 얼굴을 축소하지 않는다. 머리를 기울인 경우 가로·세로 AABB가 커지므로 회전한 타원의 축과 면적을 기준으로 비교한다. 실제 보이는 얼굴의 인상도 별도로 확인한다.

`measurements.json`의 타원은 `[중심x, 중심y, 너비, 높이, 기울기]`이며 원본 생성 이미지의 전체1254px 좌표다. 턱과 발 기준점도 별도로 기록한다. 뒤통수와 모자 아래는 **추정값**이다. 기본 경계 불확실성은 원본 정면±18px, 후면±26px, 측면±18px, 바닥±5px로 기록했다. 이는 통계적으로 측정한 오차나 신뢰구간이 아니다. 가디언 후면처럼 완전히 가려진 두개골은 ±60px, 머쉬룸킹처럼 모자·목깃이 가린 경우는 더 큰 값을 명시한다.

## 3. 공통 몸과 작은 개성

몸 프레임은 여성형·중립형·남성형3종이며, 각각 조금 작게·보통·조금 크게3단계다. 총9개 구조 마스터다. 프레임 이름은 원화의 실루엣을 위한 제작 분류다. 성별 설정을 이유로 의상이나 체형을 재해석하지 않는다. 바니 의상의 세 토끼, 루미, 신데렐라의 원래 디자인도 그대로 존중한다.

512px 구조 셀에서 정면 두개골 목표는160×150px, 측면 깊이 목표는144px, 바닥은(256,480)이다. 턱 아래 길이 목표는176·188·200px이다. 키 변화는 주로 턱 아래 몸에서 만들고 머리는 거의 같게 둔다. 어깨·허리·골반의 폭은 프레임에 따르되 얼굴은 성별에 따라 다르게 확대하지 않는다.

기본 자세는 **자연스럽게 서 있거나 가볍게 전투를 준비하는 정도**다. 무기를 든 캐릭터만 공격 직전 자세가 되지 않도록 한다. 큰 칼을 치켜들거나 찌르기 직전으로 내밀기, 넓은 다리 벌리기, 큰 팔 동작, 과한 허리·고개 비틀기는 기본 대기 에셋에서 피한다. 무기를 반드시 내리는 규칙도 아니다. 그 무기의 무게를 자연스럽게 지지하고 캐릭터에 맞는 편한 자세를 고른다.

허용할 작은 변주는 약한 체중 이동, 가까운 무릎과 가벼운 발목 교차, 미세한 고개 기울기, 낮게 든 작은 소품, 입꼬리·눈썹·시선이다. 모든 캐릭터에 특별한 포즈를 하나씩 강제로 넣지 않는다. 원화에 있는 비대칭은 보존한다.

## 4. 방향과 손·장비

아틀라스는 왼쪽 위 정면(↓), 오른쪽 위 후면(↑), 왼쪽 아래 실제 왼쪽 측면(←), 오른쪽 아래 실제 오른쪽 측면(→)이다. 한 캐릭터와 같은 미세한 자세를 회전한 것으로 생각한다.

3D 가이드의 해부학적 오른팔은 청록색, 왼팔은 분홍색이다. 왼쪽을 보는 측면에서는 캐릭터의 왼팔이 카메라에 가깝고, 오른쪽 측면에서는 오른팔이 가깝다. 정면의 화면 왼쪽 손은 캐릭터의 오른손이다.

- 창·검·우산의 잡은 손과 고정 장착 위치를 먼저 정한다. 후면과 측면에서도 같은 손과 연결점이 이어지는지 확인한다.
- 비대칭 무기·검집·귀걸이·머리 장식·가터가 있으면 좌우를 무조건 반전하지 않는다. 반전을 택했다면 실제 비대칭을 되돌려 교정하고 별도 기록한다.
- 가까운 빈팔이 내려와야 하는 측면에 무기 팔이 붙는지, 먼 손의 무기를 가까운 손이 잡은 것처럼 그렸는지 확대 확인한다.
- 우산은 앞·뒤에서 같은 판을 머리 뒤에 붙이지 않는다. 우산 안쪽과 볼록한 바깥면, 손잡이·줄기, 실제 얼굴 가림을 3D로 확인한다. 가디언 후면에서 우산 바깥면이 뒤통수를 가리는 것은 물리적으로 맞는 가림이다.
- 작은 마법 구체·불꽃의 손은 시각 품질과 캐릭터의 매력을 위한 방향별 변주를 허용한다. 물리적 장비의 고정 손과 같은 강도로 강제하지 않는다. 완전한 동일 포즈3D 연속성이라고 주장하지도 않는다.

이 작업에서 자스민의 지팡이는 왼손, 번개의현자·시간의마술사·여왕·은하고래의 지팡이는 오른손으로 정리했다. 지크는 대검을 양손으로 받친다. 둠은 앞으로 내민 후보보다 자연스럽게 선 원안을 선택했다. 루나는 조용한 허리 높이의 곡검 자세를 유지했다.

## 5. 원화에서 특히 오인하기 쉬운 점

- 은하고래 뒤의 푸른 고래와 궤도는 **배경**이다. 고래 지느러미나 귀·왕관으로 만들지 않는다. 실제 이마 펜던트, 고래형 가슴 장식과 별 지팡이는 보존한다.
- 큐어마스터의 간호 모자·리본·양갈래는 두개골 측정에서 제외한다. 정면의 오른눈 윙크가 같은 눈의 측면으로 이어지는지 확인한다.
- 언더독은 별도 모자가 아니라 검은 가죽 후드다.
- 밤토끼의 하의는 막힌 검은 쇼츠이며, 후드 아래 의상을 구멍 난 하의로 만들지 않는다. 별도 단일 가터는 왼쪽 허벅지다.
- 애쉬의 머리 장식은 검은 깃털이며, 의상은 검은 레이스와 광택 있는 보디슈트·스타킹이다. 군복이나 흰 러플 셔츠로 대체하지 않는다.
- 화염의현자의 흰 가슴 띠는 원화에 실제로 있다. 새로 생긴 오류로 오판해 지우지 않는다.
- 세이렌의 금색 별 장식이 다른 캐릭터에 섞이지 않았는지 확인한다.

## 6. 생성과 재작업 기록

최종 그림만 보관하지 않는다. 원본·동결 비교본·구조 가이드·실제 생성 프롬프트·참조 순서·생성 원본·후보 선택 이유를 남긴다. 경로와 SHA-256을 생성 전에 기록하는 것이 원칙이다. 후속 수정은 새 버전을 만들고 이전 파일을 유지한다.

현재 `records/`는 실제 수정 참조를 다시 대조해 정리했다. 초기에 가이드가 수정되어 정확한 당시 바이트가 남아 있지 않은 지크·체리프린스·신데렐라 파일의 가이드 해시는 `null`과 설명으로 남겼다. 현재 가이드의 해시를 과거의 실제 입력이었다고 바꾸어 쓰지 않았다. 이미 남은 생성 프롬프트를 새 해석에 맞춰 소급 수정하지 않는다.

다음 생성에서 캐릭터별 초안 텍스트와 원화가 다르면 원화를 다시 확인하고, 실제 수정 프롬프트를 새 버전으로 남긴다. `character-specs.mjs`와 `review-notes.json`은 현재 선택의 해석이며 과거 프롬프트를 대신하는 증거가 아니다.

재작업은 구체적인 문제에 한정한다. 얼굴·표정·의상·선·재질이 이미 좋으면 유지한다. 비율이 잘못된 경우에는 이미지 모델로 몸을 다시 그린다. 픽셀 조각을 가로·세로로 각각 늘리거나, 목·몸 경계에 붙여 넣거나, 발 기준을 바꾸어 키 차이를 숨기지 않는다. 결과가 목표보다 길거나 짧게 나오면 다시 비교해서 선택한다.

## 7. 정규화와 전처리

`pack-assets.mjs`는 정면 두개골 추정 타원에서 한 캐릭터의 전신 등방 배율 하나를 정한다.

`scale = sqrt((160 × 150) / (원본 두개골 너비 × 높이))`

같은 배율을 네 방향 전신에 적용하고, 방향별로 평행 이동만 하여 발 기준을(256,480)에 둔다. 전체 외곽을 셀에 맞춰 자동 축소하거나 방향별로 다른 배율을 쓰지 않는다. 비등방 늘리기나 머리·다리 따로 확대는 하지 않는다.

원본 네 방향은 무조건1254/2에서 잘라서는 안 된다. 윗행 발과 아랫행 귀가 세로로 겹치는 원본이 있다. `source-views.mjs`는 알파와 연결 성분을 기준으로 네 그림을 분리하고 전체 원본 좌표를 유지한다. 중간에서 맞닿은 머리카락은 세로 연결 경계로 분리한다. 투명 배경의 작은 고립 잡음을 제거하되 캐릭터의 실제 그림을 잘라내지 않았는지 확인한다. 알파32 이상 그림이 셀 밖으로 잘리면 실패시키며 자동 축소로 통과시키지 않는다.

배포용 기본본은1024×1024 아틀라스(512px 셀), PNG 보존본과 WebP 품질95·알파100이다. 방향별 PNG160장은 최종 아틀라스에서 손실 없이 추출해 픽셀이 일치하게 한다. 별도 모바일용512×512 아틀라스(256px 셀)는 품질94·알파100이며 기본1024 보존본을 대체하지 않는다.

## 8. 검수 순서와 실행

1. 원화·디자인 메모를 직접 보고 공통 화풍 참조와 캐릭터 구조 가이드를 확인한다.
2. 실제로 읽은 참조 순서와 해시를 먼저 기록하고 생성한다. 입력 이미지를 보지 않은 채 수정하지 않는다.
3. 네 방향 원본을 펼쳐 의상·표정·손·장비·바닥·큰 가림을 확인한다.
4. 두개골·턱·발 좌표와 불확실성을 기록한다. 기울기와 모자·머리카락을 분리한다.
5. 같은 전신 배율과 바닥선으로 패킹한다. 64·96px 밝은/어두운 배경, 네 방향 전체, 문제가 있었던 캐릭터 나란히 비교, 5×5 배치를 실제로 본다.
6. 파일·참조 해시·알파·방향 추출·클리핑 검증과 `file://` PC·모바일 브라우저 검증을 실행한다. 파일 검사 통과가 시각 품질의 증명은 아니다.

비교 도구는 `review/index.html`을 브라우저에서 열면 된다. 서버·API 키·인터넷·Node 설치가 필요 없다. 64px는 전장 캔버스 폭360px에서 캐릭터 프레임63px로 그리는 현행 게임의 모바일 표시 크기에 가깝다. 5×5 미리보기는 현행 게임의90px 배치 간격,126px 프레임과 바닥 오프셋을 재현한 정지 그림이다. 전투·이펙트·상태 표시의 검증을 대신하지 않는다.

제작 스크립트를 다시 실행하려면 Node24와 `package.json`에 기록한 Sharp·Playwright가 필요하다. 로컬 의존성이 없으면 `DEFENSE_ART_PACKAGE_JSON`을 기존 의존성이 설치된 프로젝트의 package.json 절대 경로로 지정할 수 있다. 폴더의 초기 준비·수정 보조 스크립트는 제작 이력이며 일괄 재실행 대상이 아니다. 특히 `catalog.mjs`, `prepare-production.mjs`, `reconcile-*`, `select-*`, `polish-*`를 아카이브 위에 재실행하면 과거 입력 기록을 바꿀 수 있으므로 새 작업 폴더에서 사용한다.

일반 재빌드 진입점은 `npm run pack`, `npm run mobile`, `npm run review`, `npm run verify`다. 브라우저 검증은 `npm run verify:browser`이며 이 환경에서는 설치된 Playwright 브라우저 경로를 명시했다. 다른 PC에서는 해당 PC에 설치된 브라우저를 지정해야 한다. 생성 도구를 호출하는 부분은 이 저장 스크립트에 포함되지 않는다.

## 9. 한계와 다음 제작의 기준

이 방식은 실제3D 구조를 참고해 그린 네 방향 일러스트다. 같은 캐릭터 메시와 리그를 그대로 회전해 렌더한 결과는 아니다. 숨은 두개골의 정확한 실측, 모든 자수·머리 가닥의 완전한 일치, 방향 전환의 완전한 모션 연속성은 보장할 수 없다. 엄격한 회전 연속성을 더 높이려면 공통 리그에 실제 캐릭터를 모델링하거나 정밀한2D 리깅·수작업 턴어라운드를 함께 써야 한다.

정규화한 타원 면적이 같아지는 것은 배율 공식의 결과다. 그것만으로 실제 머리가 같다는 독립 증거가 되지 않는다. 좌표 추정과 실제 크기에서 보이는 인상을 계속 함께 검수해야 한다. 모든 캐릭터를 같은 얼굴·같은 표정으로 바꾸는 것도 통일성의 목표가 아니다.

현재 자세 기준이 반영된 새 공통 프롬프트는 `common-prompt-v2-natural-idle.txt`다. 실제 참조 경로·해시의 사전 기록은 `prepare-input-record.mjs`로 만들고 `ingest-generation.mjs`의 마지막 인자로 전달한다. 새 수집기는 기존 생성본 덮어쓰기와 참조가 바뀐 입력 기록을 거부한다.
