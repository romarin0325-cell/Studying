# Star Garden SD art

This is a repository-owned production workflow. Locate the repository root; all commands below run there. Do not reconstruct the procedure from the newest chat correction.

1. Read `defense/docs/art/sd-pipeline/RUNBOOK.md`, `defense/scripts/art/sd-pipeline/policy.mjs`, `defense/docs/SD_CAST_GUIDE.md`, and the applicable `AGENTS.md`. The first two are the execution entrypoint and cumulative contract; the guide identifies frozen style and9 actual body masters. `defense/docs/art/sd-pipeline/index.html` shows stages, masters, real executed prompts and the selected cast.
2. When resuming, run `npm run sd:defense -- status <run>` and `next <run>`. Keep all mandatory head, face, body, direction, original-design, style, outline, equipment, actual-size, portrait and packaging checks. A new requirement adds a check and a versioned policy; it does not replace earlier checks.
3. Inspect the actual original illustration/concept and current approved cast. Infer a body/height class, observable face/expression details and anatomical equipment ownership. Exclude hair, ears, hats, horns, ornaments and weapons from the skull. Use `sd:brief:defense` to prepare reference crops/brief after writing design/equipment notes; this does not approve A or call an image model. Original art is an explicit input, never an inferred machine-specific default.
4. Execute A–G in order with the runner. A records what was actually seen and input hashes. B uses the exact frozen job and actual built-in image output, native file and ordered reference hashes. Respect the user's generator/model restrictions. The scripts never secretly call a paid API or route to another model. If the required generator is unavailable, report that limit rather than fabricate provenance.
5. C measures the unwarped source's skull/pupils/chin/joints/soles in every view, with uncertainty. D uses one isotropic whole-character scale and per-view translations; no accessory auto-fit, face/limb stretching or per-direction scaling. Do not enlarge inferred skull bounds to hide a long body. E runs the independent checker and creates the fixed-scale review book. Set up the optional CPU checker once with `setup:defense:sd-pipeline -- --warm-models`; missing dependencies do not mean audit pass.
6. Inspect all current review captures: original/style, fixed face windows, body/directions,64/96px in light/dark beside peers, contour/material probes and portrait. Judge skull/visible face, perceived hair/hat mass, head-to-body/torso/legs and overall cast impression together. Detector boxes and normalized areas are not skull ground truth. Explain raw warnings rather than deleting them.
7. Prefer bounded edits on the new painting, using an explicit mask and reproducible protected composition. Pixel preservation does not prove natural hair/neck/garment joins. If selecting a whole painting instead, create a new run and redo every visual judgment. Changed landmarks/pixels/policy/code invalidate downstream receipts.
8. F requires every mandatory item and current evidence hashes. Do not mark unviewed screens as viewed. Caution/fail/unreviewed blocks G. An owner may subsequently choose a disclosed candidate for installation; record that selection separately and keep the original art caution. Do not relabel it as a17-check pass.
9. Install only authorized selections. Preserve previous masters and new uncompressed/native sources; update the actual atlas inventory, optical crops, static/UI optimization manifest and provenance. Rebuild the affected game's regular/Bright/lab artifacts once, check changed screens at390×844 and real left/right targets, and follow the repository's scoped PR verification rules. Do not treat a successful workflow-control test or desktop screenshot as automatic art approval or physical-device evidence.

The selected2026-11-08 installation and its remaining limits are in `defense/docs/art/selected-cast-20261108/README.md`. Historical production records are evidence, not reusable passes for different pixels. For the tools' flags, dependencies, current17 checks and task files use the RUNBOOK; avoid maintaining a second checklist here.
