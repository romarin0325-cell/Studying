# DREAMWEAVER · Synapse Edition — 디자인 시스템

## 1. 왜 세 번째 에디션인가

같은 게임을 세 개의 시각 언어로 비교하기 위한 빌드입니다.

| 에디션 | 태도 | 인상 |
| --- | --- | --- |
| `card/` (Astra) | 하늘색 파스텔, 둥근 파티 카드, 여백 중심 | 밝고 부드러운 판타지 |
| `card_claude/` (Argon) | 테마별 일러스트 성소, 장식 프레임, 유리 패널 | 일러스트 중심 상용 리마스터 |
| `card_deepseek/` (Synapse) | 어두운 계측실, 격자·브래킷·모노 라벨, 발광 액센트 | 기술적이고 밀도 높은 서브컬쳐 UI |

Synapse는 "밝은 판타지"를 어둡게 칠한 것이 아니라, **정보를 계기판처럼 읽히게** 만드는 것을 목표로 했습니다. 모든 화면에 동일한 HUD 문법(코너 브래킷, 마이크로 라벨, 0으로 채운 번호, 틱 눈금)을 적용해 장식이 아니라 구조로 느껴지게 합니다.

## 2. 토큰

```
--ds-void      #04060d   배경(최심)
--ds-surface   #0b1222   패널
--ds-surface-2 #101a30   카드·입력
--ds-text      #e8eeff   본문
--ds-dim       #98a8c9   보조 텍스트
--ds-faint     #63719a   메타 라벨
--ds-accent    #4d6bfe   주 액션 (DeepSeek blue)
--ds-accent-2  #5ce1ff   HUD 수치·포커스 (cyan)
--ds-line      #5a76ff2e 1px 경계
--gold         #ffcf6b   전설 등급·특성
```

테마(`astra`/`strawberry`/`dreamsky`)는 **액센트와 카드 뒷면만** 교체합니다. 크롬(헤더·내비·패널)은 항상 심해 네이비를 유지해 세 테마가 같은 제품처럼 보이도록 했습니다. 밝은 테마용 `card/src/themes.css`는 상속 목록에서 제외했습니다 — `!important`로 흰 패널을 강제하는 규칙이 딥시크 레이어를 뚫기 때문입니다.

## 3. 타이포그래피

- **워드마크**: 세리프(Georgia → Nanum Myeongjo). `DREAM`은 백색, `WEAVER`는 시안→바이올렛 그라디언트. 게임 로고와 계기판 UI의 대비를 만듭니다.
- **본문**: 번들 Noto Sans KR 서브셋(`SynapseSans`, 400–900). 오프라인에서도 동일한 웨이트를 보장합니다.
- **라벨**: 시스템 모노스페이스. `// HALL OF WEAVERS`, `WEAVER // 001`, `SYNC 98%`처럼 **영문 대문자 + 자간**으로 계기판 질감을 만듭니다. 영문 라벨은 장식이며, 모든 행동은 한글 텍스트로도 읽힙니다.

## 4. 레이아웃 규칙

- 기준은 **390×844 세로 모바일**. 모든 화면은 상단 헤더 + 스크롤 본문 + 하단 내비(전투/드래프트에서는 숨김) 구조를 유지합니다.
- `≤760px` 모바일: 하단 내비를 떠 있는 캡슐로, 컨테이너 하단 패딩을 `88px + safe-area`로 확보합니다.
- `761~900px`: 상속된 2단 로비를 유지하고 파티 카드를 히어로 높이로 키웁니다.
- `≥901px`: 타이틀이 **좌 카피 / 우 키 비주얼** 2단 그리드로 전환됩니다. `display:grid`는 반드시 `#screen-title.active`에만 걸어, 비활성 화면이 남아 보이는 사고를 막습니다.
- 파티 카드는 데스크톱에서 `clamp(220px,32vh,352px)` 아트 웰 + 3:5 비율을 유지하고, 블록 전체를 세로 중앙에 둬 상단 여백이 한쪽에 몰리지 않게 합니다.

## 5. 컴포넌트 언어

| 요소 | 규칙 |
| --- | --- |
| 패널 | 1px 저채도 경계 + `inset 0 1px #ffffff14` 하이라이트 + 깊은 그림자. 라운드는 12–18px |
| 코너 컷 | 파티 카드는 우하단 14px 컷(`clip-path`)으로 "장비 슬롯" 인상 |
| 등급 틴트 | `data-grade` / `data-element` / `data-role`을 읽어 프레임 그라디언트만 교체 |
| 스탯 그리드 | 컨트롤러가 쓴 `label: value / label: value` 문자열을 파싱해 2열 셀로 분해. 파싱 실패 시 원문 유지 |
| 특성 칩 | `#md-skills > p`를 금색 테두리 칩으로 승격 |
| 번호 목록 | 모드 선택은 `counter-reset`으로 `01`–`12` 부여, 색은 인라인 스타일을 정규화 |
| 피드백 | `pointerdown` 리플 1회, `prefers-reduced-motion`에서는 비활성 |
| 전환 | 화면 진입 시 8px 상승 + 페이드 1회(`ds-screen-in`) |

## 6. 키 비주얼

타이틀의 카드 부채는 **이미지가 아니라 CSS**입니다. 부채 3장 + 홀로그램 플레이트 + 틱 눈금 + 저해상도 엠블럼 워터마크로 구성해, 2.7 MiB 단일 파일에 추가 이미지 없이 해상도 독립적으로 렌더됩니다. 카드 뒷면 3종은 360×600(3:5) SVG로 새로 그려 도감·파티·전투 아트 웰과 정확히 같은 비율을 씁니다.

## 7. 모션과 접근성

- 진입 애니메이션은 화면당 1회, 리플은 700ms 후 제거.
- `prefers-reduced-motion: reduce`에서 부채 부유·리플·화면 진입을 모두 끕니다(Playwright 검증도 이 모드로 수행).
- 모달 포커스 트랩, ESC 처리, `aria-pressed`, `aria-haspopup` 등 상속 동작은 건드리지 않습니다.
- 대비: 본문 `#e8eeff` on `#0b1222`, 보조 `#98a8c9` — 어두운 배경에서 WCAG AA 이상.

## 8. 의도적으로 바꾸지 않은 것

- `card/game`의 데이터·밸런스·세이브 스키마·핸들러 ID·모달 콜백.
- 상속 CSS의 레이아웃 계약(`.screen`, `.container`, `.astra-nav`, 그리드 템플릿).
- 런타임 외부 자산(`루미.png`, `*.mp3`) 탐색 경로.

즉 이 폴더는 **표현 계층만 교체한 비교 빌드**이며, `card/`와 저장 파일을 그대로 주고받을 수 있습니다.

## 9. 한계

- 데스크톱은 "모바일 게임을 넓은 화면에서도 성립시키는" 수준이며, 데스크톱 전용 정보 구조(다열 대시보드 등)는 두지 않았습니다.
- 세로 700px 미만의 짧은 데스크톱 창에서는 타이틀이 스크롤됩니다.
- 테마 3종은 액센트·카드 뒷면만 달라지며, 화면별 일러스트 배경은 두지 않습니다(단일 파일 용량과 오프라인 우선 원칙).
