# Card RPG 리팩터링 보고서

작성 기준: 2026-08-02, 브랜치 `fix-artifact-mobile-layout`, 기준 커밋 `737bf646eff06b2b108c0eedc7874c83096edbf3`

## 결론

기존 코드는 완전한 스파게티 코드는 아니었습니다. `data.js`, `logic.js`, `battle_runtime.js`, `rpg_features.js`로 데이터·계산·전투·기능이 어느 정도 분리되어 있었기 때문입니다. 다만 약 5,800줄 규모의 `index.html`과 큰 `RPG` 객체에 상태·DOM·이미지·미션 렌더링·호환 진입점이 함께 있어, 초급자가 한 기능의 영향 범위를 예측하기에는 스파게티 코드에 가까운 구간이 있었습니다.

이번 정리 후에는 저장, 이미지, 미션 화면의 경계가 명시되고 모바일·저장·전투 회귀 검사가 자동화되었습니다. 현재 평가는 “레거시 대형 객체는 남아 있지만, 초급자가 문서와 역할 경계를 따라 안전하게 수정 가능한 중간 이상 수준”입니다. `RPG` 전체를 한 번에 재작성하지 않은 이유는 모바일 `file://` 로딩과 저장 호환성의 기능 위험이 구조상 이득보다 컸기 때문입니다.

활성 브랜치의 원격 커밋을 직접 조회해 로컬 HEAD와 동일함을 확인했으므로 별도 병합은 필요하지 않았습니다. Windows에서 대소문자만 다른 원격 ref 때문에 일반 fetch 경고가 있었지만, 작업 대상 브랜치의 원격 SHA는 정확히 일치했습니다.

## 추가한 클래스 3개

사용자가 허용한 “기존 구조에서 최대 3개 추가” 범위 안에서 정확히 세 개만 추가했습니다.

| 클래스 | 위치 | 책임 | 금지한 책임 |
|---|---|---|---|
| `ImageAssetManager` | `index.html` | 이미지 소스 결정, 사전 로드, 성공/실패 표시, 동적 이미지 생성 | 저장·전투 계산 |
| `MissionView` | `index.html` | 월간/주간/스페셜 미션 DOM 렌더링 | 미션 진행도·저장 변경 |
| `SaveDataMigrator` | `logic.js` | 런 저장 정규화와 직렬화 | DOM·직접 `localStorage` 접근 |

이미지 모델은 요구 조건대로 메인 코드 `index.html`에 남겼습니다. 새 스크립트 파일을 추가하지 않아 모바일 순차 로더의 의존 단계도 늘리지 않았습니다.

## 구조·공통화·명명 개선

- 모든 카드·적·루미 이미지 경로와 오류 처리를 `ImageAssetManager`로 통합했습니다.
- 월간/주간/스페셜 미션의 반복 DOM 생성을 `MissionView`로 통합했습니다.
- 날짜 문자열 생성은 `getCurrentDateKey` 한 경로를 재사용합니다.
- 저장 로드 시 흩어져 있던 기본값 보정을 `SaveDataMigrator.normalizeRunState`로 모았습니다.
- 저장 직전 UI 전용 상태 제거를 `serializeRunState`로 명명했습니다.
- `renderMonthlyMission`처럼 실제 범위보다 좁은 이름을 `renderMissionView`로 바꿨습니다.
- `RPGFeatureModules.install`은 동명 메소드가 있으면 조용히 덮어쓰지 않고 충돌 이름을 포함해 중단합니다.
- `fortune_cookie.js`를 앱 코드와 같은 4칸 들여쓰기·작은따옴표 규칙으로 정렬하고, 직접 `localStorage` 접근을 `Storage`로 통일했습니다.
- `Fix:`, `버그수정`, `User request` 같은 변경 이력형 주석을 현재 보장해야 하는 이유 중심의 주석으로 바꿨습니다.
- 초급자용 파일 배치, 이름, 저장, 이미지, 연산 규칙은 `CODING_GUIDE.md`에 고정했습니다.

## 저장 데이터 호환성

다음 기존 키는 한 글자도 바꾸지 않았습니다.

`cardRpgSave`, `cardRpgGlobal`, `cardRpgVocab`, `cardRpgCollocation`, `cardRpgCollocationDetails`, `cardRpgApiKey`, `cardRpgRecords`, `fortuneCookieLastUsedDate`, `fortuneCookieLastResult`

카드·아티팩트·모드·미션·버프 ID와 기존 저장 필드명도 유지했습니다. `SaveDataMigrator`는 다음 원칙을 적용합니다.

- 구버전에서 누락된 배열과 `draft`·`factoryDraft`·리저브 중첩 구조를 기본값으로 보정합니다.
- 지원하는 스키마 안의 알 수 없는 최상위·중첩 속성은 보존합니다. 단, 카드 선택 ID 목록은 현재 존재하는 ID만 남깁니다.
- 원본 로드 객체를 직접 변경하지 않습니다.
- 저장할 때만 `currentToeicSession`을 제외합니다.
- `saveSchemaVersion`을 추가해 이후 명시적 마이그레이션 위치를 마련했습니다. 현재 코드보다 높은 버전은 낮춰 쓰지 않고 원본을 유지한 채 로드를 차단합니다.
- 잘못된 런 저장은 현재 메모리 상태나 원본 저장을 덮어쓰지 않고 불러오기를 중단합니다. JSON 손상 시에는 원문 복구용 사본도 별도 키에 남깁니다.
- 글로벌 저장의 기존 백업·손상 복구·회귀 방지 경로는 그대로 유지합니다.

주의할 레거시 계약도 유지했습니다. `cardRpgRecords`는 `최대 스테이지: N` 한국어 문자열을 파싱하며, 학습 진도는 런 저장과 전용 키에 중복 저장된 뒤 전용 키가 우선합니다. 이 둘은 별도 버전 마이그레이션 없이 정리하면 세이브가 깨질 수 있습니다.

## 의도적으로 유지한 비활성·호환 코드

- `toeic_reserve_data.js`: 파일 자체가 미래 반영용이라고 명시한 보류 데이터입니다.
- `RPG`의 전투 전달 메소드: 내부 호출이 적더라도 기존 HTML/콘솔 진입점 호환 어댑터입니다.
- `behemoth_trait`와 `behemoth_liberated_trait` ID: 효과 처리는 공통화했지만 외부 데이터 검사 호환을 위해 두 ID를 별칭으로 받습니다.
- 적 스킬의 `rate`: 현재 적은 전용 AI 정책을 쓰므로 대부분 무시되지만 미래 fallback 계약일 수 있어 일괄 삭제하지 않았습니다.
- `joker_wild`: 직접 핸들러 참조보다 조커의 카드 ID 기반 규칙을 설명하는 표식 성격이 있어 유지했습니다.

## 합연산과 곱연산 감사

현재 규칙은 완전히 무작위로 섞인 것은 아니지만, 처리 단계가 달라지면 같은 `%`도 결과가 달라집니다.

| 단계 | 현재 방식 |
|---|---|
| 자기 시너지·배치 특성 | 각각 곱한 뒤 중간 정수화 |
| 같은 파티 보너스 범주 | 퍼센트포인트를 합한 뒤 한 번 곱하고 정수화 |
| peer 보너스·혼돈 축복 | 이전 결과에 다시 곱하고 정수화 |
| 전투 중 필드/특성/디버프 스탯 | 같은 스탯 계수에 가감한 뒤 기본 스탯에 곱함 |
| 치명·회피 확률 | 퍼센트포인트 합산 |
| 스킬 “배율 추가” | `ctx.mult += 값` |
| 스킬 “N배” | `ctx.mult *= 값` |
| 특성 대미지 보너스 | `(val - 1)`을 합산한 뒤 `skillMult * (1 + bonus)` |
| 방어 | `100 / (100 + 유효 방어)` |
| 가드 | 마지막 피해에 50% 또는 정확한 `가드` 스킬만 75% 감소 적용 |

초기 자기 30%, 파티 30%, 축복 30%는 단순 90%가 아니라 단계별 곱과 중간 정수화가 적용됩니다. 반대로 같은 파티 범주의 30% 두 개는 60%로 합한 뒤 한 번 곱합니다. 한 효과 배열에서 `+=`와 `*=`를 섞으면 배열 순서에 따라 결과가 달라질 수 있으므로 신규 데이터는 이를 피하고 골든 테스트를 추가해야 합니다.

관통은 대부분 원 방어/마방 기준 비율을 합산해 0에서 제한하지만, 꿈의형태 달/사신 효과는 계산된 유효 마방을 기준으로 합니다. 또한 일반공격 특성 디버프는 피해 전에, 스킬 데이터의 일반 `debuff` 효과는 피해 후에 붙어 같은 타격 반영 여부가 다릅니다. 베히모스 같은 별도 사용 전 특성 훅은 이 일반 규칙의 예외입니다. 이 차이는 밸런스 의도 확인 없이 바꾸지 않고 문서화했습니다.

레거시 이름 예외로 `syn_light_fire_atk`는 ID에 `atk`가 들어가지만, 기존 설명과 실제 효과는 마법공격력(`matk`) 증가입니다. 영속 식별자 호환을 위해 즉시 이름을 바꾸지 않고 코드 옆에 주석으로 계약을 남겼습니다.

## 남은 개선 후보

1. 스킬 표시명 대신 안정적인 `skill.id`를 도입하고 `id` 우선·`name` fallback으로 단계 이행합니다.
2. `val`이 확률·퍼센트·배율을 모두 뜻하는 레거시 스키마를 어댑터와 함께 명시 필드로 옮깁니다.
3. 적 전용 AI를 데이터 정책으로 옮긴 뒤 의미 없는 `rate`를 정리합니다.
4. 아티팩트 정의를 `logic.js`에서 별도 데이터 파일로 옮기는 작업은 로더·저장 회귀를 동반하므로 별도 변경으로 수행합니다.
5. 관통 기준과 상태 적용 시점은 밸런스 명세를 먼저 정한 뒤 통일합니다.
6. `RPG`의 나머지 DOM 영역도 한 번에 재작성하지 말고 이미지·미션처럼 한 화면씩 분리합니다.
