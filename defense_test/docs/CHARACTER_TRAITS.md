루미를 끌어 다른 동료에 합성하든, 다른 동료를 루미에 합성하든 같은 결과를 만든다. 둠은 재료 성급 × `(18 + 훈련 등급 ×4)` 골드를 환급한다. 머쉬룸킹의 합성 독, 연금술 유물의 합성 피해, 기본 별빛12 및 별모래 시계의 추가8도 양방향에 적용한다. 새 개체의 웨이브 나이와 수확 타이머는 초기화한다. 일반 자리 이동에는 이 효과를 발동하지 않는다.

## 정보와 작은 오라

도감에는 능력의 의미를 간단히 설명한다. 번개 연결의 모든 단계 숫자는 도감에 길게 나열하지 않고, 전투에서 동료를 누르면 현재 연결 수·위력·체인 비율·추가 대상 수를 표시한다. 메이드/화염은 변경 버튼 대신 “무작위 적/무작위 위치”를 표시한다. 둠의25G는 필살기 버튼·접근성 설명·도감에 함께 표시한다.

발밑 타원은 논리 반경28×9, 활성 불투명도0.48, 약한 웨이브 단계는0.17이다. 기존 기본 공격 그림을 폭56으로 눌러 깔고, 발 옆에 활성30/약한 상태24 크기의 고유 문양을 둔다. 아우로라는 기존 거울 아틀라스의30×38 문양을 사용한다. 소년·고래는3개의 작은 단계 점으로 현재 웨이브 단계를 구분한다. 번개·아우로라·지크·시간의지배자는 실제 보너스를 받는 개체에만 오라를 표시한다. 신규 발밑 호는 캐릭터 아래층, 작은 상태 배지는 발 옆에 그려 얼굴·성급·적HP와 겹치지 않게 한다. 지속 필살기 표시와 별개로 표시해 서로의 조건을 가리지 않는다. 연출 줄이기는 호흡 움직임을 멈추되 상태 정보는 남긴다.

첫 실제390px 화면의0.32 불투명도/24 문양은 정보 비가림은 통과했지만 번개·시간 수혜 문양이 바닥 테두리와 성급 별에 섞여 활성 상태의 즉시 판독 기준에 실패했다. 활성 대비와 문양만 위 값으로 올리고 약한 상태는 그대로 두어 차이를 만들었다. 과도한 광역 연출을 추가하는 방법은 사용하지 않았다.

대비 조정 후에도320px 시간 수혜자와 번개의 작은 문양이 바닥 장식에 섞여 즉시 판독 기준을 재차 통과하지 못했다. 최종적으로 발 옆 문양에 반경16의 짙은 남색 바탕과 얇은 고유색 테두리를 추가하고, 이 작은 상태 배지만 그림자·캐릭터 뒤가 아닌 앞에 그렸다. 발밑 호는 기존 아래층을 유지한다. 활성 배지는390px에서 약17CSSpx이며 얼굴·성급과 떨어져 있다. 성장 단계 점도 반경2→3으로 올렸다.

`925529e`의 실제320×568/390×844 화면 재검토에서 이 기준을 통과했다. 네 번개의 노란 배지, 두 활성 아우로라의 거울, 같은2성 시간의지배자 중 왼쪽 한 명에만 있는 보라 배지, 소년의 푸른 별과 지크의 붉은 배지가 선택 해제 상태에서 식별된다. 얼굴·성급·보스HP는 가리지 않는다. 이 장면의 아우로라는 두 명 모두 활성이라 비활성과의 시각 비교를 통과했다고 주장하지 않는다. 약화·중립·강화 계산은 전투 회귀에서 별도로 검증한다.

폭풍 즉사는 기존 바람 문양 하나가84→36으로 수축하는0.48초 국소 연출이다. 추가 화면 흔들림·화면 전체 색칠·큰 피해 숫자를 붙이지 않는다. 화염의현자의 선택 범위는 실제 무작위 좌표 영역의 네 모서리로 표시해, 기존 사거리 원이 목표 제한처럼 보이는 문제를 피한다.

## 이어하기와 실패 기준

기존 세이브에 기록되지 않았던 과거 등장 웨이브는 복원할 수 없다. `birthWave`가 없는 저장은 최초 복원 시 현재 웨이브를 등장 웨이브로 채우고 이후 저장한다. 전투 중 미래·음수·소수 웨이브는 거부한다. 예전 메이드/화염 목표 우선순위는 무작위 고정으로 정규화한다. 시간 수혜UID가 없는 예전 저장은 최고 성급의 가장 이른UID로 정하고, 이미 저장된 유효 수혜자는 유지한다.

웨이브 종료 보상의 합류, 대기 중 소환·합성은 **다음 전투 웨이브**를 등장 시점으로 기록한다. 아직 전투하지 않은 대기 시간 때문에 첫 웨이브의150% 소년·75% 고래 단계가 사라지지 않게 하기 위해서다. 다음 웨이브를 가리키는 저장은 보상·대기 단계에서만 허용하며, 전투 중 미래 웨이브 값과 두 웨이브 이후의 값은 거부한다.

난수 상태0은 xorshift를 고정시켜1% 즉사를100%로 만들 수 있어 거부한다. 공격·합성·저장·특성 설명이 같은 상태를 가리키지 않거나, 비용 부족 시 부분 지불하거나, 새 오라가 전투 정보를 가리는 경우를 실패로 보고 수정한다.

자동 검증은 `tests/combat.test.mjs`의 경계·저장·실제 피해 회귀, `tests/browser.mjs`의 실제 동료 선택/고정 목표/25G 지불/세로 경계, 루트 `npm run verify`를 사용한다. 화면 증거와 최종 결과는 [특성 화면 검토](review/traits/README.md)에 기록한다. 기존30종의 과도한 연출 감사는 [별도 효과 검토](EFFECT_REVIEW.md)에 기록한다.
