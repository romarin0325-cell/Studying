## 미디어 파이프라인과 실제 품질

원본 선택표는 `src/memorial-media.js` 한 곳에 있다. 30명에 선택된 원본 PNG를 EXIF 적용→sRGB→불투명할 때만 알파 제거→Lanczos3 720×1080으로 정규화한다. WebP는 이 원본 파이프라인에서 직접 생성한다. 기본 수동 도구는 이미 검증된 AVIF를 보존하고 `--check-avif`로 원본 재현을 확인할 수 있다. 새로운 원본/설정은 `--candidate`로 Git 제외 임시 폴더에 양 포맷과 실제 해시 catalog를 만든 뒤 검토한다. 일반 빌드는 원본 PNG나 이 도구를 요구하지 않는다.

WebP는 총2,232,062B(2.129MiB), 최대95,642B(93.40KiB), 내장 객체2.839MiB다. 기존2,031,414B보다200,648B(+9.88%) 크지만 원본 세부 보존이 개선되고 기존2.5MiB/3MiB 배포 예산을 통과한다. 권고2.1MiB/2.8MiB보다 약30/40KiB 큰 것을 이유로 나머지28장 화질을 더 낮추지 않았다. 개별96KiB 목표를 넘는 두 장만 낮췄고 100% 검수했다. 엄격한 새로운 용량 게이트를 정기 검증에 추가하지 않았다. 상세 품질·해시·재현 방법은 [미디어 기록](MEMORIAL_MEDIA.md)에 있다.

지크/신데렐라/혹한의마녀/은하고래/하모니어스/번개의현자를 원본 정규화·기존 이중 압축·직접 WebP로 100% 대조했다. 원본의 인물·의상·구도는 편집하지 않았다. 기존 AVIF30개는 바이트 그대로다. 30명의 본문242개 줄은 기존 해시 회귀 검사로 보존을 확인한다.

## 빌드와 범주 측정

기본판은 AVIF만, 호환판은 WebP만 내장한다. 두 단일 HTML에는 fallback 객체를 생성하지 않는다. 폴더판만 양 포맷을 독립 SHA-256 앞12자리 파일명으로 복사하고 현재 그림의 AVIF 실패에만 같은 그림의 WebP를 요청한다. 한 HTML 안에서 30장 문자열을 포함하는 것과 픽셀을 디코딩하는 것을 구별한다.

| 전투 아틀라스46개 | 11,376,702B | 15,170,946B |
| 초상화30개 | 685,560B | 915,551B |

폰트만으로 Base642,333,808B(2.226MiB)를 절감한다. 기존 기본 HTML 약22.30MiB가 약20.07MiB가 된다. 호환판 약21.33MiB, 폴더판 HTML 약18.50MiB에 CG 파일 합계3.310MiB다. 실제 실행 시 각 빌드는 CSS·JS·폰트·아틀라스·초상화·전신·유물·CG·HTML/라이선스/glue 바이트를 출력하고 `test-results/build-size-<mode>.json`을 작성한다. 텍스트 입력의 CRLF는 빌드에서 LF로 정규화하므로 Windows/Linux 수치가 일관된다. 배포 HTML과 Git HEAD의 소스 빌드 결과를 대조하는 기존 검증은 유지한다.

동일30장의 메모리얼 빌드 단계만 3회 교차 순서로 측정했다. AVIF→WebP 재압축 평균6,078.29ms, 사전 WebP 읽기+해시+메타데이터 평균31.63ms(-99.48%). 이는 전체 빌드 속도나 휴대폰 성능 수치가 아니다. 전투/수집 에셋의 기존 파생 과정은 유지된다. 호환 빌드를 파일 읽기 wrapper로 계측해 WebP30개, AVIF0개, PNG0개를 확인했다. runtime bundle에 source filename/hash catalog가 들어가지 않음도 확인했다.

## 화면 수명과 메모리 보조 검사

기존 구현을 유지했다. 새 이미지1개에 decode를 한 번 수행하고 세대/메뉴/hero가 유효할 때만 삽입한다. 닫을 때 세대를 증가시키고 src·DOM·앱 참조를 제거한다. load/error 핸들러나 Blob URL은 설치하지 않으므로 불필요한 정리 코드를 추가하지 않는다.

이번 Chromium CDP390×844 검사에서는 부팅·호감도9 잠금·앨범의 CG 할당0개, 전체30장 순회의 활성 CG 최대1개·닫은 뒤0개를 확인했다. 강제로 pending decode를 유지한 뒤 닫고 resolve해도 재등장하지 않았다. GC후 DOM587→589(+2), JS heap6,886,168→5,612,748B(-1,273,420B), event listener114→114, document1→1이었다. 콘솔/페이지 오류0, HTTP 요청0. warm-up 후 동일 홈 상태의 보조 측정이다. 압축 문자열은 HTML에 남고 브라우저/GPU 캐시의 즉시 해제를 보장하지 않는다.

## 검증 자료와 배포

기존 전체 계약·전투·성장·저장·미디어·월간·1인 편성 테스트90개가 통과했다. 기존 보고서의87개 외에 기존1인 편성3개까지 포함한 수이며 새 반복 테스트를 추가한 것이 아니다. 구문/생성 보고서/Chromium·WebKit/320×568·390×844·1280×900 및 HEAD 일치는 기존 `npm run verify`로 최종 검증한다. 결과 요약은 [최종 요약](review/memorial/summary.json), 재현·실측 한계는 [검증 방법](review/memorial/README.md)에 기록한다. 폰트는 [전체 글리프 검증](FONT_OPTIMIZATION.md), 전투 계측은 [런타임 측정](RUNTIME_MEASUREMENT.md)에 있다.

검증 PNG와 큰 좌표 JSON은 로컬 Git 제외 `test-results/`에 남긴다. 기존 PR workflow는 기존 검증이 만든 최상위 PNG/JSON만 7일 Actions artifact로 업로드한다. 새 테스트 실행을 추가하지 않는다. 원본·임시 후보·Python 라이브러리·복수 배포 HTML은 artifact에 포함하지 않는다. PR #580은 이미 merge돼 있으므로 이번 삭제는 현재 트리 최적화이며 Git 과거 역사 크기를 줄였다고 주장하지 않는다.

외부 원본 없이 다음 배포 명령을 실행한다.

```powershell
node defense_test/scripts/build.mjs
node defense_test/scripts/build.mjs --compat
node defense_test/scripts/build.mjs --web
```

폴더판은 HTML과 `memorial/`을 같이 이동한다. 서버에서 해시 이미지에는 `Cache-Control: public, max-age=31536000, immutable`, HTML에는 `no-cache`를 적용할 수 있다. 저장소에서 서버 설정을 배포한 것은 아니다.

실제 Galaxy/Android·iPhone 기기는 연결된 검증 장비로 확인되지 않았다. 이번 결과는 Windows Chromium147/WebKit26.4의 터치 viewport 에뮬레이션이다. Safari 실기기·백그라운드 복귀·온도·메모리 경고·강제 종료 여부를 인증하지 않는다.
