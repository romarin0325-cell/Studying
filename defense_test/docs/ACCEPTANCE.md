# 별빛 정원: 기능별 합격 기준과 검증 기록

조사·구현: 2026-10-04. 최종 로컬 검증/정리: 2026-10-05. 기준은 기능이 존재하는 것에 더해 사용 흐름, 실제 전투 효과, 저장 안전성과 화면 경계를 통과하는 것이다. 기준을 충족하지 못한 상태를 완료로 처리하지 않고 수정·재검증했다.

2026-10-05 후속 보완: 필요한 데이터·43개 이미지·폰트·라이선스를 로컬 소스 트리에 복사해 다른 게임에 대한 live dependency를 제거했다. 생성 보고서 비교 4개와 독립성 검사 3개를 추가해 게임 회귀는 31개, 선택기 fixture는 32개다. 기존 원본과의 항상 동일한 수치를 요구하는 제약도 제거했다. [독립화와 P1/P2 검증 보완](INDEPENDENCE_VERIFICATION.md)에 범위·경계·재생성 방법을 기록했다. 아래 초기 릴리스의 기능 결과와 실제 기기/장기 밸런스 검증 한계는 유지한다.

## 실제 검증 수치

- `npm run verify:plan`: 신규 `defense_test` 계약, 한 번의 해당 빌드, 해당 파일 기반 Chromium/WebKit 시나리오, 변경 JS 파싱, 검증 선택기 fixtures만 선택.
- `npm run verify`: 관련 단위/콘텐츠/아트/저장 24개와 selector 28개, 브라우저 흐름 모두 통과. 최종 로컬 실행 시간 106.13초.
- 브라우저별 최종 32개 화면/경계 캡처, 총 64개. 기본 크기는 320×568, 390×844, 1280×900이다. HTTP/HTTPS는 차단한 채 파일에서 플레이한다.
- 화면 경계는 문서/콘텐츠의 scrollWidth, 하단 메뉴 위치, 시트의 좌우·아래 경계, 다섯 스킬과 주요 전투 버튼의 화면 내 위치로 검사했다. 그림은 로딩 완료/유효 크기도 확인했다.
- 새 초기 편성의 메인 1단계는 난수 324508639/1234/98765에서 174.15/194.00/204.65초, 남은 체력 모두 20, 합성 16/15/16회였다. 희소 동료·유물·영구 성장 없이 실행했다.
- 일반 30만 회: C 210020/R 75128/SR 14195/UR 657. 시즌 30만 회: 일반 UR 327/해당 히든 291. 다른 히든 없음, 선언 확률의 6σ 계약 통과.
- 원본 43개 텍스처의 SHA-256과 30개의 지정 초상 영역/알파를 검증했다. 빌드 과정만 초상·유물을 추출한다.

실행 로그/전체 캡처는 개발 시 `test-results/`에 생성된다. 대표 캡처와 브라우저 경계 JSON은 아래 `review/`에 보관한다. 캡처의 일부 수집/파견/도전 상태는 장기 플레이 없이 해당 UI를 정확히 검증하기 위해 브라우저 **시작 전** 저장 프로필 fixture를 사용했다. 실행 중 게임 엔진을 변경하거나 가짜 DOM으로 화면을 만든 검증은 아니다.

## 실패로 처리하고 수정한 부분

- 초기 홈에서 캐릭터 발/대사/이름이 가까웠다. 파트너 크기와 문구·이름의 세로 간격을 조정했다.
- 작은 화면에서 전투 영역과 정원 상단 바가 주요 조작 공간을 소모했다. 전투 중 정원 상단 바를 접고 짧은 화면의 도움말만 접어 스킬·소환·훈련·자동을 표시했다.
- 편성 시트를 준비 화면에서 열고 확정한 뒤 준비로 돌아오지 않았다. 출발 준비 문맥을 보존해 복귀하게 했다.
- 편성 상단의 선택 칸도 바로 해제할 수 있게 하고, 빈칸은 후보 목록으로 이동하게 했다. 성장·편성 등 같은 시트의 연속 조작은 스크롤 위치를 유지한다.
- 재화/입장/획득을 분리 저장하면 실패 시 불일치가 날 수 있다. 한 프로필 거래로 묶고 저장 실패 시 취소한다.
- 재접속 드래프트나 전투의 형식 검사가 충분하지 않았다. 후보/선택/원정 메타·전투 복원 유효성을 검사한다.
- 원정을 저장한 채 정원에서 소환하면 프로필 난수가 바뀌어 재개 기준이 달라질 수 있었다. 입장 때 전투 난수를 고정했다.
- 이전 화면의 완료 토스트가 전투 스킬 위에 남았다. 전투 시작 시 정리하고 전투 토스트를 상단 영역으로 옮겼다.
- 거의 무적이 된 도전 후반 적의 이동을 오래 기다릴 수 있었다. 주간 35초/월간 30초 라운드 제한과 중도 정산을 넣었다.
- 최종 메인 웨이브에서 다음 웨이브가 없는 축복 선택을 요구했다. 마지막 보스 이후 바로 결과로 이동한다.

테스트 자체에서도 획득 함수를 목록 비교 중 여러 번 호출한 표본 검사, 시계를 이미 현재로 고정한 뒤 과거 파견을 생성한 fixture, 시트 등장 중간 프레임을 정착 경계로 판단한 캡처를 수정했다. 제품 결함과 검사 결함을 구별하고 실제 결정 함수/조작 흐름으로 재검증했다.

## 검증 한계와 다음 수치 조정

상용 게임을 목표로 한 완성된 사용 흐름과 시각적 일관성을 기준으로 구현했지만, 시장에서 가장 재미있다는 판정이나 장기 잔존율을 이 코드 검사로 인증하지 않는다. 45개 전체를 장기간 자연 성장으로 완주한 밸런스 인증, 모든 편성의 효율 비교, 실제 Android/iOS 메모리·터치·발열·배터리·지속 프레임 측정은 수행하지 않았다.

캐릭터/유물 기본 수치의 등급별 재조정은 요청대로 남겼다. 테스트는 원본 능력치와 자체 성장 공식으로 플레이 가능하다. 서버 없는 버전이므로 기기 미래 시간 조작·저장 편집 방지나 실시간 경쟁 순위는 제공하지 않는다. 향후 조정은 확률의 특정 대상 획득 기간, 파견 수익 증가, 월간 단일 화력/약화 조합, 다섯 역할의 편성 가치를 실제 플레이 피드백과 함께 살피면 된다.
