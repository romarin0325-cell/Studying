# 별빛 정원: UI·에셋 조사와 화면별 의사결정

조사/작성일: 2026-10-04. 대상: 모바일 세로 중심 오프라인 Defense 테스트. 기존 코드 기준: origin/main `d4c32cf`.

2026-10-05 독립화 보완: 아래 원본/기준 아트는 초기 제작의 출처를 뜻한다. 현재 필요한 이미지·폰트·라이선스는 `defense_test/assets`에 복사되어 있고, 그림 영역·캐릭터·보스 정의도 `src/data.js`에서 별도로 유지한다. 빌드·보고서·테스트가 기존 Defense나 Card 원본을 실시간으로 참조하지 않는다. 상세 경계와 검증은 [독립화 보고서](INDEPENDENCE_VERIFICATION.md)에 기록한다.

구현 전에 공식 자료를 검색하고 본문과 실제 공개 화면을 확인했다. 캐릭터 수집 UI, 세로 분재 UI, 성장 수학의 세 갈래로 조사한 뒤 화면 구조를 정했다. 아래에서 **관찰**은 공개 자료에 실제로 보인 내용, **설계 추론**은 이 게임에 맞춰 결정한 내용이다. 타사의 상용 UI를 그대로 재현하거나 타사 이미지·로고를 게임 에셋으로 가져오지 않았다.

## 조사한 게임과 관찰 범위

### Stella Sora / 스텔라소라

**관찰.** 공식 Gameplay Trailer의 0:16에서는 큰 캐릭터와 배경이 화면 중심을 차지하고, 플레이어·재화는 상단, 주요 메뉴는 오른쪽 하단에 모여 있다. 1:54의 캐릭터 메시지는 인물과 대화를 강조한다. 영상은 2024-12-18 공개된 WIP 자료다. 현재 출시 버전의 모든 메뉴가 같은 구조라고 단정하지 않는다. [공식 영상](https://www.youtube.com/watch?v=rs40AGfEv60&t=16s)

공식 스토어의 공개 이미지에서는 캐릭터 중심 일러스트, 다양한 빌드와 이야기의 강조를 확인했다. 이 이미지로 현재 도감·소환 메뉴의 정확한 좌표를 추정하지 않았다. [공식 Google Play](https://play.google.com/store/apps/details?hl=en_US&id=com.YoStarEN.StellaSora), [공식 App Store](https://apps.apple.com/us/app/stella-sora/id6738407069)

**설계 추론.** 홈의 중심을 수치 대시보드보다 파트너에게 배정한다. 전투 참여와 무관하게 보유 캐릭터를 파트너로 지정하며, 인사를 통해 매일 돌아올 이유와 작은 관계 기록을 만든다. WIP 영상의 오른쪽 하단 편중은 세로 320px에서 그대로 사용하지 않고 하단 5개 메뉴로 변환했다.

### Blue Archive / 블루아카이브

**관찰.** 공식 가이드의 로비 캐릭터 선택 화면은 초상 그리드, 선택 강조, 순서 표시, 최종 확정 버튼을 제공한다. 회상 로비 설명은 애정 캐릭터를 전면에 놓는 구조를 보여 준다. 가이드 텍스트의 최대 선택 수와 일부 이미지의 수가 달라 그 숫자를 이 게임의 편성 규칙 근거로 쓰지 않았다. [회상 로비 가이드](https://forum.nexon.com/bluearchive-en/board_view?board=3222&thread=2523168), [선택 화면 원본](https://dszw1qtcnsa5e.cloudfront.net/community/20250123/5ade0e20-fde0-40b1-876d-81daaba28d7c/image.png)

편성 안내에서는 팀·선택 영역을 분리하고, 학생 상세는 큰 인물과 레벨·능력·장비 정보를 묶는다. 모집 안내는 로비에서 모집으로 이동, 1회/10회 선택, 결과와 중복 재료의 흐름을 설명한다. 실제 상세 화면과 편성 이미지를 확인했으며, 관찰하지 못한 모집 화면의 세부 픽셀 배치를 근거처럼 쓰지 않았다. [편성 가이드](https://forum.nexon.com/bluearchive-en/board_view?board=3222&thread=2523154), [학생 상세 가이드](https://forum.nexon.com/bluearchive-en/board_view?board=3222&thread=2523127), [모집 가이드](https://forum.nexon.com/bluearchive-en/board_view?board=3222&thread=2720669)

**설계 추론.** 도감 카드 → 인물 상세 → 성장/강화/파트너의 짧은 경로를 만든다. 편성은 독립 시트로 묶고 5/5 상태를 보여 준 뒤 확정한다. 메뉴별 별도 전면 페이지를 늘리는 대신 하단 시트에서 일을 끝내고 원래 준비 화면으로 돌아오게 한다.

### Mandrake Boys / 재배소년 — 세로 분재 사례 1

**관찰.** 한국판 공식 스토어는 식물을 심고 기다렸다가 회수하는 짧은 반복과 캐릭터·일러스트 수집을 소개한다. 글로벌 공개 스크린샷의 세로 EXPEDITION 화면에는 상단 재화, 중앙 여행 장면, 남은 시간, 취소/즉시 완료 조작과 하단 고정 메뉴가 보인다. 획득 화면에서는 캐릭터를 크게 보여 준다. 이 획득 장면을 실제 홈 파트너 화면이라고 오인하지 않았다. [한국 공식 스토어](https://play.google.com/store/apps/details?id=com.owlogue.mandrakeboys.kor&hl=ko), [글로벌 공식 스토어](https://play.google.com/store/apps/details?hl=en_US&id=com.slowpuppy.boy)

**설계 추론.** 시간이 흐르는 파견은 명확한 카운터와 확정 보상을 함께 표시한다. 진행 중/귀환 완료를 같은 카드에서 전환한다. 하단의 6개 메뉴를 그대로 쓰면 320px의 버튼 폭이 좁아지므로 이 게임은 5개로 줄였다. 유료 즉시 완료는 도입하지 않았다.

### Cats & Soup / 고양이와 스프 — 세로 분재 사례 2

**관찰.** 공식 세로 스크린샷에서 재화는 상단, 숲과 고양이·시설은 중앙, 생산/수익 조작은 하단과 주변부에 있다. 공식 사이트는 개별 고양이의 이름·생일·취향을 부각한다. 공개 이미지에서 직접 보지 못한 오프라인 보상 팝업은 배치 근거로 쓰지 않았다. [공식 스토어](https://play.google.com/store/apps/details?gl=GB&hl=en-GB&id=com.hidea.cat), [공식 사이트](https://www.catsnsoup.com/)

**설계 추론.** 밤하늘·달빛 정원의 다크 톤 UI 위에 골드·티얼 포인트와 등급별(C/R/SR/UR) 프레임을 배치하여 정원과 전장의 감성을 통일한다. 손이 가는 파트너 인사, 다음 출격, 방치 보상 수령을 시각적 위계에 따라 구분한다. 방치 보상은 홈 하단 패널에서 수령한다.

### Neko Atsume 2 / 네코아츠메2 — 세로 분재 사례 3

**관찰.** 공식 스토어의 세로 화면은 중앙 정원·소품·고양이, 좌상단 메뉴, 하단 재화와 선물 보상을 보여 준다. 공식 FAQ는 고양이 정보와 앨범 접근, 음식·소품 취향을 설명한다. 실제 앨범 내부의 모든 UI는 관찰하지 못했다. [공식 스토어](https://play.google.com/store/apps/details?hl=ja&id=jp.co.hit_point.nekoatsume2), [공식 FAQ](https://www.nekoatsume.com/sp2/index.html)

**설계 추론.** 아직 얻지 않은 캐릭터도 도감에 실루엣으로 남겨 미래의 만남을 보이게 한다. 소유 수, 등급, 레벨, 중복 강화 가능 여부를 한 카드에서 읽는다. 이 게임의 CP는 고양이 게임의 수치로부터 가져온 값이 아니다.

## 전체 플레이 경험

정원 방문 → 파트너 인사/별가루 수령 → 동료 메뉴에서 성장 또는 편성 → 짧은 스테이지 전투 → 첫 클리어 보상으로 소환 → 새로운 동료 또는 중복 강화 → 파견에 여분 동료 투자 → 다음 방문에서 귀환 보상. 주간은 전체 수집 풀의 성장을, 월간은 단일 대상 조합의 투자를 확인하는 별도 목표다.

매일 할 일을 전투·소환·파견 수령 세 가지로 한 시트에 모았다. 모든 일과 모든 보상을 한 번에 완료해야 진행할 수 있는 구조는 두지 않았다. 최초부터 정확히 5명이 있어 소환 결과를 기다리지 않고 전투를 시작한다.

## 에셋 방향과 실제 제작 범위

캐릭터 몸·머리 비율, 의상, 색, 그림체, 방향 셀, 발 기준은 기존 Defense를 유지했다. 원본 1024×1024 방향 아틀라스 31개(30 동료와 변신 1개 포함), 보스·전장·유물 등 합계 43개 텍스처를 그대로 내장한다. 원본을 새 생성 모델로 다시 그리지 않았다.

도감 초상은 각 캐릭터의 기존 `art.portrait` 영역에서 240×240으로 빌드 시 추출하고, 파트너/상세/드래프트는 정면 512×512 셀을 사용한다. 머리를 크게 보여 주는 도감과 몸 전체를 보는 홈의 역할을 분리한 추론이다. 캐릭터별 몸통만 임의 확대하거나 픽셀 처리 코드를 런타임에 넣지 않았다. [원본과 추출 개수·SHA-256](ASSET_PROVENANCE.json)

유물 24개는 기존 5×4/2×2 시트에서 원래 칸을 추출했다. 등급은 C 10/R 6/SR 5/UR 3으로 분류했으며 기존 고유 효과를 재조정하지 않았다.

새로 만든 것은 UI의 SVG 메뉴/잠금/시계/장식, CSS 프레임·배너·선택 상태·호흡·획득 연출이다. C는 민트, R은 파랑, SR은 보라+별, UR은 금빛 이중 프레임+왕관으로 표현한다. 모든 카드에 C/R/SR/UR 문자를 넣어 색만으로 판단하지 않게 했다. 히든도 UR 프레임이며 수호자 여부는 별도 문구로 표시한다.

배경은 원본 전장과 일관된 청록/밤색, UI는 눈을 쉬게 하는 크림·민트, 희소성은 보라·금색을 사용한다. 제목에 기존 저장소의 Jua 폰트를 내장하고 SIL OFL 문구도 완성 HTML에 포함한다. 본문은 기기 기본 글꼴로 가독성을 확보한다.

## 실제 화면 검토와 재작업

390×844 홈에서는 파트너 발과 인사 문구/이름 사이 공간을 조정했다. 320×568은 파트너 장면을 짧게 하여 최초 화면에서 다섯 편성과 출발 버튼까지 보인다. 전투 화면은 정원 상단 바를 접고 5개 스킬·소환/훈련/자동 조작이 화면 안에 들어오도록 조정했다. 전투에 남은 이전 화면의 토스트가 스킬을 덮지 않도록 시작 시 정리하고 전투 알림 위치를 위로 옮겼다.

Chromium과 WebKit에서 각각 32개 상태를 캡처하고 320×568, 390×844, 1280×900의 실제 DOM 폭/경계를 검사했다. 모달은 하단 시트, 넓은 화면에서는 가운데 시트가 된다. 시트의 본문만 스크롤하며 확정 조작은 하단에 남는다. 등장 애니메이션 중간 프레임을 레이아웃 실패로 오인하지 않도록 최종 정착 프레임에서 경계를 검증했다. [합격 기준과 증거](ACCEPTANCE.md)

공개 스크린샷/영상 조사와 브라우저 에뮬레이션이다. 타사 최신 빌드의 모든 내부 화면, 실제 휴대폰의 엄지 도달 범위, 물리 기기의 프레임/메모리/발열, 장기간의 재미·애착·잔존율은 직접 측정하지 않았다.
