# 별빛 정원: 상태 효과·인연 이야기·1인 편성 검증 기록

PR #580 merge 이후 미디어 파이프라인과 전체 글리프 WOFF2를 개선했다. 현재 배포 수치·채택/보류 근거·일회성 계측은 [메모리얼·배포 효율 개선](MEDIA_EFFICIENCY.md)에 있다. 아래 최초 버전의 전투/화면 검증은 역사 기록이며 현재 이미지·배포 절에는 후속 변경을 반영했다.

작성일: 2026-10-05. 대상은 독립 테스트 게임 `defense_test/`다. 기존 디펜스와 다른 게임의 실행 코드는 변경하지 않았다. 이 보고서는 제공된 후속 요청의 수정, 화면별 판단, 실패 후 재작업, 실제 검증 범위를 기록한다. 최초 수집·성장 설계는 [UI·에셋 조사](UI_ASSET_RESEARCH.md), [성장식과 수치 근거](GROWTH_BALANCE.md), [독립성 검증](INDEPENDENCE_VERIFICATION.md)에 남아 있다.

## 이번 버전에서 달라진 경험

홈의 파트너 호감도 버튼과 동료 상세의 인연 카드에서 기억을 연다. 기존 호감도10이 해금 조건이며, 추가 호감도 획득 수단을 만들지 않는다. 잠긴 화면은 기존 SD 그림과 해금 조건을 보여 준다. 기억 목록도 기존 초상화만 사용한다. 해금된 기억에서는 제공 일러스트 한 장과 원문을 읽고, 이전·다음·전체 이야기·그림만 보기를 조작한다. 닫았다 다시 열면 읽던 문단으로 돌아온다. 이야기 번호는 노출하지 않고 읽은 비율만 표시한다.

현재30명에 각각 한 이야기를 대응했다. 원문의242개 본문 줄, 제목, 대사와 문장부호를 보존했다. 메이드·아우로라의 제공 이름을 현재 캐릭터 ID에 연결했고, 현재 명단에 없는 에인션트소울은 추가하지 않았다. 번개의현자의16A와 신데렐라의24B를 선택한 원본 장면의 근거와30명별 파일 대조는 [미디어 기록](MEMORIAL_MEDIA.md)에 있다. 본문과 이미지의 입력·출력 해시로 잘못된 대조를 검출한다.

전투는 독·노출·화상·기절·빙결·성광의 출처와 만료 시각을 보관한다. 약한 후속 공격이 강한 효과의 위력이나 시간을 덮지 않으며, 프레임 중간에 효과가 끝나면 해당 구간만 실제 피해와 정지에 적용한다. 모든 장판은 같은 시전자·좌표여도 독립적으로 중첩한다. 보상 저장에 실패한 전투를 재개하면 미처 선택하지 않은 보상창이 다시 열린다. 자동 보상 직전에 수동으로 전환해도 선택지를 직접 고를 수 있다.

에인션트드래곤의 일반 공격은 붉은 화염 십자, 지크는 투명한 내부를 가진 화염 부채꼴이다. 전투 판정과 시각 효과의 레이어를 구별하고, 얼굴·성급·적 체력이 효과보다 위에 보이게 유지한다. 별도의1인 편성 HTML은 편성·소환·주간 드래프트·파견·저장·월간 기록까지 같은1종 규칙을 사용한다.

## 참조와 자체 설계의 구별

블루아카이브의 공식 관계·MomoTalk·Recollection Lobby 가이드, 스텔라소라의 공식 설명, Love and Deepspace의 관계·기억 구조, 재배소년의 수집·이야기를 조사했다. 지크 공격은 전용 원호, 회전 초승달, 여러 얇은 리본, 약한 판정 윤곽+적중 표시의 네 대안을 비교했다. 선택은 전용 원호와 약한 실제 판정 윤곽의 조합이다. 기능별 참조 URL, 확인한 사실, 추론, 채택·기각 이유는 [메모리얼·부채꼴 조사](MEMORIAL_AND_CONE_RESEARCH.md)에 있다.

연결된 Computer Use 브라우저가 없어 해당 설치 게임을 직접 플레이하거나 원격 스크린샷 픽셀을 직접 관찰했다고 주장하지 않는다. 공식 본문과 이미지 검색의 화면 설명을 참고했고, 구체적인 좌표·색·스크롤 구조는 자체 세로 화면 검증에서 결정했다. 제공 캐릭터 일러스트는 의미적 편집이나 새 생성 없이 축소·인코딩했다. 두 화염 에셋만 기존 효과를 실제 열어 참조하여 ImageGen으로 제작했다. 정확한 프롬프트·출력 설정·일반 공격에만 쓰는 이유는 [화염 에셋 기록](FIRE_ASSET_GENERATION.md)에 있다.

## 공식과 상태 효과

완전한 적용·소유자·마이그레이션·측정 방법은 [상태 효과 규칙](STATUS_RULES.md)에 기록했다. 이번 작업에서 등급별 기본 능력치 전반을 다시 조정하지 않았다.

- 독의 실제 적용 상한은40이다. 출처별 원래 스택·위력·종료 시각을 남기고, 위력 상위40스택만 활성화한다. 약한 독을 추가해도 기존 DPS나 필살기12초를 낮추지 않는다. `독 DPS = Σ(활성 스택 × 시전자 공격력 × 3/11)`이며 이미 계산한 성장 배율을 다시 곱하지 않는다.
- 팬텀 필살기는 전체 생존 적에 성급×4 독을12초 부여한다. 머쉬룸킹 필살기도 같은 공통 독 계산을 사용한다.
- 노출·화상은 살아 있는 가장 강한 효과를 적용한다. 약한 효과의 개별 시각은 유지하지만 이미 끝난 강한 화상을 되살리지 않는다. 화상 피해는 실제 소유자에게 귀속한다.
- 기절과 빙결은 독립적으로 보관하고 실제 정지는 두 종료 시각 중 가장 늦은 시각까지다. 시간을 합하지 않으며 짧은 제어가 긴 제어를 줄이지 않는다.
- 성광은 각6초·최대3중첩·중첩당 받는 피해+2%다. `범용 받는 피해 증가 = min(.80, 노출 + 성광×.02)`. 공격자의 조건부 주는 피해는 별도 한 번만 적용한다.
- 장판은75개까지 독립적으로 존재하고76번째는 가장 오래된 하나를 제거한다. 새 독립 중첩의 고정 seed DPS를16회 측정해 팬텀·시간의지배자의 과도한 증가를 확인하고, 화염의현자를 제외한 장판 영웅의 기본 대기시간을1.15배로 보정했다. 최종 비교에서도 일부 상승을 남긴 임시 설계이며 최종 등급 밸런스 완료를 뜻하지 않는다.
- 밤토끼 필살기는 기본9표적, 전장의 다른 눈토끼·은토끼 종류마다+2다. 같은 토끼 여러 기는 중복하지 않아9/11/13표적이다.

개별100KiB·전체2.5MiB·내장 객체3MiB 기준을 모두 통과한다. 메모리얼은 `__MEMORIAL_MEDIA__`에 한 번만 들어가며 ASSET_PATHS에 없다. 기존 전투 텍스처는 지크 일반 공격 한 장 추가로46개다. 원본 PNG는 저장소 밖에 보존하고, 초상화·아틀라스·LocalStorage에 CG를 중복 저장하지 않는다. RGBA 픽셀만 계산하면 한 장은약2.97MiB이며 브라우저·GPU 부가 메모리를 포함한 실기기 메모리를 측정한 값은 아니다.

현재 Windows Playwright WebKit은8×8 AVIF의420/444·8/10/12bit 조합과 원본 AVIF 모두 디코딩하지 못했다. 같은 입력의 Chromium은 성공한다. [Playwright 문서](https://playwright.dev/docs/browsers#webkit)도 플랫폼별 미디어 코덱 차이를 설명한다. 기본판에서 실패 안내와 계속 읽기·닫기를 확인하고, 첨부가 허용한 별도 WebP 전용 호환판을 제공한다. 한 HTML에 두 형식을 중복 삽입하지 않는다.

호환판은 원본 PNG에서 직접 생성한720×1080 WebP만 읽는다. AVIF에서 다시 변환하지 않는다. 28장 q82, 은하고래 q80, 혹한의마녀 q78이며 effort6·smartSubsample를 유지한다. 바이너리2,232,062B·2.129MiB, 최대95,642B·93.40KiB, 내장 객체약2.839MiB다. 실제 품질 향상과 기존 예산 통과를 확인했으며 자세한 원본/이중 손실/직접 인코딩 비교는 [미디어 기록](MEMORIAL_MEDIA.md)에 있다.

## 남은 검증 범위

실제 Android·iPhone의 터치·디코딩 지연·메모리·발열·배터리는 검증하지 않았다. Playwright WebKit 통과는 실제 Safari 기기 인증이 아니다. 외부 참조 게임의 직접 설치 플레이와 원격 픽셀 관찰도 확인하지 못했다. 현재 구현의 세로 화면과 제공 원본 대조는 실제 로컬 브라우저·캡처에서 확인했다. 모든 캐릭터 조합의 후반 밸런스는 사용자가 추후 조정할 범위다.
