# Pixel route pilot

Input: cast-v2 sheets, top-left and bottom-right quadrants; alpha was already present. Transparent-bound cropping precedes R1/R2. Files in `sprites/` are native resolution. `pilot-sheet.png` places both backgrounds, 1× and nearest-neighbour 4× at a common bottom baseline. R0 is the actual atlas cell, so its subject occupies only part of 64×64. R1 and R2 are height-normalized sprites. R2's output dimensions include its one-pixel outline. The comparison therefore also shows a scale difference, not just processing quality.

Timings are wall time measured by `performance.now()` around each route's processing and PNG write, in one warm process on these four inputs; individual values are in `timings.json`. Extrapolations are simple multiplication, exclude manual inspection, correction, input availability, I/O preparation, and variability, and are not a production estimate. No per-character editing was performed. The 49 cast sheets do not establish source coverage for 161 definitions. Generated sprites, animation, consistency across directions, actual in-game appearance, and quality across the full cast remain untested.

Run from repository root: `node card_pixel/plan/pixel-pilot/pilot.mjs`. It reads the existing atlas and cast sheets and writes only this pilot directory. Re-running replaces pilot outputs. No game build or game files were changed.
