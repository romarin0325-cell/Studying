Survivor 후속 리뉴얼: 조사한 48가지 방법과 적용 결정
실행 기준: main 614e099, PR #568 병합 확인; 이어서 병합된 PR #569의 성장/적 곡선을 보존.
조사 날짜: 2026-10-02 UTC. source ID와 실제 HTTP 결과/본문 해시는 sources.json에 기록.
'조사'는 자료를 읽은 상태이며 해당 소프트웨어/모델을 실행했다는 뜻이 아니다.
'기존 유지'는 앞선 구현에 이미 있던 방법을 이번 패치에서도 유지/검증한 것. 새 구현으로 주장하지 않는다.
수동 두개골/골반 기준은 가려진 신체의 추정값이다. 2~3% 같은 업계 합격선이나 자동 포즈 검출의 SD 정확도를 주장하지 않는다.

01. 공유 승인 원화로 인물 정체성 고정 — 적용. Defense 활성 원본과 Shooter/Card의 이름·성별·의상·기술 대응. survivor/docs/ART.md.
02. 화풍 참조와 인물 참조 분리 — 생성 시도. 루미를 스타일 참조, 각 기존 시트를 정체성 참조로 제공. 결과는 자동 승인하지 않음.
03. 고정 마네킹의 단신/성인 규격 분리 — 제작/시도. 머리 144, 턱 아래 140/212, 골반 46%, 바닥 474. mannequin-authoring.txt, VNCCS README.
04. 실루엣 참조 — 조사/부분 적용. 귀·무기 윤곽은 정체성/잘림 검수에 사용, 머리 배율의 경계로 사용하지 않음. Spine mesh/skins.
05. 깊이/포즈 제어 참조 — 조사. HF ControlNet/IP-Adapter, VNCCS. 실제 ControlNet/OpenPose/MediaPipe를 설치·실행하지 않음. SD 두개골 검출 보증으로 해석하지 않음.
06. 직교 카메라로 3D 마네킹 렌더 — 조사. Blender camera. 현재 2D 원화에는 직접 만든 평면 마네킹이 간결해 3D 제작을 선택하지 않음.
07. 공통 리그/몸 템플릿 — 적용. 머리/몸통/다리의 세 구역 변환을 BODY_PROFILE에 통합. Spine weights의 구조/그림 분리 개념을 참고. Spine 런타임 사용 아님.
08. 본 웨이트와 mesh 변형 — 조사. Spine weights/meshes. 머리카락/의상 레이어가 분리되지 않은 그림은 잘못된 가중치로 얼굴/손이 늘어날 수 있어 미채택.
09. linked mesh와 스킨 복제 — 조사. Spine meshes/skins. 새 캐릭터 제작의 장기 대안. 현재 전체 원화에 공통 UV가 없어 미채택.
10. 무기 손잡이가 있는 캐릭터는 별도 좌우 그림 — 적용. 루나 오른손 단검, 지크 오른손 검, 자스민 왼손 지팡이 보존. Godot weapon pivot/smooth 실제 토론.
11. 비무장/대칭 캐릭터 좌우 같은 사이클 반전 — 적용. 6명. 오른쪽을 별도 생성 원화로 표시하지 않음. Godot Sprite2D/JA sprite animation.
12. 반전 기준점은 발/몸 중심 — 적용. 208 셀의 래스터 반전축과 x=104 발축 차이를 1px 이동으로 보정. 실제 WebP 알파 반전 계약 검사.
13. 그림 반전과 물리/입력 좌표 분리 — 기존 유지. Godot scale-body 토론의 전체 플레이어 scale 반전으로 velocity가 바뀐 실패 사례 확인.
14. 방향별 skullTop/chin/bodyCenter 계측 — 적용. 앞 모습 값을 모든 방향에 쓰는 이전 방법 폐기. 가려진 두개골은 수동 추정.
15. 머리 너비/깊이와 얼굴 크기를 같이 검수 — 적용한 육안 검수. 전체 알파 너비를 머리 너비로 오인하지 않음. 숫자상 같은 높이가 같은 얼굴을 보증하지 않음.
16. 몸통/다리 길이를 독립적으로 변경 — 적용. chin/pelvis/foot 세 기준. 균등 전체 스케일만으로 내부 비율을 바꾸려는 방법 폐기.
17. 네 보행 위상의 머리/몸 배율 고정 — 적용. 발 접촉의 높이만 이동 보정; 턱/두개골 좌표를 발 픽셀 변화만큼 옮기는 이전 방법 폐기.
18. alpha bbox는 잘림 검사에만 사용 — 적용. 출력 셀 바깥 실픽셀은 실패. 귀·왕관·망토·무기의 bbox로 신체 배율/중심 결정 안 함.
19. 검토한 부츠/맨발 밴드에서 접지 픽셀 확인 — 적용. 망토와 지팡이 끝을 배제. 실제 발 접촉은 매 프레임 검토하고 숨은 발은 불확실성 명시.
20. 방향별 위상 순서와 passing 포즈 — 적용/기존 유지. 걷기 4위상, 멈추면 위상1. 반전 사이클의 위상은 원본과 동일.
21. 잘못된 손/방향 프레임 대체 — 기존 유지. 루미/밤토끼 잘못 향한 위상, 루나 단검 손이 바뀐 위상을 기존 명시된 passing 포즈로 교체.
22. onion skin으로 인접 프레임 비교 — 적용. authoring review-art HTML에서 이전 위상 반투명 겹침과 재생 제공. Aseprite onion-skin.
23. 64/96 및 실제 표시 크기 검수 — 적용. 공통 크기/바닥선, 어두운/밝은/자홍색 바닥. 크기별 실제 브라우저 검토 이미지 별도 기록.
24. 투명 셀 여백과 bleed 방지 — 적용/기존 유지. 캐릭터 가장자리 3px 안전 검사, 아이콘/보스 여백 20px. TexturePacker padding/extrude.
25. 가장자리 extrude — 조사. TexturePacker. 독립 투명 셀 drawImage에는 안전 여백이 충분해 원화 색을 확장하는 추가 extrude 미채택.
26. 흰 재료를 알파로 오인하지 않기 — 기존 유지. native alpha와 연결 성분; 밝기/흰색 key 제거 안 함. 방패/옷/머리의 불투명 흰색 계약.
27. 원본/후보/처리 결과 해시 — 적용. body-profile, prepared-manifest, candidate-hashes. 변경된 입력은 빌드가 거부.
28. 정체성+마네킹+스타일 생성 — 실제 세 후보 시도 후 거부. 자스민/은토끼/시간의지배자 모두 요청한 체형 변화가 충분하지 않음. trials.txt와 원본 PNG 보존.
29. 단일 포즈부터 생성해 시트로 확장 — 조사. Krita pose-to-pose/animation, VNCCS. 현재 후보 전체의 구조 변경 효과가 낮아 기존 그림의 검토 가능한 기하 보정 선택.
30. 국소 얼굴/목 연결 보정 — 적용. 시간의지배자 측면 턱의 잘못된 분리 좌표와 루트 자동 추정을 고침. 눈/얼굴 자체를 재생성하지 않음.
31. 프레임별 수동 몸 루트 보정 — 적용. 밤토끼 불균등 열(352/287/288/327)의 각 위상 원점 별도 명시. '셀 중심' 또는 alpha run은 잘못된 중심이 됨.
32. 로비와 전투의 같은 인물 포즈 — 적용. 로비 전신은 같은 보행 passing 포즈, 384px 별도 캐시. 저해상도 208px 시트를 확대하는 시도는 흐림 때문에 폐기.
33. 최근 보행 두 장만 디코딩 — 기존 유지/검증. 선택한 캐릭터의 비동기 그림 완료 후 다시 표시. Pixi performance/textures 참고.
34. WebP 캐시/해상도 예산 — 적용/검증. 44텍스처 전체 논리 RGBA 86.90MiB < 기존 88MiB 예산. 전부 동시 상주한다는 주장 아님.
35. 이미지 처리 오프라인화 — 기존 유지/확장. 원본은 제작 단계에서만 정리. 실제 HTML은 이미지 디코딩/그리기만 수행. MDN optimizing canvas.
36. 이동 거리 위상 + 60Hz 고정 시뮬레이션 + 화면 보간 — 기존 유지. render FPS에 걸음/게임 속도를 종속시키지 않음. Phaser animation, Godot AnimatedSprite.
37. 바닥/문양/그림자/피해 글자 캐시 — 기존 유지. 매 프레임 필터/텍스트 raster 작업 감소. MDN/Pixi performance.
38. 화면 밖 그림 제외, spatial hash — 기존 유지. 그림 품질 향상을 모든 적의 충돌 반복으로 지불하지 않음. learningPixi/MDN 개념 참고.
39. FX 풀/엔티티/이벤트 예산 — 기존 유지/검증. 새 보스 위험도 같은 한도 안에서 처리. 경고를 넣기 전에 비활성 탄을 우선 정리.
40. DPR 제한/자동 품질/절약 모드 — 기존 유지/검증. 실제 휴대전화 FPS 인증이라고 하지 않음. cloud 렌더 작업 시간을 별도 계측.
41. 아군 효과 위의 적 예고 — 적용/기존 유지. 절약 모드에서도 고리/선의 실제 안전 영역을 숨기지 않음.
42. 보스 컨셉별 실루엣/발동 포즈 — 제작/적용. 장미사슴, 시계 종, 밤고래를 기존 남색/아이보리/금속 판타지 재료에 맞춰 제작. 새 보스 각 2포즈를 4개의 독립 포즈라고 하지 않음.
43. 예고와 판정의 같은 기하 — 적용. 선분 최단거리/고리 내부 안전 공간/지속 장판; 이동과 회피로 읽고 피할 수 있음. Halls/Soulstone/10 Minutes 자료 참고.
44. 무한 모드의 실질적 끝 — 적용. 클리어 이후 60초마다 등장, 체력/속도/피해/공격 압력 상승. 강제 타이머 종료 아님. Vampire Survivors 커뮤니티의 반복 사신과 성장 한계 논의 참고.
45. 일시정지의 고정 행동/단일 정보 스크롤 — 적용. Shooter 현재 메뉴의 구조와 Card의 명확한 계층, 실제 웹게임 메뉴 참조. 4개 동작을 한 줄에 구겨 넣는 기존 UI 폐기.
46. 제목/캐릭터/실제 그림 메뉴 + 단일 하단 도크 — 적용. 10 Minutes 실제 웹 메인, HoloCure 공개 UI/소개, PokeRogue 실제 로그인/메뉴 소스 확인. 서로 다른 UI 에셋을 복사하지 않음.
47. 왼쪽 이동/오른쪽 회피+필살기 — 적용/검증. MDN pointer capture, 실제 두 손가락 입력. 입력 이동 방향을 그림 반전으로 변경하지 않음.
48. dvh/safe-area/가로 화면/320px — 적용/검증. 일시정지 동작은 본문 스크롤과 독립, 하단 도크와 본문 겹침을 여백으로 방지.
