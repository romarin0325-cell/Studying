# 원본과 공개판의 차이 · 의도 · 수정의 적용 범위

> 2026-11-24 작성(Claude, 소유자 요청). 공개판(`defense_public/`)이 원본(`defense/`)과 다른 곳을 모두 적고, 각 차이를 **왜** 두었는지 남긴다.
> 목적: 나중에 어느 한쪽을 고칠 때 **어디까지 적용할지**(두 판본 / 공개판만 / 원본만)를 이 문서 하나로 정한다.
> 숫자의 기준은 코드와 [PUBLIC_TEMPO.md](PUBLIC_TEMPO.md)다. 이 문서는 숫자보다 "무엇이 다르고 왜 다른가"를 적는다. 차이를 새로 만들거나 없애면 이 문서를 같이 고친다.

## 0. 두 판본의 성격

| | 원본 `defense/` | 공개판 `defense_public/` |
|---|---|---|
| 누가 하나 | 소유자의 본 게임. 하루 한두 번 들르는 **준방치형** | 웹 공개 테스트의 테스터. **하루 안에 게임 대부분을 본다** |
| 시간 단위 | 일·주·달 | 시간·분 |
| 학습 | 강의·용어 퀴즈·오답 노트·루미 AI 해설 | 없음 |

두 판본의 차이는 거의 모두 이 한 가지 차이(시간 단위와 목적)에서 나온다. 그래서 **차이가 '시간·수입·진행 길이'에 관한 것이면 공개판 고유, 그 밖(전투·동료·유물·그림·연출·화면 구조·문구)은 공통**이 기본이다.

## 1. 수정의 적용 범위를 정하는 순서

1. 고치려는 것이 아래 **2장의 차이 항목**에 해당하는가?
   - 해당하면: 그 항목의 "수정이 오면" 칸을 따른다(대개 공개판은 자기 값으로 따로 정한다).
   - 해당하지 않으면 2번으로.
2. 고치려는 코드가 **3장의 '같은 파일'** 에 있는가? → 두 판본에 똑같이 적용한다(파일째 복사해도 된다).
3. **3장의 '갈라진 파일'** 에 있는가? → 두 판본에 적용하되, 파일째 덮어쓰지 말고 바뀐 부분만 옮긴다(갈라진 이유가 그 파일에 섞여 있다).
4. **원본에만 있는 파일**(학습, 신규 동료 16명 등)이면 원본만. 공개판에 필요하면 5장의 절차로 옮긴다.
5. 판단이 서지 않으면: "같은 날 하루 안에 보는 테스터에게도 같은 경험이어야 하는가?"를 묻는다. 그렇다면 두 판본, 아니면 원본만이고, 공개판에는 공개판 값으로 따로 넣는다.

옮긴 뒤 공개판은 `npm run test:defense-public`, `node defense_public/scripts/build.mjs`, 시간·수입을 건드렸다면 `node defense_public/scripts/day-sim.mjs`를 돌리고 [PUBLIC_TEMPO.md](PUBLIC_TEMPO.md)의 측정표를 갱신한다.

### J. 판본마다 다른 화면 문구
루미 대사의 주기 낱말("4시간마다" 대 "달마다" 등)은 `app.js`의 `PACE`, 서재 소개는 `LIBRARY_LINES`, 새싹 안내는 `SPROUT_TIP` 한 곳에 모았다. 나머지 튜토리얼 코드는 두 판본이 같다.
**수정이 오면**: 대사·안내를 고치면 두 판본에 같이 적용하고, 주기·서재·새싹에 관한 낱말만 각 판본의 `PACE`·`LIBRARY_LINES`·`SPROUT_TIP`에서 따로 고친다.

### K. 카드 동료 16명 — 어느 판본에도 넣지 않음 (시험판 전용)
- 카드 게임에서 옮긴 16명(빅토리아 등, PR 701)은 **별도 시험판**용이다. 시험판은 브랜치 `codex/defense-full-roster`(작업 폴더 `full-test`)에 있다.
- 원본에 잘못 병합되었던 것을 2026-11-24 PR 705로 원본에서 뺐다(소유자 결정). 공개판에는 처음부터 없다.
- **수정이 오면**: 16명 관련 작업은 시험판에서만 한다. 원본·공개판에 넣으려면 소유자 결정이 먼저다.
