# 공개판 템포와 재화 수급 (2026-11-23)

웹 공개 테스트용 `defense_public/`의 주기·수입 설계다. 원본 `defense/`는 하루 한두 번 들르는 준방치형이다(파견·방치 24시간, 드래프트 주간, 토벌 월간, 서약·쌍성 격주, 새싹 일주일, 학습 퀴즈). 공개 테스트의 테스터는 하루에 게임 대부분을 보고 싶어 한다. 그래서 주기를 시간 단위로 줄이고, 수입의 중심을 "기다림"에서 "플레이"로 옮겼다. 코드는 `src/tempo.js`(주기), `src/content.js`의 `TUNING`, `src/economy.js`, `src/bond.js`, `src/beginner.js`, `src/profile.js`, `src/monthly.js`, `src/preview/*.js`에 있다.

## 0. 원칙

1. **진행 대비 자원은 원본과 비슷하게, 걸리는 시간만 하루로.** 원본에서 1부(스테이지 54)는 첫 클리어 1.9만에 한 달가량의 출석·임무·도전·방치·파견이 더해진 자원으로 깨는 구간이다(45 이후 원본 속도 모델은 하루 0.5스테이지, `defense/docs/archive/DAWN_GARDEN.md` 4.1). 공개판은 그 시간 수입을 첫 클리어·스테이지 별가루·짧은 주기의 도전으로 바꿔, 같은 진행 지점에서 비슷하거나 조금 넉넉한 자원을 하루 안에 준다. 성장 비용 곡선(화단 소프트캡, 중복 강화)과 전투 난이도는 건드리지 않았다.
2. **플레이가 가장 많이 준다. 쉬는 시간은 방치와 파견이 메운다.** 열심히 하는 테스터의 별가루는 대부분 클리어에서 온다(아래 측정). 방치 상한은 흔한 휴식 길이(4시간)에 맞춰, 점심 뒤에 돌아오면 15분쯤 플레이한 만큼이 쌓여 있게 했다. 기다리는 것이 플레이보다 이득인 순간은 없다.
3. **보이는 목표는 늘 한 시간 안에 있다.** 파견 1시간, 선물 15분, 부탁 30~60분, 픽업 2시간, 수호자·드래프트·이벤트 4시간, 토벌·이벤트 시즌 8시간. 한 번 앉은 플레이 안에서 각 고리를 한 바퀴 돈다.
4. **벽 앞에서 할 일이 있다.** 막힌 스테이지 앞에서는 지난 스테이지를 다시 깨 별가루를 모으고(호감도와 루미의 별도 함께 오른다), 도전 콘텐츠의 보상(3배)이 꿈의결정을 채운다.
5. **운은 뽑기 안에.** 퀴즈 정답 때의 확률(UR 0.4%)을 기본으로 고정하고, 정답 보너스였던 "행운의 보너스 10회"를 유료 10회 소환의 10% 무작위 행운으로 옮겼다.

## 3. 판단과 남은 결정

- **첫 세션.** 가벼운 기본 오토 모델도 45분에 새싹 7단계를 마쳤고, 평균 꿈의결정 14,793을 받았다. 유료 동료·유물 소환과 행운 보너스를 합쳐 평균 177회 소환했다.
- **진행 편차.** 합리 오토 6명의 첫날 범위는 스테이지 26–66, 둘째 날 끝은 47–81이었다. 기본 오토 6명은 첫날 23–62에 도달했다. 합리 오토 중앙값은 둘째 날에 14.5스테이지 올랐다.
- **반복 정산.** 패배 보상과 전투 인연은 깬 웨이브에 비례해 0웨이브에서는 0이다. 루미의 별은 서재가 열린 뒤 메인 원정에서 이겼을 때 켜진다.

## 4. 확인하지 못한 것

- 실제 사람의 플레이 속도·휴식·선택. 시뮬레이터는 자동 편성과 정해진 규칙으로만 고른다. 2배속·메뉴 25초 가정이 다르면 시간 축이 늘거나 준다.
- 쌍성 원정은 시뮬레이터가 하지 않아 도전 수입이 실제보다 낮게 잡혔다.
- 실제 휴대폰(터치·성능), WebKit. 화면은 Chrome 390×844 두 테마로 확인했다(`tests/browser.mjs` 74장, `scripts/review-tempo.mjs` 전후 비교).
