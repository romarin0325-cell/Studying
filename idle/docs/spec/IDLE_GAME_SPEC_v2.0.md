# 0. 제작 목표와 변경 불가 조건

## 0.1 목표 경험

플레이어는 다섯 영웅이 돌아오는 거점을 방문한다. 방치 보상을 수령하고, 오늘 성장시킬 영웅을 고르고, 어제와 달라진 돌파 결과를 확인한다. 새로운 동료는 전투 선택지를, 기억은 일러스트와 관계 장면을 제공한다. 시간이 있는 날에는 별도의 짧은 모험을 즐긴다.

**핵심 루프:** `귀환 → 일괄 수령 → 오늘의 작은 기대 공개 → 성장 선택 → 돌파 결과 → 소환/관계/수집 → 다음 목표 지정`.

“할 일이 열 개 생겼다”보다 “오늘 루미의 기술 순환이 달라졌다”가 성공이다. 동시에 5분 접속에는 “이번 귀환에는 무엇이 조금 더 나왔을까”라는 기대가 최소 한 번 존재해야 한다. 무작위 획득은 놀라움을 담당하고, 확정 성장은 진척을 담당한다. 두 역할을 서로 대체하지 않는다.

v2.0의 보상 원칙은 **바닥을 낮추지 않고 위쪽 분산만 추가하는 것**이다. 강화 실패·파괴·천장 초기화·기본 보상 삭감으로 긴장을 만들지 않는다. 상향 보너스는 전용 RNG에서 결과를 먼저 확정·저장한 뒤 연출하며, 표시되지 않은 비공개 보정이나 가짜 근접 연출을 사용하지 않는다.

## 0.3 이번 문서에서 확정한 설계 수정

1. 주역 5명 + 동료 24명 + 특수 기억 2개로 분리한다. 31개의 독립 육성 대상을 만들지 않는다.
2. 다섯 원정은 각각 기록을 가지지만 수령·훈련·돌파 조작은 묶을 수 있다.
3. 동료는 독립 레벨/장비를 요구하지 않는다. 지원 행동의 수치가 배속 영웅을 참조한다.
4. 장비 소환, 강화 실패, 환생에 의한 영구 육성 초기화, 필수 광고는 없다.
5. **기억의 일러스트 획득과 전투 성능을 분리한다.** 전투 스타일은 숙련으로 상시 해금하고, 기억은 그림·장면·연출을 준다. 특정 그림을 놓쳐 영웅 운용이 불완전해지지 않는다.
6. 개인용 최초 버전은 계정 생성일 기준 28일 시즌이다. 처음 설치한 시점 때문에 시즌 보상을 놓치지 않는다. 실제 달력의 계절 장식은 별도 옵션이다.
7. 일일 보상은 전투 성공이나 소환 소비를 요구하지 않는다. 티켓을 모아두어도 손해가 없다.
8. 동료·기억 소환의 실패 결과를 4단계 재료 등급으로 나누되, 완성품 확률·천장·평균 재료량은 유지한다. 무작위 성공도 천장을 초기화하지 않는다.
9. 방치 귀환 상자·강화 대성공·일일 별나비·보스 반짝 흔적은 모두 **기존 보상 위의 추가 보너스**다. 기본 수율을 낮춰 평균만 맞추지 않는다.
10. 결정론 전투의 정확한 승패 분석은 첫 도전의 긴장감을 없애지 않도록 기본 입장 전에는 숨기고, 첫 패배 뒤 사용자가 요청할 때 제공한다.
11. 두 번째 접속 훅은 경제 격차가 아니라 ‘귀환 편지를 더 빨리 읽는 것’으로 만든다. 하루 한 번 접속해도 다음 날 편지를 회수할 수 있다.
12. 실제 사람인 척하는 로컬 봇 리그, 무작위 10분 소환 창, 하루 15회 보너스 게이트, 광고 연쇄 보상은 넣지 않는다.

## 0.4 비목표

PvP, 서버 계정, 길드, 실시간 협동, 과금, 광고 SDK, 외부 LLM/API 대화, 학습 문제, 푸시 알림, 신규 주인공 추가, 무작위 장비 옵션 감정은 최초 출시 범위에 넣지 않는다. 개인용 파일의 시계 조작·저장 편집을 완벽하게 방지한다고 주장하지 않는다.

고스트 리그처럼 실제 이용자가 아닌 대상을 사람처럼 꾸며 비교시키는 기능, 접속 중 임의의 10분에만 열리는 소환 혜택, 여러 번의 카운트다운 시청을 일일 루프로 만드는 기능도 비목표다. 향후 광고/퀴즈 대체 보상을 실험할 수 있도록 비활성 인터페이스를 둘 수는 있지만, 기본 빌드에는 플레이어용 게이트 UI를 노출하지 않는다.

## 2.2 ID와 소유권

영웅 ID는 `zeke/lumi/queen/jasmine/luna`다. 원본의 `rumi`, `zeek` 같은 철자와는 별도의 명시적 import map을 둔다. 표시 이름으로 저장 데이터를 찾지 않는다.

| 2~3분 | 선택한 영웅의 1전투, 기술 연출과 속성 배율 설명. 언제든 결과 보기 가능 |
| 3~4분 | 확정 동료 5명을 자동 배속, 편성 교체를 한 번 체험 |
| 4~5분 | 지급 10회 동료 소환. 결과는 한 거래로 확정·저장한 뒤 5단계 승급 연출로 공개. 비초기 동료 1명 보장 |
| 5~7분 | 첫 관계 장면과 첫 상시 기억 미리보기. 시즌 시작 선물 지급 |
| 7~10분 | 오늘의 목표 3개 이하, 천장 링·지정 기억 진척, 보상 누적과 수동 백업 안내 |

대사 강제 재생·설정 강의·여러 메뉴의 연속 팝업으로 이 흐름을 막지 않는다. 처음부터 다섯 영웅을 지급하고 기능만 순차 안내한다. 첫 10분 안의 무지개 연출은 초보자 동료 보장의 정직한 표시이며, 실제 결과보다 높은 등급을 스쳐 보여주지 않는다.

## 3.2 기본 일일 행동과 보상

추가 수령 화면 없이 조건 완료 즉시 보상 장부에 지급한다.

| 조건 | 동료권 | 기억권 | 기타 |
|---|---:|---:|---|
| 그 게임 날짜의 첫 접속 | 2 | 1 | 연구권 2(보유 상한 4), 선물 3개, 교류 횟수 +1(상한 2) |
| 원정 보상 1회 수령 | 2 | 1 | 해당 없음 |
| 오늘의 정비 1회 | 1 | 1 | 승패/자원 소비 무관 |

`오늘의 정비`는 훈련·장비 강화·새 기록 도전·검증된 최고 기록의 일괄 정산 중 하나다. 만렙/재화 부족 플레이어도 기록 확인 버튼으로 완료 가능하다. 소환을 해야 소환권을 받는 순환 미션은 없다. 세 조건을 완료한 날짜를 `qualifiedDay`로 기록한다.

개인 주간 2/4/6개의 qualifiedDay에서 기억권을 각각 3개 지급한다. 최대 주 9개. 이전 날 미지급 로그인 보상을 자동 소급하지 않는다. 이미 조건을 달성한 주간/시즌 보상은 시즌이 끝나도 회수할 수 있게 자동 우편함에 보관한다.

## 3.3 기본 접속 화면 순서

`원정 일괄 수령+귀환 상자 공개 → 성장 추천 하나 선택 → 자동 돌파 묶음 → 소환(선택) → 교류/편지(선택)`.

숙제 메뉴 전체를 순회하지 않는다. 관계/소환은 5분 루프에서 즐길 수 있지만 해당 행동을 생략해도 주요 성장 자원을 잃지 않는다. 홈의 빨간 점은 신규 장면/즉시 수령에만 쓴다. 매번 살 수 있는 상점에는 붙이지 않는다.

귀환 상자 공개·소환 결과·신규 장면이 같은 접속에 겹쳐도 모달을 연속으로 강제하지 않는다. 먼저 홈 요약에 쌓고 사용자가 하나씩 열 수 있게 한다. 5분 루프에서 자동 팝업은 튜토리얼을 제외하고 최대 2개다.

## 3.4 짧은 기대 장치와 두 번째 접속

### 일일 귀환 상자

그 게임 날짜의 첫 번째 **2시간 이상 누적분 수령**에서 한 번만 등급을 판정한다. 첫 수령이 2시간 미만이면 그날 다음 적격 수령까지 보류한다. 기본 XP/골드/광석은 항상 100% 지급하고 아래 보너스만 추가한다. 훈련점·관계점·티켓은 배수 대상이 아니다.

| 등급 | 확률 | 적격 수령분 추가 보너스 |
|---|---:|---|
| 나무 | 70% | 없음 |
| 은 | 22% | XP/골드/광석 +15% |
| 금 | 7% | XP/골드/광석 +50% |
| 별 | 1% | XP/골드/광석 +150%, 동료권 1 |

기대 추가량은 적격 수령분의 8.3%다. 이 기대값을 맞추려고 §5.1의 기본 수율을 낮추지 않는다. 상자 결과는 `rewardRng`로 먼저 확정·커밋한 뒤 공개한다. 하루 여러 번 잘게 수령해 상자 횟수를 늘릴 수 없다.

### 일일 별나비

첫 입력 후 30~90초 사이 홈/원정에 하루 한 번 등장한다. 60초 동안 떠다닌 뒤 화면 가장자리의 작은 아이콘으로 정착해 당일 언제든 누를 수 있으므로, 보고 있지 않았다고 보상이 사라지지 않는다. 보상은 현재 총 기본 수율 기준 XP/골드 15분분이며, 5% 황금 나비는 동료권 1개를 추가한다. 광석·훈련점·관계점·기억권은 주지 않는다. 재접속·화면 이동으로 재추첨하지 않는다.

### 귀환 편지

그날 첫 원정 수령 또는 qualifiedDay 성립 시각에서 4시간 뒤 편지 1개가 열린다. 대표 영웅 또는 가장 오래 편지를 보내지 않은 영웅의 검수된 짧은 대사와 XP/골드 20분분을 담는다. 미수령 편지는 다음 게임 날짜까지 하나만 보관한다. 다음 날 첫 접속에서 어제 편지를 받고 오늘 편지를 새로 예약할 수 있으므로, 하루 한 번 접속하는 사람도 장기 경제에서 손해 보지 않는다. 두 번째 접속은 보상을 더 받는 것이 아니라 더 빨리 관계 반응을 보는 선택이다.

# 4. 다섯 원정과 자동 돌파

## 4.1 원정의 의미

각 영웅은 자신의 `highestClearedStage`를 갖는다. 선택하지 않은 네 영웅도 같은 시간 동안 자원을 축적한다. 현재 홈에 누구를 표시하는지, 현재 앱이 켜져 있는지, 몇 배속인지가 기본 수익률을 바꾸지 않는다.

원정 파밍은 수익률 계산이고, 단계 돌파는 전투다. 파밍 연출의 적을 처치할 때마다 실제 골드를 추가하지 않는다. 그렇지 않으면 화면을 켠 사람만 두 번 보상을 받게 된다.

일반 단계는 한 적을 상대하는 짧은 전투다. 10단계마다 관문, 20단계마다 챕터를 표시한다. 10단계 관문은 짧은 축하, 20단계 챕터는 배너와 보상 요약, 영웅별 100단계 단위는 큰 원정 기록 연출과 도감 문장을 제공한다. 전투 엔진은 보스/모험과 공용이다. 배경은 챕터 팔레트와 기존 지역 자산을 교체하되 다른 장소가 아닌 것을 새 지역이라고 부르지 않는다.

## 4.2 속성 배치

개인 원정의 10단계 중 1~8단계와 10단계는 해당 영웅의 유리 속성, 9단계는 중립이다. 여기서는 영웅 성장 결과를 안정적으로 보여준다. 속성/동료를 바꾸는 실질적인 선택은 공용 보스와 선택형 모험에서 만든다.

유리 속성 매핑: 지크→자연, 루미→불, 여왕→물, 자스민→어둠, 루나→빛. 같은 적 그림의 속성만 몰래 바꾸지 않는다. 속성이 다른 변형이면 외형 표식·이름 접미사·아이콘을 함께 표시한다.

## 4.3 일괄 자동 돌파

사용자가 누르면 각 영웅의 준비된 편성으로 다음 단계를 순서대로 전투 시뮬레이션한다. 영웅당 최대 30단계 또는 첫 패배까지, 전체 최대 150전투다. 계산은 UI를 블로킹하지 않게 작은 묶음으로 yield한다. 취소한 시점까지 확정된 승리만 저장한다.

새로 얻은 동료나 미장착 유물의 영향을 자동으로 가정하지 않는다. 실제 장착 스냅샷만 쓴다. 결과는 `5명 요약 → 오늘의 가장 큰 돌파 1개 → 자세히` 순서로 표시한다. 나머지 네 명의 새 기록을 숨기지 않는다.

최초 관문에서도 장시간 관전은 강제하지 않는다. 연출 보기/결과 보기 모두 동일한 엔진 결과를 사용한다. 빠른 계산과 관전의 결과가 다르면 회귀 오류다. 오프라인 중 새로운 단계를 자동으로 뚫었다고 계산하지 않는다.

## 4.4 관문 보상과 개방

일반 단계의 반복 승리는 자원 보상을 주지 않는다. 최초 관문 승리는 `현재 시간당 공용 XP/골드의 0.1시간분 + 해당 영웅 훈련점 4`를 한 번 지급한다. 최초 20단계 챕터 승리는 추가 동료권 1개를 준다. 보상 ID에는 영웅 ID와 단계 ID를 포함한다.

전 계정 진행은 `M=sum(다섯 영웅 highestClearedStage)`로 본다. 기능 개방은 M 기준이며 최저 영웅 레벨로 계정 전체를 잠그지 않는다. 동료 두 번째 슬롯 M=15, 보스 M=10, 장신구 M=20, 유물 제작 M=30, 선택형 모험 M=60, 아스테아 M=200. 모든 기능을 레벨 100~150까지 감추지 않는다.

다섯 원정 모두 특정 챕터를 달성하면 장식용 단체 기록/배경을 준다. 필수 화력의 큰 덩어리를 이 조건에 잠그지 않는다.

일괄 돌파로 여러 매듭을 넘긴 경우 전투마다 팝업하지 않는다. `넘긴 관문 수 → 새 챕터 → 100단계 원정 기록` 순서로 한 번에 요약하며, 사용자가 원하는 항목만 펼친다. 50단계마다 별도 동료권을 추가하지 않는다. 이미 20단계마다 존재하는 동료권 경제와 중복되어 수집 속도를 과도하게 올리기 때문이다.


## 4.5 원정 적 생성식

```text
r = 1 + floor((단계-1)/3)
일반 적 HP = 1000×F(r); ATK = 24×F(r)
관문 적 HP = 5000×F(r); ATK = 55×F(r)
공통 DEF/MDEF = 60×(1+0.015×(r-1))
평타 = 3초마다 물리 1.0배, 관문 추가 공격 = 10초마다 물리 2.0배(2초 예고)
```

관문은 20단계 단위로 방어 구간/작은 보호막/짧은 약화 중 하나만 추가한다. `floor(단계/20)%3`에 따라 0: 12초마다 3초간 직접 피해 감소 30%, 1: 15초마다 최대HP 8% 보호막 5초, 2: 14초마다 약화 4초다. 최초 10단계 관문에는 추가 변형이 없다. 아트는 일반 원정 정예의 변형을 사용하고, 해당 패턴을 익힌 뒤 10종의 이름 있는 보스로 이어진다.

# 5. 성장 공식과 자원 흐름

## 5.1 정의

`L`은 현재 영웅 레벨(1~400), `s`는 현재 최고 원정 단계(0~1200), `g`는 강화 전 장비 단계(0~99), `n`은 구매한 숙련 노드 수(0~59)다. `ceil`/`floor`의 적용 시점을 그대로 지킨다.

```text
F(L) = (1 + 0.05 × (L-1))²
XP 비용(L→L+1) = ceil((20 + 4L + L²) × C)
C = max(0.5, 0.5 + 0.5 × L / 계정 최고 영웅 레벨)
골드 레벨 비용 = ceil(1.5 × 실제 할인 후 XP 비용)

영웅별 시간당 XP = 30 × (1 + s/25)
영웅별 시간당 골드 = 90 × (1 + s/25)
영웅별 시간당 광석 = 5
영웅별 시간당 훈련점 = 1
영웅별 시간당 관계점 = 0.25
```

광석은 공용으로 합산한다. 훈련점/관계점은 해당 영웅에게 귀속한다. 따라잡기 할인은 XP/레벨 골드에만 적용하고 장비·티켓·숙련 비용에는 적용하지 않는다. 구매 도중 최고 레벨이 바뀌면 다음 한 레벨 비용부터 재계산한다. 부동소수점 경계 오차를 피하려면 실제 XP 비용을 `ceil(baseCost×(maxLevel+L)/(2×maxLevel))`라는 정수 분수로 계산한다.

시작 자원은 골드 6,000 / XP 1,000 / 광석 300 / 동료권 10. 시즌 시작 기억권 3은 별도의 season-start 보상이며 초기 저장에도 다시 넣지 않는다. 초기에 다섯 명 모두 레벨 1이다.

## 5.2 능력치 구성

```text
공격 스탯 = baseATK_or_MATK × F(L)
             × (1 + 0.025×무기강화)
             × (1 + 0.03×숙련노드 + 장착유물의 가산 보너스)
             × (1 + 동일 스탯의 모든 전투 중 가산 증가)
HP = baseHP × F(L) × (1 + 0.03×방어구강화) × (1 + HP 증가 합계)
DEF/MDEF = baseDefense × (1 + 0.015×(L-1))
            × (1 + 0.015×방어구강화) × (1 + 방어 스탯 증가 합계)
장신구 치명 증가 = 0.002×g; MP 회복 증가 = 0.01×g/초
```

숙련/장비 계수와 일시 버프를 어느 버킷에 넣는지 바꾸지 않는다. 최종 대미지 가산 증가끼리는 합하고, 속성·치명·방어·노출은 별도 승산으로 한 번만 적용한다. 상세 화면에서 각 버킷의 기여를 볼 수 있게 한다.

## 5.3 숙련과 운용 변화

영웅별 훈련점으로 노드를 구매한다. 비용은 `36+12n`. 모든 노드는 ATK/MATK +3%를 위 가산 버킷에 제공한다. 2/6/12/20번째 노드에서 고유 운용 선택이 추가된다. 노드 하나당 새로운 능력을 무한히 만들어내지 않는다.

| 영웅 | 노드 2: 두 스타일 중 선택 | 노드 6 | 노드 12 | 노드 20 |
|---|---|---|---|---|
| 지크 | 철벽: 가드량 +30%, 이그니스 피해 -10% / 결전: 가드량 -20%, 라그나로크 +15% | 가드 유지 중 기본 공격 +12% | 라그나로크 저HP 조건 60%로 완화 | 치명상 생존 시 MP 30 회복 |
| 루미 | 순환: MP 회복 +1/초, 궁극 피해 -10% / 유성: 궁극 +20%, 궁극 MP +10 | 별 최대 4(계수 보너스 최대 +80%) | 문라이트세레나 별 +2로 변경 | 꿈의형태 후 별 1개 남김(소모량과 별개로 사후 생성) |
| 여왕 | 개화: 왕관 보유 가산 7%/개, 피날레 -10% / 수확: 보유 가산 3%/개, 피날레 +20% | 왕관 최대 4 | 로열블룸 왕관 +2 | 피날레로 4왕관 소모 시 HP 15% 회복 |
| 자스민 | 성역: 배리어 +40%, 더홀리 -10% / 강림: 여신강림 지속 +2초, 배리어 -20% | 더홀리 디바인 +2 | 디바인 3 대상 피해 1.30배로 변경 | 여신강림 MP 비용 -10 |
| 루나 | 월영: 회피 +5%p, 다크메테오 -10% / 암살: 이클립스 +20%, 회피 -5%p | 이클립스 암흑 +2초 | 다크메테오 후 행동 정지 0.5초 | 암흑 대상 궁극 피해 +15% |

스타일은 전투 밖에서 무료 변경한다. 서로 배타적인 스타일을 동시에 적용하지 않는다. 숙련은 가챠나 기억 그림과 무관하다.

## 5.4 장비

영웅당 세 슬롯의 고정 성장형 장비다. 장비 아이템 수백 개를 드롭하지 않는다. 각 슬롯에는 강화 트랙 하나와 효과 선택 두 개가 있다. '추천 장착' 버튼 대신 '추천 효과'를 제공한다.

강화 비용: 광석 `10+4g`, 골드 `120+40g+10g²`. 실패·파괴·강화 단계 하락 없음. 무기/방어구/장신구를 바꾸어 표현하더라도 강화 단계는 슬롯에 남는다.

각 강화 단계는 10% 확률로 `대성공`이 발생해 그 단계에 사용한 광석의 50%를 즉시 환급한다. 골드는 환급하지 않는다. 대성공은 강화 단계나 성능을 추가로 올리는 대신 비용만 줄이는 상향 보너스이며, 실패 결과가 없다. 일괄 강화는 단계별 결과를 한 거래로 확정하고 `대성공 ×N / 광석 환급 M`으로 요약한다. 새로고침으로 결과를 다시 굴릴 수 없고, 대성공을 이유로 기본 강화 비용을 올리지 않는다.

강화 5에서 다음 효과 쌍을 열고 선택한다. 강화 15/30에서 효과의 수치가 각각 기본의 1.25/1.5배가 된다. 그 이후에는 일반 강화 스탯만 증가한다.

| 슬롯 | 선택 A | 선택 B |
|---|---|---|
| 무기 | 기본 공격 직접 피해 +10% | 영웅 공격형 기술 직접 피해 +8% |
| 방어구 | 최대 HP +10% | DEF/MDEF +15% |
| 장신구 | MP 회복 +0.5/초 | 치명타 피해 배수 +0.10 |

전투 중 교체 불가. 선택은 프리셋에 저장된다. 대량 강화는 지출 상한과 최종 결과를 미리 표시하고 한 번의 원자적 거래로 처리한다.

## 5.5 성장 수치의 해석

동봉한 경제 점검기는 전투 승리를 계산하지 않는다. `최고 원정 단계=3×(레벨-1)`이라는 가정으로 자원 흐름만 검사한다. 해당 가정에서 대략 첫날 레벨 13~14, 28일 레벨 70 전후, 90일 레벨 127 전후의 분산 육성이 나온다. 이것을 실제 플레이 결과나 밸런스 통과로 기재하지 않는다.

실제 제작자는 전투 엔진을 연결해 30/60/90일 계획을 다시 계산해야 한다. 경제식의 초기 목적은 90일에도 계정 전체에서 하루 몇 번의 레벨 상승을 남기는 것이다. 목표 달성 여부는 능력치 증가뿐 아니라 관문·기술 주기·공략 변화로 따로 평가한다.

# 6. 전투 엔진 계약

## 6.1 단위와 전투 순서

고정 tick 50ms(20Hz)로 논리를 진행하고 화면은 별도 렌더링한다. MP는 시작 50/최대 100/기본 회복 **초당 4**다. 기본 공격은 MP를 쓰지 않는다. 스킬 공통 행동 잠금은 0.5초. 개별 CD는 시전 완료 시점부터 시작하며 쿨다운 감소 상한은 30%다.

한 tick의 순서는 `만료 처리 → MP/주기 회복 → 예약 착탄/DoT → HP0/승패 처리 → 동료 지원 → 영웅 기술 선택 → 기본 공격 → 적 행동 → HP0/승패 처리`다. 같은 시각 이벤트는 고정 event sequence로 정렬한다. 스킬 피격판정 뒤에 피격 연출이 따라가도록 하지 말고, 착탄 이벤트가 피해와 연출을 함께 발생시킨다.

1/2/4배속은 동일한 tick을 더 빠르게 처리할 뿐 스킬 주기, 횟수, 보상을 바꾸지 않는다. 전투가 끝나면 남은 이벤트를 실행하지 않는다. 동시 사망은 그 tick의 모든 이미 예약된 피해를 처리한 뒤 판정하고, 보스와 영웅 모두 HP0이면 패배로 통일한다. 지크의 1회 생존은 HP0 판정 전에 적용한다.

최대 시간은 일반 30초, 관문/보스 60초, 아스테아 개별 시험 45초다. 일반/보스의 시간 초과는 패배, 아스테아는 기록으로 남긴다. 전투 시작/끝에 HP·MP·상태를 초기화하며 이전 실패의 상태 이상이 다음 도전에 남지 않는다.

## 6.2 피해 계산

```text
p,m = 기술에 명시된 물리/마법 계수
P = p × 시전자 ATK × max(0.25, 500/(500 + 대상 유효DEF))
M = m × 시전자 MATK × max(0.25, 500/(500 + 대상 유효MDEF))
직접 피해 = floor((P+M) × 속성배율 × 치명배율 × (1+직접피해증가합)
                   × 노출배율 × 특수패턴피해감소 × 받는피해배율)
```

두 성분을 각각 방어 계산하고 합한다. 혼합 공격에 속성/치명을 두 번 곱하지 않는다. 최소 피해 1은 명중했고 계수가 양수일 때만 적용한다. 회피·무효·비공격 기술은 0이며 이 경우 최소 피해를 만들지 않는다.

기본 치명타율 10%, 치명 배수 1.5, 치명 확률 상한 70%, 회피 상한 50%. 일반 루나는 패시브 회피 10%를 갖는다. 치명과 회피는 고정 전투 시드에서 독립 판정한다. 한 피해 패킷의 물리·마법 성분은 동일 치명 판정을 공유한다. 분할 타격은 계수 총합을 지키고 패킷마다 판정한다.

보호막은 HP 피해 전에 감소한다. 남은 보호막보다 작은 새 보호막을 받아 기존 보호막이 약해지면 안 된다. 같은 계열은 `max(현재량, 신규량)`으로 대체하고 지속 시간을 갱신한다. 서로 다른 출처의 보호막도 v1에서는 합산하지 않고 가장 큰 하나만 유지한다. 보호막 획득 후 발동 효과는 신규 부여가 성공한 1회에만 처리한다.

회복은 최대 HP를 초과하지 않으며 보호막 수치에 더하지 않는다. 직접 피해와 DoT의 원인 ID를 구분해 '피격 시' 효과가 자기 자신을 무한 재발동하지 않게 한다. 지원 기술이 다시 지원 기술을 호출하는 루프를 금지한다.

## 6.3 속성 표

| 공격→방어 | 불 | 물 | 자연 | 빛 | 어둠 | 무속성 |
|---|---:|---:|---:|---:|---:|---:|
| 불 | 1 | 0.65 | 1.8 | 1 | 1 | 1 |
| 물 | 1.8 | 1 | 0.65 | 1 | 1 | 1 |
| 자연 | 0.65 | 1.8 | 1 | 1 | 1 | 1 |
| 빛 | 1 | 1 | 1 | 1 | 1.8 | 1 |
| 어둠 | 1 | 1 | 1 | 1.8 | 1 | 1 |
| 무속성 | 1 | 1 | 1 | 1 | 1 | 1 |

이 배율은 **아군이 적에게 주는 피해**에만 적용한다. 적의 공격은 자신의 패턴과 ATK/피해 유형을 사용하고 역상성 배율을 다시 곱하지 않는다. 빛/어둠의 상호 우위를 이유로 두 배 가까운 피격 부담을 추가하지 않는다. 이 비대칭은 도움말에 공개한다.

지원 기술의 속성은 배속 영웅의 속성을 따르는 '영웅 공명'이다. 동료의 원래 세계관 속성은 프로필에 남기되 지원 피해의 적용 속성을 함께 표시한다. 처음부터 특정 속성 동료 두 명을 강제하지 않는다.

## 6.4 상태 레지스트리

| ID | 효과 | 상한/기간 규칙 |
|---|---|---|
| burn/작열 | 1초마다 시전자 MATK의 12%에 속성 배율 적용. 치명·방어 무시 | 3스택, 8초, 새 스택은 각각 snapshot/만료 보유 |
| poison/중독 | 1초마다 시전자 (ATK+MATK)의 6%에 속성 배율 적용. 치명·방어 무시 | 3스택, 8초, 개별 만료 |

| blind/암흑 | 대상 기본 공격 명중 확률 -20%p. 큰 기술/DoT에는 미적용 | 기본 4초, 출처별 기간 중 긴 값으로 갱신 |

기본 duration과 기술에 명시된 duration이 다르면 기술 값을 쓴다. DoT는 첫 부여 1초 후 첫 tick, 만료 시각의 마지막 tick은 적용하고 제거한다. 기본 기술 피해가 없는 지원이라도 상태 부여는 가능하다. 스킬 설명/아이콘/계수 화면은 하나의 데이터에서 생성한다.

## 6.5 자동 행동과 전술 설정

기본 자동 우선순위는 `조건 충족 생존 기술 → 사용 가능한 궁극기 → 공격 기술 → 자원/강화 기술 → 기본 공격`이다. 같은 계열은 플레이어가 지정한 순서, 미지정이면 데이터 순서다. 조건이 안 맞는 기술 때문에 뒤 기술을 모두 대기시키지 않는다.

'공격 보류' 설정은 공격형 기술만 최대 4초 미루어 방어 구간이 끝나거나 노출이 시작되길 기다린다. MP 회복/기본 공격/생존 기술/동료 지원은 계속된다. 보류 종료 또는 남은 전투시간 5초 이하면 사용한다. 무한 대기 금지.

초반에는 표준/생존/폭발 세 프리셋을 제공한다. 추가 설정은 기술 순서와 '방어 구간 보류' 하나만 노출한다. 전투 중 수동 버튼은 선택 기능이며 보상을 독점하지 않는다. 기본 보상 티어는 자동 전투로 달성 가능해야 한다.

## 6.6 시드와 재현

전투 시드는 `contentVersion + encounterId + difficulty + heroId + canonicalizedLoadoutHash`의 해시에서 만든다. 재도전 횟수/현재 시각/애니메이션 속도는 넣지 않는다. 같은 편성과 같은 데이터는 재도전해도 같은 결과다. 로드아웃을 바꾸는 것은 허용되는 전략이다.

소환 RNG와 전투 RNG는 분리한다. 전투로 소환 순서를 조작할 수 없어야 한다. 시드 재현은 테스트와 공정한 재도전의 도구이며 서버 없는 앱의 치팅 방지책이라고 부르지 않는다.


## 6.7 보상 RNG와 연출 계약

전투 RNG, 동료 소환 RNG, 기억 소환 RNG, 모험 RNG, 상향 보너스용 `rewardRng`를 분리해 직렬화한다. `rewardRng`는 귀환 상자·대성공·별나비 황금 여부·보스 반짝 흔적에만 사용한다. 전투 시뮬레이션 횟수, 배속, 화면 전환, 연출 스킵이 어느 RNG의 다음 결과도 바꾸지 않는다.

가변 보상 명령은 `sourceId + gameDay/대상ID + sourceCounter + commandId`로 중복을 차단한다. 결과를 생성하고 재화·카운터·장부와 함께 원자적으로 저장한 뒤 애니메이션을 시작한다. 공개 연출은 이미 저장된 등급까지만 상승하며, 실제 등급보다 높은 색·실루엣·소리를 잠깐 보여주는 가짜 근접은 금지한다.

# 7. 다섯 영웅 초기 데이터

아래 기술명 중 기존 이름은 식별 모티프를 계승하되, 계수·MP·CD·실시간 효과는 본 게임의 새 구현이다. `p`는 ATK 계수, `m`은 MATK 계수다. 레벨 1의 기반 방어는 지크 > 루미 > 여왕 > 자스민 > 루나 순서다.

## 7.1. 지크

속성 `fire` / 대검 / 물리 중심. HP 650 / ATK 120 / MATK 30 / DEF 110 / MDEF 95.

기본 공격: 1.25초마다 `p=1, m=0`. 패시브: 전투당 최초 치명상에서 HP 1, 2초 무적, 8초 ATK +30%. 재발동 없음.

| 기술 | MP | CD(초) | 계수/효과 | 자동 조건 |
|---|---:|---:|---|---|
| 가드 | 20 | 14 | 최대 HP의 25% 보호막, 6초. | HP 70% 이하 또는 보스 큰 기술 착탄까지 3초 이하 |
| 이그니스스매시 | 25 | 8 | p=2.6, m=0. 작열 1스택, 8초. 본 게임에서는 물리 기술로 재구성. | 항상 |
| 라그나로크 | 50 | 25 | p=6, m=0. 자신 HP 50% 이하이면 피해 1.5배. | 공격 가능 시 |

## 7.2. 루미

# 8. 동료 24종과 배속 규칙

동료는 자체 HP/피격/레벨/장비가 없다. 영웅 뒤의 두 초상화와 지원 이펙트로 표현한다. 지원의 계수는 현재 영웅 ATK/MATK를 참조하고 영웅 속성으로 공명한다. 동료 소환 등급으로 원작 인물의 신분/실력을 새로 설정하지 않는다.

각 동료의 첫 지원은 슬롯 1이면 전투 3초, 슬롯 2이면 7초. 이후 표의 CD마다 발동한다. 배속 위치를 바꾸어도 전투 중 교체는 불가능하다. 전술 태그는 콘텐츠 조건용이며 원작 속성을 덮어쓰지 않는다.

교체 화면은 기존 배속 위치를 보여주고, 확인하면 두 영웅의 동료를 swap하거나 해당 위치를 비운다. 복사해서 같은 동료를 두 곳에 두지 않는다. 원정/보스/모험 프리셋은 각각 저장할 수 있지만 실제 출전 스냅샷은 한 편성으로 확정한다.

동료 랭크는 0~5. 순서대로 인연토큰 20/40/60/80/100을 쓰며, 랭크당 그 동료의 직접 지원 피해만 +3%다. 패시브/회복/보호막/해제/CD는 랭크로 늘리지 않는다. 따라서 핵심 대응 능력은 첫 획득에서 완성이다. 이미 얻은 동료의 프로필/이야기를 보는 데 추가 중복을 요구하지 않는다.

# 9. 보스·유물·연구

## 9.1 보스 공통 수치

일반 보스 티어 t(1~50)의 권장 레벨은 `5+6(t-1)`. HP는 `6000×F(권장레벨)`, ATK는 `60×F(권장레벨)`, DEF/MDEF는 원정 적과 같은 공식이다. 평타는 3초마다 물리 1배. 표의 마법 기술도 보스 ATK를 기준 피해 스탯으로 사용한다(보스의 별도 MATK는 ATK와 동일).

아스테아는 15초에 물리 감소 30%를 4초, 30초에 마법 감소 30%를 4초 적용한다. 다른 보스의 “N초마다”는 첫 발동이 전투 N초 시점이며 포세이돈/인조 마신처럼 시작 상태가 명시된 경우만 예외다.

패턴 예고, 보호막, 노출 기간은 티어가 올라가도 짧아지지 않는다. 초기 난도는 수치로 증가시키고 '동일 이름인데 예고 없이 즉사'하는 패턴을 추가하지 않는다. 패턴은 화면과 상세 설명에 동일하게 표시한다.

첫 클리어는 보스/티어별 1회. 연습 도전과 재시도는 무제한이며 패배로 연구권을 소모하지 않는다. 클리어했던 티어의 파밍은 재전투 대신 정산한다.

| 해신 포세이돈 | water | 120 | 전투 0~5초는 피해 감소 40%, 5~10초는 노출; 이 10초 주기를 반복. 10초마다 마법 2.5배. | 기술 지연 설정 또는 지속 피해. | 조수의 보석 |

저주의 여신 아이리스의 불속성은 최초 사용자 초안에 맞춘다. 이름에 '저주'가 있다는 이유로 어둠으로 자동 변경하지 않는다. 사랑의 여신 아이리스/저주의 여신 아이리스는 보스 형태로 별도 기록하되, 이 둘의 세계관 관계를 임의로 서술하지 않는다.

플로라의 회복 직후에는 회복 감소 여부와 무관하게 3초 노출한다. 파라오/포세이돈의 방어는 직접 피해에만 적용하고 DoT에는 적용하지 않는다. 토르의 방해 피해 카운터는 예고 시작 때 0으로 초기화하고 회복으로 되돌리지 않는다.

## 9.2 아스테아 합동 시험

아스테아는 별도의 5영웅 동시 AI 전투가 아니다. 각 영웅의 독립 45초 전투에서 `score_i=min(1, 누적 직접+DoT 피해/해당 티어 보스HP)`를 기록한다. 보스 HP가 0이면 점수 1에서 종료한다. 다섯 최고 점수 합계가 3.5면 기본 티어 클리어, 5.0이면 완전 기록 장식을 준다. 네 영웅으로 기본 클리어 가능하므로 최약 영웅 하나가 전부를 잠그지 않는다.

점수는 영웅/티어/콘텐츠 버전별 최고치다. 다른 영웅/티어의 점수를 중복 합산하지 않는다. 동일 티어 반복은 최초 보상을 다시 주지 않는다. 패치로 점수를 무효화하더라도 이미 얻은 수집물은 회수하지 않는다.

## 9.3 연구권과 유물 제작

일일 첫 접속에 연구권 2, 보유 상한 4. 이미 4개면 더 넣지 않고 상한을 표시한다. 연구권 1개로 이미 완료한 보스 티어를 정산하여 해당 보스 흔적 `3+최고티어`를 얻는다. 새 클리어 직후에 '연구권으로 추가 정산'을 선택할 수도 있다. 최초 클리어의 흔적은 `6+2×티어`이며 연구권 없이 지급한다.

보스별 흔적 12개로 전용 유물 1개 제작. 제작 후 강화 2~5의 비용은 20/35/55/80. 고유 효과는 1단계에서 모두 켜지고, 2~5단계는 장착 영웅의 ATK/MATK 가산 버킷에 단계당 +2%만 추가한다. 5단계일 때 추가 +8%다.

유물은 한 영웅당 한 개, 같은 유물의 계정 내 동시 장착 한 곳만 허용한다. 모든 영웅이 착용 가능하다. 강화는 유물에 귀속되고 옮겨도 유지한다. 5단계 이후 흔적은 20개당 아카이브용 장식 토큰 1로 교환할 수 있으며 XP/가챠권으로 무제한 환전하지 않는다.

| 유물 | 1단계부터 완성되는 고유 효과 |
|---|---|
| 봉인의 파편 | 적 방어 구간의 직접 피해 감소를 25%p 무시한다. 다른 피해 감소에는 미적용. |
| 신록의 씨앗 | 최대 HP +10%. 12초마다 최대 HP 6% 회복. |
| 뇌광의 인장 | 보스 예고 구간 중 직접 피해 +20%. |
| 저주의 거울 | 자신 디버프를 해제하면 최대 HP 8% 회복. 내부 대기 6초. |
| 장미의 서약 | 자신이 보호막을 받을 때 6초 ATK/MATK +12%; 중복 갱신만. |
| 쌍극의 핵 | 혼합 피해 패킷의 물리/마법 성분 각각 +12%. |
| 잔향의 가시 | 받는 지속 피해 -30%. 직접 피해에는 미적용. |
| 기원의 별 | 전투 시작 8초간 ATK/MATK +15%. 최대 HP +8%(항상). |
| 투쟁의 문장 | 전투 시작 20초 후 직접 피해 +18%. |
| 조수의 보석 | 노출 대상 직접 피해 +20%. |

추천 보스는 `gameDay mod 10`으로 날짜별 순환하지만 보스 개방/필수 흔적을 그 날짜에만 제한하지 않는다. 그날 추천 보스의 **첫 연구 정산 1회**는 기본 흔적을 1.5배로 올림 계산해 지급한다. 이후 정산은 정상 수치다. 홈에는 오늘의 보스와 다음 교대 시각을 표시하되 빨간 점으로 강요하지 않는다.

연구권 정산마다 15% 확률로 반짝 흔적 +1, 추천 보스는 25%다. 4회 연속 반짝 흔적이 없었다면 다음 정산은 확정 +1이며 이후 카운터를 초기화한다. 이 보너스는 기본 흔적 위에 더하고, 기본 흔적을 줄이지 않는다. 추천을 안 했다고 모든 성장 경로가 멈춰서는 안 된다.

# 10. 소환과 수집 경제

## 10.1 공통 원칙

동료권/기억권은 다른 자원이며 자동 교환하지 않는다. 상시 확률을 UI에 정확히 표시한다. 결과는 한 번의 영속 거래로 `티켓 차감+결과+토큰/가루+누적 카운터+history`까지 저장한 후 연출한다. 연출 중 새로고침/닫기/스킵은 같은 결과를 다시 보여줄 뿐 새 추첨이 아니다.

10회 소환은 1회 함수를 10번 UI 호출하는 방식이 아니라, 하나의 batch transaction 안에서 순서대로 확률/누적 보상을 처리한다. 여러 누적 선택권이 발생해도 모두 보존한다. 소환권이 7개일 때 '10회'를 누르면 묻지 않고 7회 소비하지 않는다. 보유 수량 소환 버튼을 별도로 둔다.

무작위 완성품을 얻어도 30/60회 선택권 카운터는 초기화하지 않는다. 이것은 운의 가치를 없애는 규칙이 아니다. 운이 좋으면 완성품을 앞당겨 얻고, 보존된 선택권으로 다른 대상을 고를 수 있어 결과가 누적된다. UI에 `무작위 획득은 선택권 진행을 지우지 않습니다`를 표시한다.

## 10.2 동료 소환

| 등급 | 색 | 결과 | 확률 |
|---|---|---|---:|
| 별빛 | 무지개 | 완성 동료 | 8% |
| 황금 | 금 | 인연토큰 10 | 4% |
| 은빛 | 은 | 인연토큰 4 | 10% |
| 청동 | 청 | 인연토큰 2 | 27% |
| 일반 | 백 | 인연토큰 1 | 51% |

완성 동료 안에서는 24명이 균등 확률이다. 비완성 결과의 인연토큰 기대값은 1회당 1.85로, v1.0의 1.84와 사실상 같다. 중복 완성 동료는 인연토큰 20개가 된다. 인연토큰 120개로 미보유 동료를 지정 영입할 수 있다.

총 소환 30/60/90…마다 추가 선택 영입권 1장. 선택권으로 미보유를 고르는 것이 기본이며, 전원 보유 후에는 선택권 1장→인연토큰 120개. '선택권을 쓰면 누적 30회가 차감된다' 같은 별도 처리 없이 총 횟수와 이미 지급한 임계점 수를 보관한다.

초보자 10회 안에 비초기 동료 1명을 보장한다. 첫 9회 동안 비초기 동료를 얻지 못했다면 10번째 결과의 완성 동료를 비초기/미보유 중 균등 선택한다. UI에 이 특별 보장을 표시하고 실제 확률표에 예외를 설명한다. 기본 30회 누적 보장도 동시에 증가한다. 해당 결과는 실제 별빛 등급으로 커밋되고 무지개 연출을 사용한다.

원하는 동료를 이미 선택했거나 다른 경로로 획득했을 때 선택권은 소모하지 않는다. 영입/랭크업 확인 화면에는 '미보유 영입에 사용할 토큰'과 '랭크 강화'의 기회비용을 표시한다. 중복 동료 결과 카드에는 다음 랭크까지의 실제 토큰 진행 막대를 함께 표시한다. 전부 얻은 이후 추가 동료를 자동 생성하지 않는다.

## 10.3 기억 소환

| 등급 | 색 | 결과 | 확률 |
|---|---|---|---:|
| 별빛 | 무지개 | 완성 기억 | 3% |
| 황금 | 금 | 기억가루 9 | 5% |
| 은빛 | 은 | 기억가루 4 | 10% |
| 청동 | 청 | 기억가루 2 | 27% |
| 일반 | 백 | 기억가루 1 | 55% |

비완성 결과의 기억가루 기대값은 정확히 1.94로, v1.0의 `97%×2`와 같다. 완성 기억이 중복이면 기억가루 60개. 기억가루 200개로 현재 열려 있는 추첨 대상 기억 1개를 지정 획득한다. 관계/특수/무료 시즌 최종 보상 그림은 이 추첨/교환 풀에 들어가지 않는다.

첫 시즌 완성 기억 그룹은 현재 시즌 2개(그룹 가중치 40%)와 상시 5개(60%). 각 그룹 내부 균등이다. 전체 3%를 다시 정규화하지 않는다. 예: 시즌 각 0.6%, 상시 각 0.36%, 비완성 97%로 합계 100%다.

총 60회마다 추가 기억 선택권 1장. 무작위 성공은 카운터를 초기화하지 않는다. 선택권/가루/티켓/누적 진행은 시즌 종료에도 유지된다. 대상 풀이 비어 있으면 버튼을 비활성화하고 어떤 것도 소모하지 않는다. 복각 또는 아카이브에서 그룹이 하나뿐이면 그 그룹이 완성 확률 3% 전체를 받는다.

첫 획득으로 그림 전체와 장면을 얻는다. 중복을 모아야 그림의 일부를 보게 만드는 방식은 없다. 같은 이미지를 색상 필터만 바꿔 새 기억으로 계산하지 않는다. 수집 보유 효과로 전투력이 증가하지 않는다.

플레이어는 미보유·교환 가능 기억 하나를 `지정 기억`으로 고정할 수 있다. 수집 화면에 흐린 미리보기와 `기억가루/200`을 표시하고 40가루마다 다섯 단계의 베일 하나를 제거한다. 이는 교환 진척 시각화일 뿐 그림 조각을 별도 상품으로 만들지 않는다. 지정 변경은 무료이며 가루를 소모하지 않는다.

## 10.4 결과 공개 연출과 천장 표시

모든 결과 구슬/카드는 백색에서 시작해 커밋된 최종 등급까지만 `백→청→은→금→무지개`로 상승한다. 단계당 기본 0.20~0.25초, 무지개는 0.35초 정적 뒤 등장 대사 한 줄. 저연출 모드에서는 중간 단계를 생략하고 최종 색만 보여준다. 스킵은 즉시 가능하다.

10연 결과는 한 거래로 모두 확정한 뒤 등급 오름차순으로 공개하고 최고 등급을 마지막에 둔다. 같은 등급 안에서는 원래 추첨 순서를 유지한다. 마지막 결과는 탭하면 즉시 열리고, 입력하지 않아도 0.8초 뒤 자동 공개된다. 탭을 강제해 5분 루프를 지연시키지 않는다. 별빛이 없으면 금/은을 무지개처럼 속여 연출하지 않는다.

30회/60회 진행은 링 게이지와 정확한 남은 횟수로 표시한다. 동료 25회, 기억 50회부터 게이지를 강조한다. 선택권이 발생한 뒤 사용하지 않아도 다음 누적 횟수는 계속 계산된다. 소환 결과 화면은 천장·토큰/가루·지정 대상 진척을 한 번에 갱신한다.

접속 중 임의의 10분에만 열리는 `행운의 시각`은 구현하지 않는다. 사용자의 생활 시간보다 게임을 켜둔 시간을 우대하고, 놓쳤을 때 손실감을 만들어 하루 5분 목표와 충돌하기 때문이다.

## 10.5 28일 지급 산식

```text
일일 3×28 = 84
개인 주간 9×4 = 36
시즌 시작 3 = 3
총계 = 123회
하루 결석 + 해당 주 6일 완료 = 120회
```

따라서 하루를 결석해도 기본 활동만으로 60회 선택 보상 두 번에 도달한다. 여기에는 선택형 모험, 관문 추가권, 복각 보너스, 임의 우편 선물이 포함되지 않는다. 2일 이상 결석 때 동일한 보장을 약속하지 않는다. 3% 무작위 확률만 있을 때 60회 무획득 확률은 `0.97^60≈16.08%`; 이 불운과 별개로 누적 선택권은 두 번 지급된다.

티켓을 쓰지 않고 쌓아도 시즌 일일/주간 보상을 받는다. 선택권은 획득 시점이 아니라 사용 시점에 열려 있는 대상 풀을 참조하되, 사용 전 실제 선택 가능 목록을 보여준다.

# 11. 관계·대사·특수 기억

## 11.1 관계점

모든 영웅은 방치 시간당 0.25점, 하루 최대 6점을 얻는다. 일일 교류는 한 명을 선택해 +12점. 교류 충전은 하루 1/보유 2. 선물은 하루 3개이며 각각 선택한 영웅 +4점, 미사용 선물은 최대 6개까지 보관한다. 선물은 다른 재화로 판매하거나 소환권으로 교환하지 않는다.

주역의 장면 문턱은 `[0,20,50,90,140,210,300,420,570,750,960,1200]`. 각 문턱에서 고유 장면 하나. 210점 장면에서 관계 기억 그림을 준다. 최애 집중 시 첫 큰 그림은 약 1주 목표, 다른 영웅도 기본 원정으로 지속 진전한다. 실제 일수는 수령/교류/선물 선택에 따라 달라지므로 확정 날짜로 표시하지 않는다.

호감도 하락, 결석 원망, 유료 정답 선물, 오답 대사로 관계 초기화는 없다. 대화 선택지는 문장/주제만 다르고 동일 관계점을 준다. 관계는 연애만을 뜻하지 않으며 인물 설정에 따라 신뢰·우정·친밀감을 표현한다. 성별/나이/관계가 확인되지 않은 인물을 임의로 연애 대상으로 지정하지 않는다.

## 11.2 장면 구조와 읽기

각 장면은 `id, actors, requirements, priority, lines, choices, readFlag, rewardId, artId`를 갖는다. 주역 장면은 6~10개 대사 버블, 동료 기록은 4~6개, 특별/시즌 장면은 8~12개를 기준으로 쓴다. 대사마다 화자 ID와 표정 ID를 지정한다. 임의 문자열 HTML을 삽입하지 않는다.

한 번 읽은 장면은 앨범에서 무제한 다시 볼 수 있다. 읽기 속도/스킵이 관계점이나 보상을 바꾸지 않는다. 스킵 버튼은 보상을 지급하면서 `skipped=true`와 `read=true`를 기록해 나중에 찾아 읽을 수 있게 한다. 보상 지급과 readFlag는 한 거래다.

초기 60개 주역 장면은 같은 대화에서 이름만 바꿔 생성하면 불합격이다. 설정 확인 전까지는 원정 준비·돌아온 뒤의 이야기·장비 손질·동료와의 일상 같은 비모순적 현재 장면으로 쓰고, 출생/과거 비극/혼인/혈연을 새로 만들지 않는다.

## 11.3 실제 플레이에 반응하는 홈 대사

우선순위는 `미열람 주요 이야기 → 방금 달성한 관문/숙련 → 새 동료/기억 → 시즌 맥락 → 시간대 일상`이다. 최근 14개의 홈 대사 ID를 기억해 가능한 한 반복을 피한다. 날짜가 바뀌었다는 이유만으로 문장 하나를 매일 새 콘텐츠로 계산하지 않는다.

영웅별 최소 18개의 짧은 홈 반응을 준비한다: 성장 4, 원정 4, 수집 3, 관계 3, 시간대 4. 실제로 발생하지 않은 사건을 회상하지 않는다. 외부 생성형 API 없이 로컬 조건 선택으로 동작한다. 핵심 대사 집합은 인물별 문체/호칭/금지 설정 검토를 통과해야 한다.

## 11.4 동료 개인기록

동료 최초 획득에 첫 기록, 해당 동료를 배속한 원정에서 최초 관문 승리 5회에 두 번째 기록을 연다. 반복 파밍 5회가 아니라 서로 다른 관문 5개다. 시간의마술사만 관문 10개에서 세 번째 기록을 추가한다. 도감에 진척을 보여주고 전투 중이 아니어도 열람 가능하다.

프로필의 이야기 때문에 특정 동료에게 영구 성장 스탯을 몰아줄 필요는 없다. 기록 해금은 영입을 가치 있게 만드는 수평 보상이며 필수 유물이나 주역 기술을 잠그지 않는다.

## 11.5 트라우마

해금: 시간의마술사 보유 + 그 동료 기록 3개 열람 + 영웅 중 하나 원정 60단계. 특수 장면 3개는 조건 달성 후 순서대로 읽을 수 있다. 마지막 장면이 기억 `trauma`를 지급한다.

동일 인물의 외형/연출 선택으로만 구현한다. time_magician의 랭크/배속/기록을 공유하고 지원 수치도 동일하다. 별도 소환 대상·별도 인원 수로 세지 않는다. 원작의 상세 사연이 확인되지 않으면 단정적인 비극 서사를 새로 쓰지 않는다.

## 11.6 루나&자스민

해금: 루나와 자스민 관계점 각각 210 이상 + 두 영웅의 최고 원정 단계 합계 120 이상. 공동 장면 3편을 순서대로 연 뒤 `luna_jasmine` 기억을 얻는다. 새 주역을 만들거나 두 영웅을 소비하지 않는다.

홈 공동 표시, 도감 공동 장면, 아스테아 결과 화면의 합동 연출에서 사용한다. 전투 성능 보너스나 별도의 소환 확률은 없다. 원작에서의 두 사람 관계/해당 모습의 맥락을 보존한다.

# 12. 28일 시즌과 장기 운영

## 12.1 날짜 체계

v1은 UTC+9, 오전 05:00 고정 초기화다. 기기 설정 시간대에 따라 바뀌지 않는다. 프로필을 만들 때의 게임 날짜를 `epochDay`로 저장한다.

```text
gameDay = floor((utcMs + 9시간 - 5시간) / 24시간)
relativeDay = max(0, gameDay - epochDay)
weekIndex = floor(relativeDay/7)
seasonOccurrence = floor(relativeDay/28)
seasonDay = relativeDay%28 + 1
```

생성 당일은 첫 번째 자격 날짜이며 그날에도 일일 조건을 완료할 수 있다. 시작일이 오전 5시 직전이면 첫 날짜가 짧다는 사실을 안내하고, 최초 프로필에 한해 첫 qualifiedDay를 튜토리얼 완료로 인정한다. 그 보상은 당일 일일 보상과 중복하지 않는다.

초기 `s01`을 28일 운영한다. 새 콘텐츠가 아직 설치되지 않았다면 다음 주기를 자동으로 같은 '신규 시즌'으로 위장하지 않고 `아카이브 기간`으로 표시한다. 일일/주간 성장과 누적 선택권은 계속 유지한다.

후속 업데이트의 새 시즌은 다음 28일 경계에서 시작한다. 업데이트 도중 현재 시즌을 중단하거나 기한을 당기지 않는다. 모든 일정과 시작/종료일은 UI에서 실제 날짜로도 표시한다.

## 12.2 첫 시즌: 별빛 아래의 휴식

중심은 루미, 관련 동료는 눈토끼·은하고래다. 새로운 거대한 세계관 사건을 확정하는 대신 원정 후 거점에서의 현재 일상을 다룬다.

추첨 기억 2개는 `루미 · 별빛 아래의 휴식`, `눈토끼 · 돌아오는 길`. 무료 트랙 마지막 기억은 `루미와 은하고래 · 저녁의 기록`. 세 장 모두 서로 다른 완성 그림이어야 한다. 신규 장면/복장은 원본 정체성을 기준으로 제작한다.

시즌 이야기 4장(각 2장면)은 qualifiedDay 1/7/14/21에 열린다. 달력 날짜가 지난 것만으로 읽지 않은 이전 장면을 건너뛰지 않는다. 종료 후 미열람 이야기와 이미 획득한 그림은 아카이브에 남는다. 이야기를 못 읽었어도 수치 보상이 사라지지 않는다.

## 12.3 시즌 트랙

qualifiedDay 1개당 시즌점수 10. 총 240점, 24일 완료로 최종 그림. 초과 접속/무한 전투로 점수를 더 벌 수 없다. 28일 중 하루 결석해도 27일이 남으므로 최종 그림 획득 가능하다.

## 12.4 복각과 아카이브

`s01`은 최초 등장 이후 3개의 28일 주기가 지난 다음부터 복각 대상으로 삼는다. 후속 시즌이 없더라도 그 전에는 상시 풀만, 복각 시에는 s01 두 추첨 기억이 다시 열린다. 복각 일정은 설치된 데이터로 미리 보여준다.

`contentId`와 `occurrenceId`를 구분한다. 그림 최초 지급 여부는 contentId, 그 회차의 일일/트랙 보상은 occurrenceId로 관리한다. 같은 그림을 복각에서 다시 얻으면 기억가루로 바꾸고 '신규 일러스트'로 표시하지 않는다. 무료 마지막 그림 중복도 기억가루 60개로 변환한다.

획득 그림/동료/관계/장비/레벨은 시즌이 바뀌어도 초기화하지 않는다. 완료한 보상은 자동 정산 후 다음 회차를 연다. 실행하지 않은 날짜의 접속 보상은 소급하지 않는다.

## 12.5 지속 업데이트 단위

새 시즌 하나의 표준 단위는 3개 완성 일러스트, 8개 장면, 모험 사건 2개, 기존 보스의 선택형 도전 변형 1개다. 새 인물/새 화폐/새 강화 탭을 매 시즌 추가하지 않는다.

수치 증가만으로 수집 욕구를 영원히 유지할 수 있다고 전제하지 않는다. 실제 새로운 그림/장면을 공급하지 않으면 아카이브 재도전 기간이라는 사실을 드러낸다. 제작자가 새 시즌을 추가할 때 엔진 파일을 고치지 않고 데이터와 에셋 묶음으로 등록할 수 있어야 한다.


## 12.6 연속성 표시와 복귀 보정

주간 2/4/6 qualifiedDay 보상은 별자리 보드 형태로 보여주고, 달성한 별이 일주일 동안 이어지게 한다. 별도 연속 출석 스트릭은 만들지 않는다. 하루 결석으로 1일 차로 돌아가거나, 광고/재화로 스트릭을 보호하게 하지 않는다. 이미 존재하는 주간 누적 구조가 7일의 커밋먼트를 담당한다.

마지막 처리 gameDay 이후 3개 이상 게임 날짜가 지났다면, 28일 occurrence당 한 번만 복귀 보정을 제공한다. 기본 24시간 방치 수령과 별도로 **현재 기본 XP/골드/광석 12시간분**을 한 번 지급하고, 이후 72시간 동안 XP/골드 방치 수율만 +25%로 계산한다. 티켓·연구권·훈련점·관계점·qualifiedDay·시즌점수는 소급하지 않는다. 3일 결석자가 계속 접속한 플레이어보다 더 많은 보상을 받지 않는지 ECONOMY_REPORT에서 확인한다.

복귀 화면은 결석을 탓하거나 캐릭터가 원망하는 문장을 쓰지 않는다. `돌아온 것을 환영합니다 / 다음 완성 가능한 성장`을 먼저 보여준다. 보정은 공개된 규칙이며 시계 역행으로 반복 수령할 수 없게 occurrence 장부에 기록한다.

## 13.1 구조와 보상

## 13.3 사건 12종과 정보 공개

사건은 길 잃은 안내판, 휴식처, 장비 점검, 오래된 기록, 갈림길, 작은 상자, 잠든 정령, 빛바랜 무대, 비 내리는 회랑, 동료의 제안, 보스의 흔적, 숨겨진 전망대로 구성한다. 이는 새 지명/정사 인물을 추가하는 것이 아니라 기능용 사건 제목이다.

각 사건은 2개 선택지와 정확한 결과 조건을 가진다. v1 기능 결과는 `HP 회복/HP 대가/임시 유물 선택/다음 전투 스탯·MP·보호막 변경/최종 보스 수치 변경/모험 도감 기록`만 사용한다. 정확한 두 선택지의 효과는 §13.4를 따른다. 확률 사건이면 선택 전에 수치를 표시한다. UI가 좋은 결과를 암시했는데 코드가 다른 보상을 지급하지 않게 데이터 단일화한다.

희귀 '숨겨진 전망대'는 보상 slot당 12%로 사건 노드 중 하나에 배치할 수 있다. 등장 여부와 위치는 시작 시드에 고정된다. 발견은 모험 도감의 영구 기록 하나이며 전투력 보너스는 없다. 모든 경로에 최소 한 개 안전 회복 수단을 둔다. 상세 사건 대사는 제작자가 인물 검토 후 작성하며 사건 ID만 넣고 완료 처리하지 않는다.


## 13.4 사건별 확정 선택 결과

다음 전투 보너스는 다음 전투 한 번 후 소멸한다. 최종 보스 보너스는 마지막 노드까지 유지한다. 같은 버킷의 사건 보너스는 합산하며 피해 증가/적 감소는 각각 ±30% 한도다. 현재 HP 소비는 남은 HP가 1보다 낮아지면 1로 멈춘다. 모험의 HP는 노드 사이에 이어지며 MP는 전투마다 기본값으로 리셋하되 해당 사건 보너스를 더한다.

| 사건 | 선택 A | 선택 B |
|---|---|---|
| 길 잃은 안내판 | 안전한 길: 다음 일반 전투 적 HP -15% | 지름길: 현재 HP 10% 소비, 다음 일반 전투 적 ATK -25% |
| 휴식처 | 잠깐 쉰다: 최대 HP 25% 회복 | 마력을 정돈한다: 최대 HP 10% 회복 + 다음 전투 시작 MP +20 |
| 장비 점검 | 칼날을 다듬는다: 다음 전투 ATK +15% | 마력을 다듬는다: 다음 전투 MATK +15% |
| 오래된 기록 | 천천히 읽는다: 모험 기록 1개 열람, 최대 HP 10% 회복 | 실전에 적용한다: 다음 전투 MP 회복 +1/초 |
| 갈림길 | 완만한 길: 최대 HP 15% 회복 | 험한 길: 현재 HP 15% 소비, 추가 임시 유물 선택 1회 |
| 작은 상자 | 상자를 연다: 추가 임시 유물 후보 2개 중 1개 선택 | 내용을 양보한다: 최대 HP 20% 회복 |
| 잠든 정령 | 조용히 지나간다: 최대 HP 15% 회복 | 기운을 나눈다: 현재 HP 10% 소비, 다음 전투 시작 보호막 최대 HP 25% |
| 빛바랜 무대 | 기록을 남긴다: 모험 기록 1개 열람, 다음 전투 시작 MP +10 | 몸을 풀어 본다: 다음 전투 기본 공격 피해 +20% |
| 비 내리는 회랑 | 비를 피한다: 최대 HP 20% 회복 | 빗속을 지난다: 현재 HP 10% 소비, 다음 전투 직접 피해 +15% |
| 동료의 제안 | 첫 동료의 제안: 다음 전투 지원 슬롯1 피해 +30%(비공격이면 시작 시 HP 15% 보호막) | 둘째 동료의 제안: 다음 전투 지원 슬롯2 피해 +30%(없거나 비공격이면 시작 MP +15) |
| 보스의 흔적 | 방어를 준비한다: 최종 보스 ATK -15% | 약점을 조사한다: 최종 보스 HP -10% |
| 숨겨진 전망대 | 잠시 머문다: 고유 도감 기록 지급, 최대 HP 30% 회복 | 다음 길을 바라본다: 같은 고유 도감 기록 지급, 추가 임시 유물 선택 1회 |

희귀 전망대를 제외한 사건은 동일 run에서 중복 없이 배치한다. 유물 후보가 부족하면 남은 후보만 제시하고 없으면 최대 HP 20% 회복으로 전환한다. 모든 선택이 의미 있는 결과를 가지며 프리미엄 재화는 소비하지 않는다. 사건 기록은 첫 열람만 도감에 추가하고 반복 열람으로 배지를 무한 생성하지 않는다.

# 14. 성장 체감·정직한 근접·다음 목표

## 14.1 목표 3개 제한

홈에는 최대 세 개만 표시한다: `지금 완성할 성장 1개 / 중기 공략 목표 1개 / 원하는 수집 1개`. 사용자 고정 목표가 있으면 그것을 우선한다. 목표 선택이 자원 수입을 추가로 곱하지 않는다.

후보 우선순위: 지금 가능한 숙련 운용 해금 → 새 장비 효과 문턱 → 신규 유물 제작 → 의미 있는 레벨 묶음 → 관계 장면 → 지정 소환권 문턱. 이미 완성한 목표를 루프해서 새 목표처럼 재제시하지 않는다.

'오늘 돌파 가능'이라는 확정 문구는 실제 현재 편성 시뮬레이션이 이긴 경우에만 사용한다. 아직 시뮬레이션하지 않았다면 '성장 후 재도전 추천'이라고 표시한다. 계산한 시점 이후 편성이 바뀌면 가능 표시를 무효화한다.

## 14.2 의미 있는 성장의 측정

기록 가능한 성취는 새 관문/새 보스 티어, 기본 스킬 순환에서 사용 횟수 증가, 숙련 스타일 해금, 장비 효과 문턱, 신규 동료의 즉시 사용, 관계 장면/그림 획득이다. 매일 ATK +0.1%를 받았다는 것만으로 성취 목표를 충족했다고 평가하지 않는다.

전후 비교는 동일 보스·동일 데이터 버전의 실제 전투 결과끼리 한다. 표시 예: 처치 시간 45초→38초, 남은 HP 5%→22%, 궁극 사용 1→2회. 비교 상대가 없거나 조건이 달라졌다면 수치 비교를 숨기고 새 기록만 표시한다.

오랫동안 패배한 보스를 몰래 약하게 만들거나 RNG를 조작해서 성취를 연출하지 않는다. 따라잡기 할인/누적 보상/안내는 공개된 규칙으로 제공한다.

## 14.3 정직한 근접 실패와 전투 분석

보스/관문의 **첫 도전 전에는 정확한 승패를 자동 표시하지 않는다.** 결과를 미리 확정해 보여주면 전투의 긴장과 관전 이유가 사라지기 때문이다. 첫 패배 뒤에는 실제 전투 결과의 보스 잔여 HP, 생존 시간, 마지막 큰 기술까지 남은 시간을 크게 보여준다.

패배 화면의 `돌파 분석` 버튼을 누르면 현재 deterministic engine으로 커밋 없는 headless simulation을 수행한다. 다음 후보 중 현재 실제로 적용 가능한 5~8개를 각각 단독으로 시험한다: 레벨 묶음, 무기/방어구/장신구 +1 또는 효과 문턱, 해금된 스타일 전환, 보유 동료 교체, 보유 유물 교체, 공격 보류 설정. 후보 결과는 `현재 재화로 가능 / 다음 비용 / 예상 잔여 HP 또는 승리`로 표시한다.

서로 다른 재화를 임의 환율로 환산해 거짓으로 '가장 싼 방법'이라고 부르지 않는다. 대신 `현재 자원으로 즉시 가능한 방법`과 `강화 단계가 가장 적은 방법`을 최대 하나씩 추천한다. 단일 후보로 승리하지 못하면 가장 큰 개선을 보여주고 승리를 보장하지 않는다. 결과 캐시는 `encounter+contentVersion+loadoutHash+candidate`로 관리하고 편성/수치 변경 시 폐기한다.

같은 데이터·편성·시드에서 분석 예측과 실제 전투는 일치해야 한다. 분석은 Web Worker 또는 작은 묶음 yield로 UI를 막지 않는다. 외부 +15% 재도전 가호나 광고 버프로 패배를 우회하지 않는다. 플레이어가 실제 성장·편성 변경을 한 뒤 재도전하게 한다.

영웅 HP 10% 이하 또는 제한시간 3초 이하에 첫 클리어하면 `간발의 승리`를 표시하고 해당 최초 클리어에 한해 관계점 +2를 준다. 반복 파밍으로 관계점을 생성하지 않는다.

## 14.4 다음 접속 이유

홈 하단에는 알림이 아니라 한 줄의 다음 변화만 표시한다. 우선순위는 `귀환 편지까지 남은 시간 → 추천 보스 교대 → 지정 기억 교환까지 남은 가루 → 다음 숙련/장비 문턱`이다. 앱을 백그라운드로 보낸 뒤 팝업을 띄우지 않고, 다음 접속 시 홈에서 자연스럽게 보여준다.

# 15. 화면·입력·시각 사양

## 15.1 화면 정보 구조

하단 탭은 `홈 / 원정 / 영웅 / 교류 / 수집` 5개. 소환·도감·기억·시즌은 수집 안, 보스·모험은 원정 안에 둔다. 독립 상점 탭을 처음부터 늘리지 않는다.

모바일 기준 390×844. 상단 자원줄 약 56px, 하단 탭 64px+safe-area, 중앙 스크롤 영역. 홈의 주역 일러스트는 첫 화면의 가장 큰 요소다. 기본 레이아웃은 큰 세로 그림, 작은 원정 상태, 핵심 행동 버튼 하나, 목표 3개 이하. 지표 카드 12개가 늘어선 대시보드형 홈은 금지한다.

PC 1280px 이상은 중앙 주역/우측 목표/하단 원정 기록을 배치하되 모바일에 없는 필수 기능을 PC에만 추가하지 않는다. 360px 폭에서도 수치·버튼이 잘리지 않아야 한다.

전투 로그는 접어서 제공한다. 로그만 흐르고 인물 행동은 안 보이는 화면을 최종 전투로 취급하지 않는다. 적 체력 감소는 타격 연출과 같은 이벤트에서 발생한다.

## 15.3 시각 방향

주역과 기억은 인물 중심의 서브컬처 일러스트, UI는 짙은 남색 바탕과 밝은 문서/패널, 장식은 절제된 별·편지 모티프로 통일한다. 버튼/프레임/아이콘은 한 세트로 만든다. 모든 패널에 글로우·그라데이션·둥근 카드를 중첩하지 않는다. 효과보다 인물의 얼굴과 다음 행동을 먼저 읽을 수 있어야 한다.

전투는 영웅의 일러스트/스탠딩을 주연으로, 동료는 지원 초상화로 표현한다. 원작의 일반 등신 그림과 제각각인 SD를 같은 전열에 섞지 않는다. SD를 선택할 경우 다섯 영웅 전체에 통일된 신규 세트를 만들고 비교 시트를 남긴다. v1 기본은 기존 인물 일러스트 중심이므로 SD 필수 제작은 아니다.

공격 유형은 색+문자+아이콘을 함께 쓴다: 물리/마법/혼합/보조. 혼합은 각 계수를 표시한다. 빨간색과 초록색만으로 불리/유리를 구분하지 않는다. 본문 기본 16px, 보조 13px 이상, 터치 영역 최소 44×44px를 제작 기준으로 삼는다. 키보드 focus, Escape 닫기, 스크린리더용 버튼 이름도 제공한다.

## 15.4 연출과 소리

기본 공격은 작고 짧게, 궁극기는 0.4~0.8초의 짧은 강조와 고유 이펙트. 화면 전체를 매번 하얗게 덮지 않는다. 피해 숫자는 동시에 24개 이하, 저연출 모드에서 합산한다.

| ID | 렌더 전용 연출 |
|---|---|
| FX-01 | 피해 숫자. 치명타는 크기/문자, 속성 우위는 색+속성 아이콘으로 구분 |
| FX-02 | 치명타 2px, 궁극기 4px 이하의 0.15초 화면 흔들림. 설정에서 끔 |
| FX-03 | 재화 획득 아이콘이 상단 지갑으로 이동하고 숫자가 실제 확정값까지 롤링 |
| FX-04 | 성장 뒤 `ATK +4.2%`, `궁극 예상 1→2회`처럼 확인 가능한 변화 티커 1.2초 |
| FX-05 | 지원 기기에서 별빛 결과에 `navigator.vibrate(30)` 선택 사용. 기본 끔/설정 가능 |
| FX-06 | 백·청·은·금·무지개 5단 효과음의 음정을 상승 연출과 동기화 |

FX는 엔진 상태·결과·RNG에 영향을 주지 않는다. reduced-motion에서는 흔들림·아이콘 비행·단계 승급을 줄이고 최종 상태를 즉시 읽을 수 있게 한다. 소환 스킵은 즉시 가능하고 10연 마지막 탭은 0.8초 자동 공개 대체가 있다.

오디오는 첫 사용자 입력 후 시작하고 음소거 상태를 저장한다. 선택한 영웅의 대표곡/기억 장면 곡을 감상할 수 있는 소형 플레이어를 수집에 둔다. 오디오 파일이 없으면 버튼을 비활성화하고 '제작 중'을 표시하며 재생됐다고 처리하지 않는다. 음악이 없어도 게임 초기화가 막히지 않는다.

# 16. 에셋 제작·재사용 계약

## 16.1 출처 목록부터 작성

`asset_manifest.template.json`에는 29인 초상화+보스 10+특수 변주 2의 목적지 ID가 있다. `sourcePath=null`은 미확인이라는 뜻이다. 현재 확인하지 않은 파일명이 존재한다고 가정하거나, 이름을 비슷하게 맞춰 잘못된 그림을 불러오지 않는다.

제작 시작 때 실제 저장소에서 31항목/10보스의 원본을 대조하고 manifest에 `sourcePath, sourceSha256, canonicalPersonId, crop, anchor, reviewed`를 채운다. 카드 데이터에 이미지가 외부 URI로 지정되어 있으면 런타임 외부 의존성으로 두지 말고 사용 가능 여부를 확인한 뒤 로컬 자산화한다. 외부 권리 관계가 불명확한 새 자산은 대체하지 않는다.

사용 가능한 그림이 없으면 새 제작 대상으로 적고, 임시 silhouette는 개발 화면에서만 허용한다. 완성되지 않은 보상 그림을 가챠에서 지급하지 않는다. '아이디는 존재하므로 수집 기능 완료'는 불합격이다.

## 16.2 신규 그림의 최소 묶음

상시 기억 5장(주역 각 1), 관계 기억 5장(각 210점), 시즌 그림 3장 = 새 장면 13장. 특수 기억 2장은 기존 변주 자산을 확인해 재사용하거나 품질이 부족하면 새로 제작한다. 홈 기본 초상화의 색만 바꾼 것은 새 장면으로 세지 않는다.

기억은 세로 단독 그림 1024×1536, 공동 장면 1536×1024를 작업 원본의 기준으로 한다. 최종 WebP는 표시 크기와 실제 품질을 보며 축소한다. 전체 그림을 감상할 수 있도록 확대/축소와 원본 비율 보기를 제공한다. 모바일 카드에 맞추려다 얼굴이나 동반 인물을 잘라 버리지 않는다.

## 16.3 일관성 체크

인물별 기준 이미지 한 장을 고정하고 머리/몸 비율, 얼굴, 머리색, 성별 표현, 의상 문양, 악세사리 위치를 대조한다. 포즈마다 바운딩박스를 꽉 채워 몸 크기를 제각각 바꾸지 않는다. 무기/귀/날개가 크다고 신체 자체를 줄이지 않는다. 기존 아트 지침은 포즈 간 공통 발 기준선과 머리 비율 확인을 강조한다. [R3]

동일 인물의 기본/새 기억을 2~3장씩 비교한 시트, 주역 5명의 홈 화면 실제 크기 비교, 밝은/어두운 배경 비교를 남긴다. 자동 알파 검사만으로 그림의 통일감을 통과 처리하지 않는다.

## 16.4 빌드와 파일 실패

크롭/알파 정리/크기 조절/WebP 변환은 sharp 기반 빌드 단계에서 한다. 런타임 픽셀 키 제거·배경 제거·`getImageData` 대형 반복을 넣지 않는다. 소스 해시와 전처리 설정 해시가 같으면 이전 변환 결과를 재사용한다.

런타임 이미지 하나가 실패해도 게임 전체 초기화가 멈추면 안 된다. 대체 프레임+이름을 표시하고 오류를 기록한다. 다만 최종 배포 검증에서 필수 그림 누락은 출시 실패다. 런타임 내결함성과 제작 완료 기준은 다른 문제다.

## 17.2 엔진/렌더 분리

코어 엔진은 DOM 없이 테스트 가능해야 한다. `reduce(state, command, context) -> nextState + effects` 형태의 결정 로직을 사용하고, 화면은 저장된 상태와 이벤트를 렌더한다. 애니메이션 종료 콜백에서 재화/단계/소환 결과를 확정하지 않는다. 빠른 전투의 시뮬레이션 tick은 현실 방치 시간으로 환산하지 않는다. 현실 보상은 clock 시스템만 정산한다.

전투 엔진을 원정용·보스용·빠른 계산·패배 분석용으로 복제하지 않는다. 하나의 engine이 같은 시드와 입력으로 같은 결과를 낸다. 동료 소환/기억 소환/전투/모험/reward RNG 상태는 독립적으로 직렬화한다.

필수 함수 계약:

```text
settleAccrual(state, logicalNowMs) -> nextState
claimAccrual(state, commandId) -> nextState, claimSummary
purchaseLevels(state, heroId, countOrBudget) -> nextState, receipt
resolveSummon(state, poolId, count, commandId) -> nextState, results
resolveRewardEvent(state, sourceId, context, commandId) -> nextState, committedResult
simulateBattle(loadoutSnapshot, encounter, seed) -> battleResult
analyzeDefeat(loadoutSnapshot, encounter, candidates) -> analysisResult
applyBattleResult(state, battleResult, rewardId) -> nextState
resolveCalendar(state, logicalNowMs) -> nextState, earnedRewards
validateAndMigrate(importedBytes, installedContent) -> validState or typedError
```

전투 결과는 `encounterId, difficulty, contentVersion, loadoutHash, seed, winner, elapsedTicks, heroHP, damageBySource, skillCounts, replayDigest`를 포함한다. 최소 UI 로그와 상세 디버그 로그를 구분한다.

## 17.3 용량/성능 목표

단일 HTML 목표 35MiB 이하, 50MiB를 넘으면 사유와 축소안을 보고한다. 파일명 문자열에만 이미지를 넣고 파일은 빠뜨린 배포물은 허용하지 않는다. 중복 이미지 바이트는 한 번만 포함하고 참조한다.

현재 홈/전투/앞뒤 앨범만 디코드하고 모든 대형 그림을 시작 시 일괄 디코드하지 않는다. HUD는 상태 변화 또는 최대 10Hz, 전투 렌더는 기본 60fps/저전력 30fps. DPR은 2까지, 파티클 120개, 피해 팝업 24개를 초기 상한으로 한다. 전체 한 번의 장면 진입에 이미지 디코드가 끝나지 않아도 이름/버튼을 먼저 사용할 수 있게 한다.

대표 데스크톱 브라우저에서 입력 반응 100ms 이내를 목표로 하되 실제 측정 환경을 기록한다. 패배 분석 8후보×1,200tick은 주 스레드를 100ms 이상 연속 점유하지 않도록 Worker 또는 yield 묶음으로 처리하고, 대표 PC에서 500ms 내 첫 분석 요약을 목표로 한다. 물리 Android/iOS를 실행하지 않았다면 그 플랫폼의 성능을 인증했다고 쓰지 않는다.

브라우저는 백그라운드에서 requestAnimationFrame을 중단하거나 타이머를 지연시킬 수 있다. 따라서 수익을 frame/timer 횟수에 비례시키면 안 된다. [W2] 숨김→복귀 때 경과 시간을 한 번 정산하고 연출 루프만 재개한다.

# 18. 24시간 방치 정산과 날짜 경계

## 18.1 누적 상한은 '접속 간격'이 아니라 미수령 시간

보상 장부는 `accrualCursorMs`, `unclaimedDurationMs`, `pendingAmounts`, `rateSnapshot`을 가진다. 단순히 재접속 때만 min(경과,24h)를 계산하는 구조는 금지한다. 앱을 켜두어도 미수령 24시간이면 더 쌓이지 않아야 한다.

```text
elapsed = max(0, logicalNowMs - accrualCursorMs)
accepted = min(elapsed, 24h - unclaimedDurationMs)
pending += rateSnapshot × accepted
unclaimedDurationMs += accepted
accrualCursorMs = max(accrualCursorMs, logicalNowMs)
```

상한을 넘겨 버린 시간은 cursor를 앞으로 옮겨 폐기한다. 수령 후 그 시간이 다시 계산되면 안 된다. 다섯 원정은 같은 accepted 시간을 쓰되 각각의 rateSnapshot을 적용한다.

단계/보상 계수가 바뀌기 직전에 기존 rateSnapshot으로 먼저 정산한다. 이후 새 rate를 기록한다. 새로 높은 단계에 도달했다고 지난 24시간 전체가 새 수익률로 재평가되지 않는다.

## 18.2 정확한 소수 누적

정수 미만 관계점/시간 보상을 매번 floor해서 버리지 않는다. 공통 분모 `Q=360,000,000`의 정수 누적 단위를 사용하면 현재 수식을 정확히 표현할 수 있다.

| 자원 | 영웅별 1ms 누적 Q 단위 |
|---|---:|
| XP | `120×(25+s)` |
| 골드 | `360×(25+s)` |
| 광석 | 500 |
| 훈련점 | 100 |
| 관계점 | 25 |

수령할 때 `floor(pendingQ/Q)`를 지갑/영웅에게 더하고 `pendingQ%Q`는 다음 정산의 소수 잔여로 보존한다. 지갑 전체를 Q배로 저장하지 않는다. 24시간×최대 단계 범위의 pendingQ는 JS 안전 정수 범위 안에서 검증한다.

모든 단계가 0일 때 12시간은 공용 XP 1,800/골드 5,400/광석 300, 영웅별 훈련 12/관계 3이다. 24시간은 그 두 배. 12시간 두 번 수령과 24시간 한 번 수령이 같은 결과여야 한다.

## 18.3 전투 도중 종료

원정의 관전 전투가 앱 종료로 멈추면 재개 또는 처음부터 같은 시드로 재시뮬레이션한다. 승리가 확정되지 않았다면 최초 보상을 주지 않는다. 이미 확정한 승리는 연출을 다시 봐도 추가 지급하지 않는다. 선택형 모험은 노드 경계마다 저장하며 현재 노드만 재시도한다.

배속은 방치 수익에 영향을 주지 않는다. 한 개 탭에서 일괄 돌파 중 다른 탭이 레벨을 올리는 상황에서는 저장 revision 검사를 통해 승리 결과를 독립적으로 검증하고, 이전 스냅샷의 결과라는 사실을 보존한다. 가급적 한 탭만 쓰기 권한을 가진다.

## 18.4 시계 역행/급변

`logicalNow=max(lastTrustedLogicalMs, wallNow+clockOffsetMs)`로 역행하는 음수 경과를 차단하고 역행 경고를 표시한다. 일일 보상/시즌의 처리된 gameDay는 되돌리지 않는다. 시계 변경으로 같은 날짜 보상을 다시 지급하지 않는다.

정상 시계로 복구했는데 과도한 미래 기록 때문에 진행이 막히면 '시계 기준 재설정' 복구 기능을 제공한다. 재설정은 기존 logicalNow와 달성한 상대 시즌 날짜를 연속 유지하도록 clockOffset을 다시 계산하며, 그 순간 방치 추가 보상은 0이다. 보정 중에는 '보정된 게임 날짜'를 명확히 표시한다. 장기 손상은 수동 백업 복구도 지원한다.

기기 시각만으로 실제 시간을 증명할 수 없으므로 치팅 방지를 보증하지 않는다. 재화 손실이나 저장 삭제로 사용자를 벌주지 않는다. 거대한 시간 차이는 보상 24시간만 인정하고 경고하되, 접속하지 않은 일일 보상을 소급하지 않는다.


## 18.5 귀환 상자·편지·복귀 보정의 시간 장부

`dailyReturnChest`는 `gameDay, eligibleClaimCommandId, committedTier`를 기록한다. 2시간 적격 여부는 보너스 적용 전의 accepted duration으로 판정한다. 상자가 나무 등급이어도 그날 사용된 것으로 기록한다. 수익률 변경 구간이 섞인 수령은 각 구간의 기본 pending을 합한 뒤 같은 보너스 비율을 적용하되, 티켓·훈련·관계에는 적용하지 않는다.

귀환 편지는 `scheduledFromDay, availableAtLogicalMs, actorId, rewardRateSnapshot, claimed`를 저장한다. 예약 당시 rate snapshot을 써서 나중의 단계 상승으로 편지 보상을 소급 증폭하지 않는다. 하나가 미수령이면 새 편지는 대기열에 쌓지 않고, 기존 편지를 받은 뒤 그날 새 편지를 예약한다.

복귀 보정은 마지막 정상 처리 day와 occurrence 장부로 판정한다. 시계 역행·수동 재설정으로 같은 occurrence에서 다시 생기지 않는다. 72시간 +25%는 별도의 공개 multiplier 구간으로 rate snapshot에 포함하며, 종료 경계에서 먼저 정산한다.

# 19. 저장·거래·복구

## 19.1 지원 등급

우선 저장 backend는 IndexedDB. 시작 때 실제 쓰기/읽기 probe를 수행한다. 실패하면 localStorage를 probe해 단일 탭 호환 모드로, 둘 다 실패하면 명시적인 메모리 모드로 실행한다. 성공한 저장처럼 표시하지 않는다.

`file:` URL의 localStorage 동작은 브라우저별로 정의가 보장되지 않는다. 파일명/경로 변경 후 자동으로 같은 저장이 열린다고 약속하지 않는다. 안정적인 브라우저 origin에서 사용하는 방법과 JSON 내보내기/가져오기를 함께 안내한다. [W1]

localStorage가 객체로 존재해도 쓰기가 가능한 것은 아니므로 실제 probe 실패를 처리한다. [W3] 메모리 모드에서는 화면에 '이번 세션만 유지됨'을 상시 표시하고 백업 버튼을 항상 제공한다. 이 모드의 결과는 영속 저장 완료가 아니다.

## 19.2 원자적 명령

모든 경제 변경은 command queue를 통한다. `commandId, expectedRevision`을 붙여 같은 명령의 중복 처리를 차단한다. IndexedDB readwrite transaction 안에서 현재 state를 읽고 revision 검사, 명령 적용, 보상 장부와 state 저장을 함께 수행한다. transaction 완료 전에 성공 UI나 희귀 결과를 공개하지 않는다. 서로 겹치는 쓰기 transaction의 직렬화는 해당 저장소 범위에서 활용한다. [W4]

transaction 내부에 이미지 로딩, 네트워크, 긴 전투 계산, 사용자 확인을 await하지 않는다. 긴 계산은 snapshot으로 밖에서 하고 commit 시 revision/명령 유효성을 다시 검사한다. 충돌 시 최신 상태에서 재계산하거나 UI에 재시도를 요청하며 중복 지출하지 않는다.

보상 ID 예:

```text
daily:{profileId}:{gameDay}:login
weekly:{profileId}:{weekIndex}:qualified6
season:{profileId}:{occurrenceId}:track240
firstClear:{heroId}:{stageId}
bossFirst:{bossId}:{tier}
memorySelector:{floor(totalMemoryDraws/60)}
companionSelector:{floor(totalCompanionDraws/30)}
```

단순 commandId 캐시만으로 최초 보상을 보호하지 않는다. 오래된 캐시가 삭제되어도 first-clear 기록, 누적 지급 임계점, 일일/주간 장부가 중복을 막아야 한다. transaction의 일반적인 완료가 OS 손상/브라우저 데이터 삭제까지 막는 백업을 대신하지는 않는다. [W4]

## 19.3 다중 탭

IndexedDB 모드에서는 같은 profile object store transaction과 revision 검사를 필수로 사용한다. 가능하면 Web Locks로 주 쓰기 탭을 정하고 나머지는 읽기 전용으로 표시한다. Web Locks의 같은 origin 잠금과 지원 조건은 feature detect한다. [W5]

localStorage fallback은 IndexedDB 수준의 원자적 다중 탭을 보장하지 않는다. BroadcastChannel/storage event로 다른 탭을 감지하면 쓰기를 잠그고 '한 탭에서 계속'을 안내한다. 감지 경쟁까지 완벽히 막았다고 주장하지 않는다. fallback의 공식 지원 범위는 단일 탭이다.

## 19.5 백업과 마이그레이션

최근 정상 저장 2개를 별도로 보관한다. 버전 마이그레이션은 사본에 적용→검증→성공 후 교체하며 원본을 먼저 삭제하지 않는다. 미래 schemaVersion은 가져오기를 거부하되 현재 정상 저장을 건드리지 않는다. 알 수 없는 콘텐츠 ID는 삭제하지 말고 보존된 orphan 목록으로 남긴다.

내보내기 파일은 UTF-8 JSON, 최대 가져오기 크기 2MiB, type/range/ID/중복 검증. `__proto__`, `constructor`, `prototype` 등 위험 키를 재귀 검사하고 가져온 텍스트를 innerHTML/eval로 실행하지 않는다. 모든 지갑 수량은 0~10^12의 안전 정수, 비정상 NaN/Infinity/음수는 오류로 처리한다.

가져오기 전 현재 저장을 백업하고 대상 요약(작성일/주요 레벨/수집 수)을 보여준다. 정상 저장을 이름이 비슷한 다른 게임의 데이터로 덮어쓰지 않는다. 체크섬은 우발적 손상 검출용이며 위조 방지 서명이라고 하지 않는다.

브라우저 종료 이벤트만 믿고 저장하지 않는다. 보상/소환/강화/관계/노드 완료 때 저장하고, 숨김 전환은 추가 정산 지점이다. 갑작스러운 강제 종료의 모든 손실까지 보증하지 않는다.

# 20. 콘텐츠 제작 순서와 데이터 검증

## 20.1 실제 기능을 먼저 연결

데이터에 이름/설명만 추가하고 해당 패시브/상태가 전투 엔진에 없으면 콘텐츠 누락이다. 모든 기술/effect ID에 실행 함수와 테스트를 연결한다. 구현되지 않은 효과가 등장하면 조용히 무시하지 말고 개발 빌드에서 명확히 실패한다.

필수 데이터 검사: ID 유일성, 5영웅/24동료/10보스/2특수 구분, 속성 표 전체, 참조 존재, 에셋의 실제 존재, 계수 단위, 확률 합계, 등급별 기대 재료량, 상향 보너스의 일일 상한, 획득 경로 존재, 해금 의존성의 순환 없음. 예를 들어 기억을 얻어야 읽는 장면을 먼저 읽어야 같은 기억을 얻는 순환을 만들지 않는다.

모든 소유 가능 수집물에는 `sourceType, sourceId, availableFrom, rotation, duplicateBehavior`를 넣는다. 풀 밖 아이템이 확률표에만 나오는 일, 종료된 시즌의 itemId를 여전히 추첨하는 일을 차단한다.

## 20.2 대사·그림 작업의 완료 기준

장면에 빈 문장, '추후 작성', 임시 이름이 있으면 출시 상태는 content-incomplete다. 개발자 기능 프로토타입에서는 허용하되 플레이 가능한 완제품이라고 보고하지 않는다. 도구가 없어 그림을 만들 수 없으면 그 항목과 필요한 원본/제작 작업을 명시하고 기존 그림을 조용히 복제해 채우지 않는다.

캐릭터별 `CANON.md`에는 확인된 외형/말투/관계, 원본 위치, 모순 위험, 새 게임에서만 적용되는 기계적 해석을 분리한다. 사용자가 준 동일인물/공동 모습 관계가 최우선이다.

# 21. 검증 정책: 새 게임에 필요한 최소 증거

## 21.1 원칙

현재 저장소는 신뢰 가능한 base와 HEAD의 merge-base부터 실제 변경을 판별하고, 알 수 없는 runtime/config 경로를 성공한 빈 범위로 취급하지 않는다. `idle/`은 새 범위이므로 명시적으로 검증 선택기에 등록해야 한다. root 검증을 우회하기 위해 새 게임을 '문서'로 분류하면 안 된다. [R1][R5]

선택기만 수정한 검증에서는 실제 Card/Shooter/Defense를 돌리지 않고 mock command plan/fixture로 그 게임의 선택 결과 보존을 확인한다. `idle/` 런타임도 동시에 바뀌면 선택기 fixture + 해당 idle 검증만 돌린다. 다른 게임 전체 빌드·대량 자동 전투·브라우저 설치를 불필요하게 실행하지 않는다.

아래 명령은 **새로 만들어야 할 명령**이다. 현재 저장소에 이미 존재한다고 가정하지 않는다.

```text
npm run build:idle             # node idle/scripts/build.mjs
npm run test:idle:contracts    # 데이터/확률/ID/해금 의존성
npm run test:idle:core         # 자원/소환/시계/저장 트랜잭션
npm run test:idle:rewards      # 귀환 상자/대성공/별나비/흔적/편지
npm run test:idle:combat       # 대표 전투/고유 효과
npm run test:idle:analysis     # 패배 분석과 실제 결과 일치
npm run test:idle:browser      # 최종 단일 HTML 대표 화면/입력
npm run simulate:idle         # 명시적으로 선택하는 장기 경제 점검
npm run verify:plan            # 기존 root 선택 계획 확인
npm run verify                 # 필요한 idle 작업 및 선택기 fixture만
```

문서만 변경하면 빌드/브라우저/전투를 돌리지 않는다. 테스트만 변경하면 해당 테스트, 배포 입력 변경 때 해당 게임을 한 번 빌드하고 커밋할 최종 HTML을 부팅한다. generated HTML만 직접 편집하면 차단한다. default verify에 무조건 90일 전투 시뮬레이션을 넣지 않는다.

## 21.4 성장·경제·당기는 힘 검증은 별도 보고

자원 흐름/전투 시뮬레이션과 실제 재미를 분리한다. 장기 경제 시뮬레이션은 균등 육성, 한 명 우선 후 전환, 희귀 미획득, 하루 결석의 기본 네 프로필에 더해 아래 세 이용 프로필을 사용한다.

| 프로필 | 행동 |
|---|---|
| A. 바닥 | 하루 1회 5분. 기본 수령/정비, 귀환 상자, 다음 날 이전 편지 회수. 모험·추천 보스 최적화 없음 |
| B. 일반 | 하루 2회 각 3~5분. 편지를 당일 읽고 추천 보스 첫 정산, 일일 별나비 회수 |
| C. 확장 | B + 주 3회 모험, 패배 분석/편성 실험 등 20~30분 선택 플레이 |

28/90/180일에서 다음을 보고한다.

- A가 v1.0의 기본 목표(28일 분산 육성 약 Lv70, 기억 60회 선택권 2회)에 여전히 도달하는가.
- 기본 성장 자원 총량은 B/A ≤1.10, C/A ≤1.25인가.
- 소환 횟수는 B/A ≤1.10, C/A ≤1.20인가.
- 원정 단계 진척은 C/A ≤1.15인가. 선택 플레이의 가치는 조합·수집·장식에 더 두고 기본 성장 격차는 제한한다.
- 3일 결석+복귀 보정 결과가 같은 기간 연속 접속보다 많지 않은가.
- 모든 성장 경로가 동시에 3일 이상 멈추는 구간, 10연 청동 이상 수, 반짝 보너스 최장 공백을 기록한다.

상향 보너스의 정적 목표는 다음과 같다.

- 완성품을 제외한 비완성 결과 중 청동·은빛·황금 결과의 10연 기대 개수는 동료 4.1, 기억 4.2다.
- 첫 10분 안에 초보자 보장에 의한 실제 별빛 결과 1개.
- 2시간 이상 첫 수령 세션에는 귀환 상자 공개 1회. 5분 루프의 자동 모달은 최대 2개.
- 일일 별나비·상자·대성공은 모두 추가 보상이며 어떤 결과도 기본값 미만이 아니다.
- 5분 세션에 무조건 3개의 화려한 팝업을 강제하는 식으로 지표를 맞추지 않는다. 놀람의 수보다 루프 방해와 신뢰를 함께 측정한다.

일상 검증은 대표 7일+회귀 사례로 짧게, 장기 시뮬레이션은 초기 출시 또는 성장/보너스식 변경 시 명시적으로 실행한다. 실패한 지표를 숨기기 위해 적/상점에 비공개 보정을 넣지 않는다. 기존 게임 수천 번 전투 검증을 함께 돌리지 않는다.

출시 목표: 기본 루프 5분 이내, 30~90일 구간에서 모든 성장 경로가 3일 이상 동시에 멈추는 사례가 없을 것, 한 번 얻은 동료가 즉시 사용 가능할 것, 나쁜 가챠 운으로 필수 전투 대응이 차단되지 않을 것, 첫 패배 이후 다음 행동을 설명할 수 있을 것. 달성되지 않으면 병목 자원/공식/보스 체력을 근거와 함께 조정한다. 데이터상 목표를 통과해도 재미가 보증되지는 않는다.

최소 직접 플레이 시나리오는 새 저장 첫 10분, 7일차 5분 루프, 30일차 정체 상태에서 두 가지 편성 변경, 모험 한 회, 실제 근접 패배와 분석, 하루 결석 후 시즌 마지막 구간, 3일 복귀 보정이다. 과거 결과를 재사용하지 않고 최종 빌드에서 수행한다.

24동료/10보스/10유물/두 소환/5단 결과/승급 연출/천장 링/지정 기억/편성/프리셋/모험을 완성한다. 일일 별나비, 반짝 흔적, 추천 보스, 패배 분석을 연결한다. 모든 이름 있는 효과가 실제로 동작해야 한다. 원작 데이터의 이름만 복사해 효과를 공통 공격으로 치환한 결과는 불합격.

123개 장면과 15개 기억 자산, 홈 반응 90개, 첫 시즌/아카이브/복각, 복귀 보정, 음악 플레이어, FX-05~06, 최종 그림 비교, 저장 복구/모바일/단일 HTML을 완성한다. 미완성 자산은 완료 보고의 별도 목록에 남긴다. 광고·고스트 리그·행운의 시각을 임의로 추가하지 않는다.

필수 계약 테스트, 대표 플레이, A/B/C 경제 보고, UI/에셋 시각 검토, 최종 HTML 부팅, root verify 통과. 실제 확인하지 않은 휴대폰/브라우저와 남아 있는 재미/밸런스 불확실성을 함께 기록한다.

# 23. 코딩 에이전트 재량과 변경 금지 경계

수치 튜닝은 실제 플레이/시뮬레이션 근거가 있으면 가능하다. `balance` 파일에 모으고 변경 전후 영향을 기록한다. 그러나 다섯 영웅 영구 육성, 24시간 상한, 실패 없는 강화, 확정 선택권 유지, 기억의 비전투 성능, 소환 없는 일일 완료, 기본 수율 불변, 다른 게임 불변은 임의로 바꾸지 않는다.

밸런스를 맞추기 쉽다는 이유로 다섯 영웅을 같은 기술로 만들거나, 동료를 전부 공격력 버프로 바꾸거나, 10보스를 색깔만 다른 체력통으로 대체하지 않는다. 개발 시간을 줄이기 위해 관계/새 그림을 삭제하고 '추후 확장'만 남기면 전체 사양 이행이 아니다. 반대로 당기는 힘을 늘린다는 이유로 광고 카운트다운·고스트 리그·무작위 시간 창·하루 8회 포획을 추가하는 것도 허용되지 않는다.

일정과 작업 여건상 전부 구현하지 못할 때는 현재 빌드가 어디까지 실제 동작하는지 정확히 보고한다. 기능 버튼만 존재하는 상태, 표시 확률만 있고 실제 적용 안 된 상태, 소스만 되고 배포 HTML은 구버전인 상태를 완료로 간주하지 않는다.
